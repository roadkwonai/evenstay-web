### 문구 대조 방법
`copy.md` 전체와 대조하면 "교정 기록" 표에 남은 옛 문구까지 맞는 것으로 나온다. `design/site/src/copycheck.py`는 0절과 1절의 표만 본다. 문구를 맞출 때는 이 스크립트를 쓴다.
`recopy.py`는 `copy.md` 표의 현재 값을 `build.py`에 넣는다(옛 문구를 찾는 짝이라 다음 교정 때는 옛 값을 갱신해 쓴다). `capfit.mjs`는 히어로 설명 칸을 폭마다 잰다.

### 9쪽과 스크롤 모션 (새 캔버스 Version 12)
- 문구: 화면 문장은 모두 `design/site/src/strings/<페이지>.json`(공통 `common.json`)에 있다. `build.py`·`pages.py`는 `T(키)`만 쓰고 `copy.md`와 asset-plan을 빌드 때 읽지 않는다. `copy.md`가 바뀌면 JSON 값을 고치고 `check_strings.py`를 돌린다. `recopy.py`는 더 쓰지 않는다.
- 메인 영상 영역: `site.css`에서 높이 `max(420px, min(100svh - 200px, 56.25cqw))`, 초점 `50% 10%`로 바꿨다(사용자 요청, 넓은 화면). 캔버스의 site.css blob은 다시 올리지 않아 보드는 옛 600px 상한이다.
- 일반 페이지: `build_static.py`가 보드를 `design/prototype/site/`의 정적 페이지 11개로 바꾼다. 동작은 `static-site.js`이고 `build.py`의 LOGIC을 옮긴 것이라 둘을 같이 고친다.
- 생성: `design/site/src/pages.py`가 strings 값으로 쪽을 만든다. 공통 머리·푸터·전화 안내·로직은 `build.py`를 쓴다. `measure.mjs` → `layout.py` → `pages.py` → `canvas.py` 순서다.
- 2단계 이미지 19장을 Version 10에 넣었다. 앱 캡처 10장(CAP-1~10)은 Version 13에서 앱 캔버스 version id 1793776536-9bd1 기준으로 다시 찍었다. CAP-7은 FAM-06d다. 이미지 빈 자리는 없다.
- 앱 캡처 대체 텍스트 CAP-4, 7, 9, 10은 Version 16에서 `copy.md` 표로 맞췄다.
- 뷰어 자동 점검 주의: 팁 닫기 자리 (297,72)는 팁이 없으면 메모 도구다. 팁 글이 보일 때만 누른다. Version 14·15는 이 클릭과 Shift+1이 Safety에 "!" 메모를 남겨 저장된 것이고, Version 17에서 지웠다. 게시 전에는 canvas.json 최신본을 읽는다.
- 패널은 캡처 위쪽 약 510px만 보여 준다. LND-07의 CAP-6은 캡션의 목욕 도움이 잘려서 `panel('CAP-6', True)`로 전체를 보인다. 메인 시트 칸 높이는 `parts.json`에서 7630, 6820으로 늘렸다.
- 평면도와 약도의 라벨은 그림 위 HTML이다(`pages.py`의 `PLAN_PINS`, `MAP_PINS`, 위치는 그림 기준 %). 그림을 바꾸면 위치를 다시 맞춘다. 읽기 프로그램용 목록은 그림 아래 `sr-only`다.
- IMG-SAFE-PHONE 대체 텍스트는 "알림을" 뺀 문장이다. 사진에 휴대폰 뒷면만 보여서다.
- IMG-MEAL-SPECIAL1 사진에는 계란 프라이와 고기가 있는데 캡션은 "봄나물 비빔밥, 맑은 국, 과일 화채"다. 문구는 고치지 않았다.
- 카피에 제목이 없는 섹션은 보이는 제목 없이 `aria-label`만 둔다.
- 스크롤 등장: 접힌 곳 아래 요소만 숨기고, 사진·카드 240ms 12px, 글 160ms 6px, 같이 들어온 묶음은 30ms 간격(최대 60ms), 글은 기다리지 않는다. 명세에 "애니메이션 없음"인 섹션은 `data-rv`를 넣지 않는다.
- 캔버스 틀은 전체가 보여서 등장이 안 보인다. PLAY의 전체 화면에서 보인다.
