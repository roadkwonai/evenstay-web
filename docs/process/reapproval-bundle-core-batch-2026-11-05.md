# 재승인 묶음: 코어 배치 전송 시간 초과

대상: `04-planning/ideas/pms-core-billing/tech-design.md` 한 파일. 표시 19개(16줄), 바뀐 줄 21줄. 승인 뒤 표시를 "사용자 재승인"으로 바꾸고 `evenstay/docs/core/`로 복사한다.

## 바뀐 것
- 새 배치 상태 `RESULT_UNKNOWN`: 보낸 뒤 결과를 모를 때의 상태다. 2-2, 3-5, 9절에 넣었다.
- 재확인과 중복 출금 방지: 결과 대기 줄은 동의 철회나 사람의 판단만으로 닫지 못한다. 배치 거절이나 제공자 확인 뒤에만 닫힌다.
- 저장 순서: SENT를 먼저 저장하고 보낸다. SENT는 "보내기 시작함"을 뜻한다.
- "같은 배치를 다시 보내도 한 번만 처리한다"를 "제공자가 지키는지 [미확인], 믿고 다시 보내지 않는다 [가설]"로 낮췄다.
- 확인할 것 32: 수동 수납과 결과 대기 중 승계가 3-5 기본안을 가리킨다. [가설]이다.
- 확인할 것 35: 시스템 작업 범위는 사업장별 `runAs`가 기본안이다. [가설]이고 M1에 닫는다.

## 요청보다 넓어진 것
- 이미 승인된 3-5의 220, 221, 225줄을 고쳤다. 시간 초과 배치만 막으면 정상 SENT 배치의 줄을 닫고 다시 출금하는 길이 남기 때문이다.
- (바) 금액 대조 규칙을 새로 넣었다. [가설]이다.
- 228줄(중복 출금을 막는 처리)은 처음 요청(배치 시간 초과)을 넘어 수동 수납, 건별 결제, 가상계좌까지 걸치는 규칙이 됐다. 모두 [가설]이고 화면, 시드, 금액은 그대로다.
  - 보내기 직전 확인을 청구서 행 잠금 트랜잭션 안으로 옮겼다. 시작된 결제의 웹훅이 결과 대기 줄과 겹치면 버리지 않고 대사 예외로 보내 사람이 확정한다.
  - `ExpectedPayment` 전이는 모두 조건부 갱신이다. 닫힌 가상계좌 입금과 금액 불일치는 예외 목록으로 보낸다.
  - 실을 줄이 없는 배치는 SENT로 바꾸지 않고 DRAFT에 남긴다. 건별 결제가 진행 중인 청구서는 배치에 싣지 않는다. 진행 중 표시를 둘 곳은 [미정]이고 확인할 것 32에 있다.

## 값
응답 시간 초과 값, 결과 기한, 재확인 주기와 횟수, 확정 역할, 돌려주는 절차는 [미정]이다.

## 확인하지 못한 것
- 재검토를 네 번 더 돌렸고 마지막 결론은 "직접 모순 없음"이다. 그 뒤 넣은 보완 문장은 재검토하지 않았다.
- 재검토마다 새 지적이 나왔다. 빠짐없이 찾았다고 보증할 수 없다. 잠금 순서처럼 구현 때 정할 세부는 뺐다.
- 2-2의 "보내기 직전에 다시 확인한다"는 동의만 말한다. 3-5와 모순이 아니라 고치지 않았다.
- 허브는 표시 수와 228, 715, 786줄(결제 기획이 들어가기 전 번호 224, 695, 763)을 대조했고 나머지 문장은 읽지 않았다.
