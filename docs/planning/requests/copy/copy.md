이름은 `names.md` 1절에서 확정한 **생활 요청**이다(직원·회원·보호자 화면 같은 이름, 사용자 "추천대로" 2026-11-03). 종류·상태 라벨은 `names.md` 2~4절을 따른다. 브랜드는 Evenstay(운영), Evenstay 홈(회원), Evenstay 패밀리(보호자), Evenstay 홈 비서다 [사실: 코어 names v4].

**진단**: A(빈 상태). 이 모듈의 기존 카피가 없어서 `product-marketing.md`의 사실과 코어·안심 알림의 목소리(직원 합쇼체, 회원 해요체)로 새로 썼다. 사실은 만들지 않았고, 근거가 없는 것은 `[NEED: ...]`, 기획에서 정할 것은 `[가설]`, 사용자가 정할 것은 `[미정]`으로 남겼다.

**읽는 법**: 표 안의 화면 문구는 카피 제안이다. 문구가 기대는 사실, 규칙, 값에는 태그를 붙였다. 태그가 없는 규칙 줄은 이 문서가 정한 카피 규칙이다.

**모든 문구에 적용한 규칙**
- 급한 일과 몸이 불편한 일은 생활 요청이 아니다. 회원 화면마다 호출벨과 프런트 전화를 고정하고, 직원 화면에는 [안심 알림으로 옮기기]를 둔다. 무엇을 옮길지는 직원이 정한다. 시스템이 요청 내용을 읽고 가르지 않는다.
- 회원·보호자 화면에서 처리 시간을 약속하지 않는다. "곧", "바로 처리"를 쓰지 않는다. 회원이 고른 날짜와 시각만 다시 말한다.
- 직원 화면은 "입주자", 회원에게는 "회원님", 보호자 화면은 "이은숙 회원님"이다. 직원 화면에서 "회원"을 쓰지 않는다 [사실: 코어 Glossary].
- 병원 동행은 날짜, 시각, 가실 곳, 돌아오실 때 동행 여부만 받는다. 진료 과목, 증상, 진료 내용은 묻지도 받지도 않는다.
- 앱이 어려운 분을 위한 길(프런트 전화, 지나가는 직원에게 말하기, Evenstay 홈 비서)을 회원 첫 화면과 오류 문구에 넣는다. 직원이 대신 올리고, 회원의 말로 한 확인도 직원이 대신 기록한다.
- 문자에는 요청 내용을 넣지 않는다. 종류 이름까지만 쓰고 링크를 넣지 않으며 프런트 번호를 적는다(안심 알림 문자와 같은 방식, 보이스피싱 P-039).
- 낙상, 쓰러짐, 응급, 위험, 배회, 미납, 연체, 퇴소, 판정, 노인을 쓰지 않는다. 이모지를 쓰지 않는다.
- 이름, 호실, 시각, 금액 자리, 전화번호는 데모 예시다. 사람은 모두 가상이다. 주인공과 가족은 다른 모듈 시드와 같다: A동 201호 이은숙, 딸 김지민(보호자), 아들 김태호(대리인) [사실: B·D copy 시드]. 프런트 최민수는 D copy의 직원 이름을 빌렸다. 시설 담당 한도윤, 청소·세탁 담당 오수진, 운전 담당 정태영, 생활 지원 담당 윤서연은 이 문서에서 처음 쓴 가상 이름이다 [가설: 기획 시드에서 확정]. 사업장 책임자 최영미는 코어 시드의 이름이다 [사실: N1 prd 9절].

## 1. 포트폴리오 소개 (README, 면접 자료 첫 장)
**제목**
> 생활 요청: 입주자의 부탁을 받아 직원에게 나누고, 입주자 확인까지 남기는 요청 큐

대안
- A. "화장실 전등이 안 켜진다는 말이 끝까지 처리되기까지" — 장면은 보이지만 무엇을 만들었는지가 늦게 나온다.
- B. "작업 지시 모듈" — 짧지만 시니어 레지던스라는 맥락이 빠진다.
- 고른 것: 제목은 무엇을 만들었는지, 부제에서 장면과 결과를 말한다.

**부제**
> 고장, 청소, 세탁, 외출 차량, 병원 동행, 불편한 점을 한 목록으로 받습니다. 직원이 마쳐도 입주자가 확인해야 닫히고, 정기 청소와 점검은 일정에서 자동으로 만들어집니다.

**문제** (한 단락)
> 시니어 레지던스는 청소, 세탁 대행, 병원 동행 같은 생활 서비스를 함께 제공합니다(삼성노블카운티 주 2회 청소·세탁 대행, 2026년 6월 보도. 평창카운티 병원 동행, 2025년 3월 보도). 해외 입주자 앱은 수리와 서비스 요청을 직원에게 넘기는 기능을 기본으로 둡니다(Touchtown, LifeLoop). 국내 시설에서는 입주자가 말로 한 부탁을 직원이 전화로 받아 적는 것으로 보입니다. 이것은 아직 현장에서 확인하지 못한 추정입니다. Evenstay에도 AI 비서가 "직원에게 전하기"로 넘긴 말을 받을 곳이 없었습니다.

**무엇을 만들었나** (세 묶음, 묶음마다 한 가지 주장)
1. **어디서 들어와도 같은 요청으로**
   회원 앱, 보호자 화면, 프런트 직원의 대신 등록, AI 비서의 넘기기가 같은 요청 모델로 들어옵니다. 들어온 곳은 요청마다 남고, 종류에 따라 담당 팀이 정해집니다.
2. **입주자가 확인해야 끝나는 상태**
   접수 → 처리 중 → 완료 → 입주자 확인 순서로 갑니다. 입주자가 [아직이에요]를 누르면 다시 열립니다. 7일 동안 확인이 없으면 닫히고 그 사실도 남습니다. 비용이 드는 요청은 확인된 뒤에 코어 청구 항목이 됩니다.
3. **정기 작업은 일정에서**
   사업장 책임자가 "A동 매주 화·금 청소"를 정하면 회차마다 요청이 만들어집니다. 입주자는 한 회를 쉴 수 있고, 하지 못한 회차는 이유와 함께 남습니다.

**설계에서 먼저 정한 것** (면접관용, 짧게)
- 요청 하나의 수명을 상태와 전이 기록으로 남긴다. 누가 언제 어떤 상태로 바꿨는지가 변경 이력이다.
- 처리 기한은 종류별 사업장 설정이고 직원 화면에만 보인다. 회원에게 시간을 약속하지 않는다.
- 몸이 불편하다는 요청은 직원이 안심 알림으로 옮긴다. 생활 요청이 안전 신호를 대신하지 않는다.
- 병원 동행은 이동 일정만 받는다. 건강 정보를 받지 않는다는 규칙은 입력 칸 단계에서 먼저 정했다.

**CTA**
> 데모 열기: 회원 화면에서 전등 고장을 올리고 직원 화면에서 마쳐 보세요

## 2. 회원 화면 (Evenstay 홈 · 생활 요청)
큰 글씨, 한 화면에 한 가지 일, 해요체, "회원님". 종류 버튼은 그림과 글자를 같이 둔다. 모든 화면 아래에 같은 안내를 고정한다.

### 2-0. 모든 화면 아래 고정 문구
| 위치 | 문구 |
|---|---|
| 고정 문구 | 급한 일이나 몸이 불편하실 때는 호출벨을 누르시거나 방 전화로 내선 0번(프런트)을 눌러 주세요. [NEED: 실제 내선 번호] |

### 2-1. 생활 요청 첫 화면
| 위치 | 문구 |
|---|---|
| 화면 제목 | 생활 요청 |
| 첫 문장 | 고칠 것이나 필요한 일을 알려 주시면 맡을 직원에게 전해요. |
| 종류 타일 제목 | 어떤 일인가요? |
| 종류 타일 | 2-2의 6개 (병원 동행을 켠 곳은 7개) |
| 내 요청 구역 제목 | 내 요청 |
| 내 요청 구역 내용 | 2-6 |
| 정기 청소 한 줄 | 정기 청소: 매주 화요일, 금요일 [이번 주 쉬기] |
| 다른 길 | 앱이 어려우시면 프런트에 전화하시거나 직원에게 말씀해 주세요. 직원이 대신 요청해 드려요. 비서에게 말씀하셔도 직원에게 전해요. |

### 2-2. 종류 타일 (2-1 첫 화면 안)
| 위치 | 문구 |
|---|---|
| 타일 제목 | 어떤 일인가요? |
| 타일 (풀이 한 줄씩) | 고장·수리: 전등, 수도, 문, 냉난방처럼 고칠 것 · 청소: 정해진 청소 말고 더 필요하실 때 · 세탁: 옷과 이불을 맡기실 때 · 외출 차량: 장 보기, 은행처럼 나가실 때 타실 차 · 병원 동행: 병원 가시는 날 직원이 함께 가요 · 불편한 점: 소음, 서비스처럼 말씀하고 싶은 것 · 그 밖의 일: 위에 없는 부탁 |
| 아래 안내 | 어느 것을 누를지 모르시겠으면 "그 밖의 일"을 누르세요. 직원이 맞는 곳으로 옮겨요. |

### 2-3. 요청하기: 종류별 입력
한 화면에 한 칸씩 묻는다. 말로 하기 버튼은 모든 글 칸에 둔다(음성은 글로 바뀌어 저장된다) [가설: 기획에서 확정].

| 종류 | 묻는 말 | 칸 아래 안내 |
|---|---|---|
| 고장·수리 | 무엇이 고장 났나요? | 예: 화장실 전등이 안 켜져요 |
| 고장·수리 (사진) | 사진이 있으면 붙여 주세요. (안 붙이셔도 돼요) | [사진 붙이기] [건너뛰기] |
| 고장·수리 (방에 들어가도 되는지) | 회원님이 안 계실 때 직원이 방에 들어가도 될까요? | [네, 들어가도 돼요] [제가 있을 때 와 주세요] |
| 청소 | 어디를 청소할까요? | 예: 베란다, 냉장고 안 |
| 청소 (날짜) | 원하시는 날짜를 골라 주세요. | 정기 청소 날(화요일, 금요일)을 고르시면 그날 함께 해요. |
| 세탁 | 무엇을 맡기실까요? | [옷] [이불] [그 밖의 것] |
| 세탁 (가지러 갈 때) | 직원이 언제 가지러 갈까요? | [오늘 오후] [내일 오전] [날짜 고르기] [NEED: 사업장 수거 시간] |
| 외출 차량 | 언제 나가세요? | 날짜를 골라 주세요. |
| 외출 차량 (시각) | 몇 시에 나가세요? | 11월 19일 목요일 (고르신 날짜). 시각 칩은 10-10 |
| 외출 차량 (가실 곳) | 어디에 가세요? | 예: ○○은행 마곡지점 |
| 외출 차량 (돌아오실 때) | 돌아오실 때도 차가 필요하세요? | [네, 필요해요] [아니요] |
| 병원 동행 | 병원 가시는 날과 시각을 골라 주세요. | |
| 병원 동행 (가실 곳) | 가실 병원 이름이나 주소를 알려 주세요. | 어디가 불편하신지는 적지 않으셔도 돼요. 날짜와 가실 곳만 있으면 돼요. |
| 병원 동행 (돌아오실 때) | 돌아오실 때도 직원이 함께 올까요? | [네, 함께 와 주세요] [아니요, 혼자 올게요] |
| 불편한 점 | 어떤 점이 불편하셨나요? | 소음, 식당, 직원 응대처럼 무엇이든 괜찮아요. 담당 직원이 읽고 연락드려요. |
| 그 밖의 일 | 무엇이 필요하세요? | 예: 커튼 봉을 달아 주세요 |

- 병원 동행에는 자유 입력 칸이 "가실 곳" 하나뿐이다. 그 칸도 병원 이름이나 주소만 묻는다 [가설: 기획에서 확정].

| 병원 동행 칸 안내 | 날짜, 시각, 가실 곳, 돌아올 때 동행만 적습니다. 진료 과목이나 증상은 적지 않습니다. |

### 4-4. 배정
| 위치 | 문구 |
|---|---|
| 버튼 | 맡기 · 배정 |
| [맡기] 뒤 | 한도윤 님이 맡았습니다. 입주자 화면에 이름이 보입니다. |
| 배정 창 제목 | 담당자를 고르세요. |
| 배정 창 목록 | 시설 팀: 한도윤(오늘 근무, 맡은 요청 3) · 이○○(휴무) |
| 배정 뒤 | 한도윤 님에게 배정했습니다. |
| 담당 바꾸기 | 담당 바꾸기 · 바꾼 이유(선택): 근무 교대 · 다른 팀 일 · 그 밖의 이유 |
| 종류 정하기 (분류 전) | 종류를 정하면 담당 팀으로 갑니다. 외출 차량 → 운전 팀 |

### 4-5. 처리
| 위치 | 문구 |
|---|---|
| 버튼 | 시작 · 기다림 · 완료 · 하지 않음 |
| [시작] 뒤 | 처리 중으로 바꿨습니다. 입주자 화면에 "한도윤 직원이 처리하고 있어요"로 보입니다. |
| 기다림 이유 고르기 | 부품 · 바깥 업체 · 입주자가 고른 날 · 입주자와 시간 맞추기 |
| 기다림 메모 | 메모(직원만 봄): 예: 거울등 안정기 주문, 11/19 도착 예정 |
| 하지 않음 이유 고르기 | 관리 범위 밖 · 같은 요청이 이미 있음 · 입주자가 그만두겠다고 함 · 제공하지 않는 서비스 |
| 하지 않음 안내 | 입주자 화면에 이유와 프런트 안내가 함께 보입니다. 이유는 위 넷 중에서만 고릅니다. |
| 같은 요청이 이미 있을 때 | 같은 요청과 합치기: 이 요청은 닫고 먼저 들어온 요청(09:05)에 이어 붙입니다. |

### 4-6. 완료
| 위치 | 문구 |
|---|---|
| 창 제목 | 한 일 적기 |
| 입력 안내 | 입주자 화면에 그대로 보입니다. 입주자가 알아들을 말로 한 줄 적어 주세요. |
| 입력 예 | 천장 전구를 바꿨어요. |
| 버튼 | 완료로 바꾸기 |
| 완료 뒤 | 완료했습니다. 입주자 확인을 기다립니다. 7일 동안 확인이 없으면 닫힙니다. |
| 비용 있음 | 입주자가 확인하면 청구 항목 "세탁 대행 ○,○○○원"이 다음 청구서에 들어갑니다. [가설: 확인 시점 생성] |
| 사진 (선택) | 마친 뒤 사진 붙이기 |

### 4-7. 입주자 확인을 대신 기록
입주자가 앱을 쓰지 않을 때 직원이 들은 말을 기록한다.

| 위치 | 문구 |
|---|---|
| 버튼 | 입주자 확인 대신 기록 |
| 창 안내 | 입주자에게 직접 들은 말만 기록합니다. 들은 직원과 시각이 남습니다. |
| 선택지 | 다 됐다고 하셨습니다 · 아직이라고 하셨습니다 |
| 기록 뒤 | 입주자 확인으로 바꿨습니다(14:00, 들은 직원 최민수). |

### 4-8. 다시 열림
| 위치 | 문구 |
|---|---|
| 카드 딱지 | 다시 열림 |
| 카드 위 한 줄 | 입주자가 11:00에 [아직이에요]를 눌렀습니다. 입주자 의견: "거울 위 등이 아직 안 켜져요" |
| 담당에게 가는 알림 | 다시 열린 요청, A동 201호, 수리 |

### 4-9. 안심 알림으로 옮기기
| 위치 | 문구 |
|---|---|
| 버튼 (모든 카드의 더보기 안) | 안심 알림으로 옮기기 |
| 확인 창 | 이 요청을 안심 알림 "전화로 받은 호출"로 올립니다. 즉시 확인 알림으로 당번에게 갑니다. 생활 요청은 닫힙니다. [옮기기] [그대로 두기] |
| 옮긴 뒤 | 안심 알림으로 옮겼습니다(16:05, 최민수). 생활 요청에는 옮긴 기록만 남습니다. |
| 입주자 화면 (옮긴 요청) | 이 요청은 안심 알림으로 옮겨 당번 직원에게 알렸어요. |

- 옮기는 판단은 직원이 한다. 시스템은 낱말을 보고 자동으로 옮기지 않는다. 안심 알림 쪽 문구는 B `senior-lab/03-copywriting/ideas/safety-signal-hub/copy.md` 2-11을 그대로 쓴다 [사실: B copy 2-11].

### 4-10. 홈 비서에서 온 요청
| 위치 | 문구 |
|---|---|
| 카드 위 한 줄 | 홈 비서가 입주자에게 묻고 넘긴 말입니다. 입주자가 한 말 그대로입니다. |
| 넘긴 이유 표시 | 넘긴 이유: 직접 요청 · 건강 판단 · 금전 판단 · 계약 판단 [사실: G copy 직원 화면의 넘긴 이유 값] |
| 넘긴 이유가 건강·금전·계약 판단일 때 | G copy 직원 화면의 이유별 안내 문장을 카드 위에 그대로 붙인다. 이 문서에서 새로 쓰지 않는다. |
| 넘긴 이유가 금전 판단일 때 더함 | 돈을 옮기거나 맡기는 부탁은 생활 요청으로 처리하지 않습니다. [NEED: D 5-3 금전 부탁 접수와 연결] |
| 대화 보기 | 비서 대화 보기(AI 생활 비서 화면으로 이동) |

- 넘긴 요청이 모두 생활 요청 목록에 들어올지, "직접 요청"만 들어오고 판단 이유가 붙은 것은 AI 생활 비서 직원 화면에 남을지는 기획에서 정한다 [가설].

## 5. 책임자 화면 (사업장 책임자)

### 5-1. 정기 작업 설정
| 위치 | 문구 |
|---|---|
| 화면 제목 | 정기 작업 |
| 화면 위 안내 | 정기 작업은 정한 일정에 맞춰 요청으로 만들어집니다. 회차마다 마침, 쉼, 못 함과 그 이유가 남습니다. |
| 목록 한 줄 | A동 청소, 매주 화, 금, 18개 호실, 청소·세탁 팀 |
| 목록 한 줄 | 승강기 자체 점검, 매월 첫째 월요일, 시설 팀 [미확인: 법정 점검 주기는 기획에서 조문 확인] |
| 새로 만들기 버튼 | 정기 작업 만들기 |
| 입력 칸 | 이름 · 종류(청소, 점검) · 대상(동, 호실, 공용 시설) · 반복(매주 요일, 매월 날짜) · 담당 팀 · 시작일 · 끝나는 날(선택) |
| 만들기 뒤 | 정기 작업을 만들었습니다. 첫 회차는 11월 20일(금)입니다. 회차는 그날 0시에 만들어집니다. [가설: 생성 시각] |
| 입주자 쉬기 허용 | 입주자가 한 회를 쉴 수 있게 합니다. 마감: 전날 오후 6시 [가설] |
| 끝내기 | 이 정기 작업을 끝내시겠습니까? 이미 만들어진 회차는 그대로 남습니다. [끝내기] [그대로 두기] |
| 바꾸기 뒤 | 다음 회차부터 바뀝니다. 바꾼 사람과 시각이 변경 이력에 남습니다. |

### 5-2. 종류별 담당 팀과 처리 기한
| 위치 | 문구 |
|---|---|
| 화면 제목 | 요청 종류 설정 |
| 표 머리 | 종류 · 담당 팀 · 처리 기한 · 비용 |
| 예 | 수리, 시설, 접수 후 2일, 없음 [가설: 기한 값은 기획 제안값 자리] |
| 예 | 세탁, 청소·세탁, 수거 후 2일, 요금표 |
| 안내 | 처리 기한은 직원 화면에만 보입니다. 입주자와 보호자에게는 보이지 않습니다. |
| 비용 칸 안내 | 금액은 코어 요금표에서 가져옵니다. 요금표에 없는 서비스는 비용 없음으로 처리됩니다. [가설] |

### 5-3. 운영 현황 대시보드 칸 (생활 요청)
| 위치 | 문구 |
|---|---|
| 칸 제목 | 생활 요청 |

## 7. 오류와 안내 메시지
순서: 무엇이 안 됐는지 → 왜 → 무엇을 하면 되는지. 사용자 탓을 하지 않는다.

| 사진 올리기 실패 | 사진이 올라가지 않았습니다. 사진 없이 완료할 수 있습니다. | 사진이 올라가지 않았어요. 사진 없이 보내셔도 돼요. | (같음) |

### 10-8. 홈 비서에서 온 요청 (기획 번호 16, 4-10 보충)
| 위치 | 문구 |
|---|---|
| 넘긴 이유 값 (4-10 표시에 더함) | 도구 밖 질문 [사실: G `names.md` 넘긴 이유 값] |
