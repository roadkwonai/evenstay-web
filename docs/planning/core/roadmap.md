## 순서와 의존
```
Now: 코어 MVP ──► G 최소판(청구 설명) ──► B ──► D ──► G 정식 ──► C ──► (E)
              │           ▲                 ▲      ▲                ▲
              └─ Next API ┴─ 청구 설명 ─────┴ 조회 ┴ 관계·권한 확장 ┴ 계약 변경
```
- 모듈 순서 A → B → D → G → C, G 최소판은 A 직후 [사실, 2026-11-02 확정].
- **F18·F19 의존(2026-11-03)**: F18 이벤트는 D가 구독하고 B는 신호 평가 때 `AbsenceQuery.absenceOf`를 읽으므로(B ADR-S7), D·B 개발 전에 이벤트 payload와 조회를 고정한다. F19 카드는 B `SafetyBoardQuery.boardOf`, D `FamilyConsentSummaryQuery.siteSummary`(두 이름은 각 모듈이 2026-11-03 확정, 반환 형태는 [가설]), N1 열린 요청 수(이름 [가설]) 조회가 생길 때마다 채워진다. 모듈이 없으면 그 카드는 나오지 않으므로 코어만으로도 호실 현황·확인할 일·장기 부재 카드는 동작한다.
- 코어 변경은 순서대로 한다. 모듈 작업 중 코어를 바꿔야 하면 코어 문서(`tech-design.md`)를 먼저 고치고 이유를 결정 기록에 남긴다 [사실, `04-planning/CLAUDE.md`].
