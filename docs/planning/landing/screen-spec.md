## 3. 섹션별 명세

각 섹션은 **목적 · 문구 자리 · 에셋 자리 · 상호작용 · 데스크톱/모바일 · 접근성 · 애니메이션 의도** 순서로 적는다. 애니메이션은 의도만 적고 값은 emil 단계에서 정한다. 모든 섹션 공통으로 스크롤 등장은 "투명도 0 → 1, 아래에서 12px 위로, 한 번만"을 기본 의도로 하고, `prefers-reduced-motion: reduce`에서는 이동 없이 투명도만 160ms로 남긴다 [가설: `DESIGN.md` Motion 움직임 줄이기 규칙을 따름].

### LND-00 상단 바
- **목적:** 어디서든 상담 신청과 전화로 갈 수 있게 한다.

### LND-04 직원
- **목적:** 따뜻하고 친절하게 응대하는 직원을 보여 준다 [사실: 사용자 말]. 직원은 회원님을 돕는 사람이고, 회원님이 대화를 이끄는 모습으로 그린다 [가설: 시니어를 무력하게 그리지 않음].
- **문구 자리:** 제목과 장면 캡션 2개 `[NEED: 카피 C-09]`. 직원 이름·인원수·자격은 지어내지 않는다.
- **에셋 자리:** 카드 2장: IMG-T1/VID-T1(로비 맞이), IMG-T2/VID-T2(라운지에서 함께 일정 보기). IMG-T3은 LND-08에서 쓴다. 등장 직원은 반복 인물(PER-FRONT, PER-LIFE)이라 소개 페이지 직원 소개(SITE-ABOUT-03)와 같은 얼굴·유니폼이다. 섹션 끝에 소개 페이지로 가는 글자 링크 [가설].
- **상호작용:** 영상은 카드가 절반 이상 보일 때 한 번 재생하고 마지막 장면에서 멈춘다(5초 이하라 일시정지 버튼 없음, WCAG 2.2.2 예외 범위). 다시 보기 버튼 없음 [가설].
- **데스크톱/모바일:** 1024px 이상 2열(16:9), 아래 1열(4:5로 가운데 자름) [가설].
- **접근성:** 영상은 `aria-hidden`, 카드의 이미지 대체 텍스트와 캡션이 뜻을 전한다. 움직임 줄이기면 포스터만.
- **애니메이션 의도:** 재생 시작은 포스터에서 끊김 없이 이어짐(첫 프레임 = 포스터).

### LND-05 회원님이 쓰시는 앱, Evenstay 홈
- **목적:** 회원님이 앱에서 하는 일 세 가지를 실제 화면으로 보여 준다: 청구서의 이유, 생활 요청, 홈 비서 [사실: 코어·N1·G value-prop 회원]. 안심 알림 회원 화면은 LND-13으로 옮겼다(2026-11-04, 생활을 앞에).
- **문구 자리:** 섹션 제목 `[NEED: 카피 C-10]`. 기능 설명(승인 문장 그대로):
  - 청구서: "항목마다 왜 이 금액인지 적혀 있어요. 거르신 식사처럼 빼 드린 금액도 이유와 함께 보여요."(카피 C-10, 코어 copy 3절에서 만듦)
  - 생활 요청: "고장 난 곳이나 필요한 일을 알려 주시면 담당 직원에게 전해 드려요."(카피 C-10, N1 value-prop 회원 첫 화면에서 만듦)
  - 홈 비서: "계약 날짜와 청구서 내용을 물어보시면 답해요. 그 밖의 일은 직원에게 전해 드려요."(카피 C-10, G value-prop 회원 첫 화면에서 만듦)
  - 기능 이름 3개(짧은 제목) `[NEED: 카피 C-10]`
- **에셋 자리:** CAP-1(CORE-08 이번 달 청구서), CAP-9(REQ-01 생활 요청 회원 첫 화면. 캔버스에 그려진 뒤 캡처 [미정]), CAP-3(AST-02 홈 비서 첫 화면). 모두 프로토타입 캡처이고 시드 가상 데이터다. 기능 제목 옆 아이콘은 셋 다 Lucide(U-08).
- **상호작용:** 없음. 붙박이 스크롤은 쓰지 않는다(U-01, 2026-11-04).
- **데스크톱/모바일:** 1024px 이상 기능마다 설명(왼쪽) + 캡처(오른쪽) 한 줄씩 세 번 쌓음. 아래는 설명 → 캡처 순으로 세 번 쌓음.
- **접근성:** 캡처 대체 텍스트는 화면의 주요 사실(예: 청구서 금액과 이유 문장)을 적는다. 캡처 안 글자는 읽히지 않으므로 같은 뜻을 설명 글자로 둔다. 캡처에 "데모 화면, 가상 데이터" 캡션.
- **애니메이션 의도:** 줄마다 스크롤 등장만.

### LND-06 가족이 쓰는 앱, Evenstay 패밀리
- **목적:** 보호자에게 "회원님이 보여 주기로 한 만큼 같은 기록을 본다"를 보여 준다. 감시가 아니라 함께 보는 것으로 [사실: D value-prop 쓰지 않기로 한 문장 "멀리서도 부모님을 지켜보세요"].
- **문구 자리:** 제목 `[NEED: 카피 C-11]`. 승인 문장: "이은숙 회원님이 보여 주기로 한 소식이에요."(D value-prop 보호자 첫 화면 — 화면 캡처 안에 이미 있음). 설명 두 줄(볼 수 있는 항목 다섯 가지, 범위는 회원님이 정함) `[NEED: 카피 C-11]`. 항목 이름은 D copy 4-1을 그대로: 생활 소식, 일정, 청구서, 건강 소식 [사실: `mvp-screens.md` 4-7 보조 열 규칙], 그리고 생활 요청 [사실: D `prd.md` F20, P1]. 허락받은 가족은 생활 요청을 보고 대신 요청할 수도 있다(고장·수리, 청소, 세탁, 외출 차량) [사실: N1 `prd.md` F15, P1]. 승인 문장: "이은숙 회원님이 보여 주기로 한 생활 요청이에요."(N1 value-prop).
- **에셋 자리:** CAP-4(FAM-06a 보호자 소식 첫 화면), CAP-5(FAM-01 회원님이 가족마다 보여 줄 것 정하기), ILL-2.

- **데스크톱/모바일:** 1024px 이상 두 캡처를 나란히(왼쪽 회원님이 정하는 화면 → 오른쪽 가족이 보는 화면, 순서가 뜻) [가설]. 아래는 같은 순서로 쌓음.

### LND-07 도움이 더 필요해질 때
- **목적:** 도움이 더 필요해지면 무엇이 달라지는지 먼저 알려 드리고, 단계는 사람이 설명하고 정한다는 점을 알린다 [사실: C value-prop 1].

- **에셋 자리:** CAP-6(TRN-09 회원 화면 "그대로예요"와 "더해진 도움"), ILL-3.
- **상호작용:** 없음.
- **데스크톱/모바일:** 1024px 이상 글 + 캡처 2단, 아래 1단.
- **접근성:** 캡처 대체 텍스트에 "그대로인 것: 방, 입주 계약, 급할 때 연락할 분" 사실을 적는다.
- **애니메이션 의도:** 스크롤 등장만. 차분하게.

### LND-13 도움이 필요하실 때(안심·건강 지원)
놓이는 곳: LND-07 뒤, LND-08 앞. ID는 기존 번호를 바꾸지 않으려고 13을 붙였다.
- **목적:** 도움이 필요할 때 직원이 어떻게 오고, 병원에 가셔야 할 때 누가 무엇을 하며, 평소 살핌은 회원님이 동의한 만큼이라는 것을 차분하게 보여 준다 [사실: 허브 요청, `prd.md` 12절].
- **문구 자리:** 제목과 세 단계 요약(부르세요 → 직원이 찾아가요 → 기록이 남아요) `[NEED: 카피 C-35]`. 카피 C-35 문구(B copy 4-1에서 만듦): "부르세요. 호출벨을 누르시면 당번 직원에게 바로 알려요. 침대 센서가 알릴 때도 마찬가지예요." / "직원이 찾아가요. 당번 직원이 바로 받지 못하면 다른 직원에게도 알려요." / "급하시면 119에 바로 전화하셔도 돼요." 쓰지 않음: 응급, 위험, 낙상, 쓰러짐, 배회, "출동 n분", "24시간 지켜 드려요", "놓치지 않아요", 진단·치료를 한다는 문장 [사실: 허브 지시, B product-marketing Never use].
- **에셋 자리:** IMG-SAFE-VISIT(밤, 호출을 받고 숙소에 온 직원이 회원님과 눈높이를 맞추고 이야기), 영상 VID-SAFE-VISIT(5초). 단계 목록 옆에 Lucide 아이콘(U-08). CAP-2(SAF-09 회원 화면에서 호출 중 상태만 잘라 씀, LND-05에서 옮김).
- **상호작용:** 섹션 끝 글자 링크 → `/safety`. 영상은 보일 때 한 번 재생하고 마지막 장면에서 멈춤(LND-04 규칙).
- **데스크톱/모바일:** 1024px 이상 이미지 왼쪽(16:9) + 세 단계 오른쪽, 아래는 이미지 → 단계 → 링크.
- **접근성:** 세 단계는 `ol`, 영상 `aria-hidden`, 움직임 줄이기면 포스터.
- **애니메이션 의도:** 단계가 차례로 나타남(전체 300ms 이하). 경고처럼 보이는 깜빡임·흔들림·빨간 강조 없음.

### LND-10 상담·전화·방문
- **목적:** 다음 걸음을 하나로 모은다. 상담 신청이 주 행동, 전화가 앱 밖 경로, 방문 상담은 상담 방법의 선택지 [가설]. **실제 접수 기능은 [미정]**이고 첫 버전은 보내지 않는 목업이다.

#### SITE-DINE-06 드시지 않는 날과 청구서
- **목적:** 드시지 않는 끼니가 어떻게 청구서에 반영되는지.
- **내용 [사실: 코어 `prd.md` 결식 감면 규칙·F6, 코어 copy 3절]:** 드시지 않을 날을 미리 프런트에 말씀하시면 직원이 등록한다(접수 경로가 남는다). 그 끼니는 청구서에서 빼 드리고, 청구서에 "드시지 않은 식사 ○끼, ○원을 빼 드렸어요."처럼 이유가 보인다. 회원이 앱에서 직접 알리는 기능은 코어 다음 버전 후보로 넘겼고(U-20, 2026-11-04) 사이트에는 프런트 길만 쓴다. 장기 부재 때 식사 처리는 사이트에 쓰지 않는다(U-22).
- **문구 자리:** `[NEED: 카피 C-47]`. 회원 화면 말 "드시지 않은 식사"를 쓰고 "결식", "차감"은 쓰지 않는다 [사실: 코어 product-marketing Words to avoid].

- **상호작용:** 프런트 전화 버튼(가상 번호 처리). 메인 LND-05로 가는 글자 링크.
- **데스크톱/모바일:** 글 + 캡처 2단, 아래 쌓음.
- **접근성:** 캡처 대체 텍스트는 청구서의 감면 문장.
- **애니메이션 의도:** 없음.
