## 대안 경로 (디지털이 어려운 회원)
- **직원이 읽어 드림**: 프런트(FD)가 회원 화면과 같은 내용을 읽는다. 회원 화면 정책에 FRONT 직무를 둔 이유다.
- **말로 하기**: 설명과 의견은 원래 대면이다. 회원이 화면을 쓰지 않아도 흐름 1이 끝난다.
- **전화나 프런트 요청**: [다시 봐 주세요]는 프런트나 전화로도 받고 경로를 남긴다(P1).
- **함께하는 사람**: 대리인(회원 화면에서는 "대신 처리하실 분") 또는 회원이 고른 가족이 설명 자리에 함께한다. 의견은 회원 본인의 말로 적는다.

## 읽어 낸 것
- 백스테이지가 몰리는 곳은 흐름 1-5(결정) 한 트랜잭션이다. 단계 구간, 서비스 시간, 계약 변경 요청, 건강 소식 아웃박스가 함께 바뀐다. 테스트를 이 지점에 모은다(`tech-design.md` 11절).
- 회원이 기다리는 긴 구간은 결정 대기(흐름 1-3 → 1-5)와 계약 변경 전(흐름 2-2 → 코어 Next)이다. 두 구간 모두 회원 화면에 지금 상태를 쓴다(copy 3-4, 3-1 "내실 돈").
- 계약 변경 요청은 MVP에서 C 안에서 끝난다. 코어 계약 변경 API가 생기기 전까지 "결정 = 계약 반영"으로 읽히지 않게 경리 화면과 회원 화면에 "계약 변경 전"을 보인다.
