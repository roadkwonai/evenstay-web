# 화면 라벨 — senior-ai-assistant (Evenstay 홈 비서 / AI 생활 비서)

상태: 승인(2026-11-03) · 작성: 2026-11-03 · 변경: 2026-11-03 G 기획 반영(사용자 재승인 2026-11-03) · 변경: 2026-11-03 숫자 가림(사용자 재승인 2026-11-03) · 변경: 2026-11-03 직원 화면 이름 한글화(사용자 결정 2026-11-03) · 변경: 2026-11-03 브랜드 뒷말 한글 표기(사용자 결정, 사용자 재승인 2026-11-03) · 변경: 2026-11-04 공용 문구 확정안(사용자 결정, 사용자 재승인 2026-11-04)
이름은 확정돼 있어 `product-name` 스킬은 쓰지 않았다. 회원 화면은 **Evenstay 홈 비서**, 직원 화면은 **AI 생활 비서**다(`../pms-core-billing/names.md` v3 조합 1, 2026-11-02 확정. 직원 화면 이름은 2026-11-03에 한글로 바꿨다). 여기서는 화면 안 라벨만 정한다.
입력: 이 폴더 `product-marketing.md` 용어집, 코어 `../pms-core-billing/product-marketing.md` 용어집, D `../family-consent-portal/names.md`.

**라벨 원칙**
- 회원 화면에서 영문 이름은 첫 화면 제목에만 쓰고 한글 읽기를 붙인다. 메뉴와 버튼은 "비서"라고만 쓴다.
- 회원 화면 버튼은 회원님이 하는 동작이나 묻는 말로 쓴다("계약·청구서 날짜", "이번 달 청구서 설명").
- **조회 도구 하나 = 큰 버튼 하나.** 쓰기 도구(청구 문의 접수, 직원에게 넘기기)는 확인 화면 하나를 갖는다. 모듈이 붙으면 같은 꼴의 버튼을 더한다(3절).
- 직원 화면은 업무 용어(대화 기록, 넘겨받은 요청, 도구 호출)를 쓰고, 입주자를 "입주자"로 부른다.

**keyDates 라벨** (일정 조회 답에서 쓰는 말)
| 코드 | 직원 화면 | 회원 화면 |
|---|---|---|
| `moveInDate` | 입주일 | 입주하신 날 |
| `contractEndDate` | 계약 만료일 | 계약이 끝나는 날 |
| `lastInvoiceIssuedOn` | 최근 청구 발행일 | ○월 청구서가 나온 날 |
| `lastInvoiceDueDate` | 최근 청구 납부 기한 | ○월 ○일까지 내시면 돼요 (코어 용어집 Invoice.due_date와 같은 말) |
| `nextInvoiceScheduledOn` | 다음 청구 예정일 | 다음 청구서가 나올 날 |
| (BillingSchedule, 확인한 곳 표시) | 청구 일정 | 레지던스가 정한 청구서 날짜 (코어 용어집은 회원 화면에 "청구 일정"을 표시하지 않는다) |
| `moveOutDate` | 퇴거 예정일 | 이사 나가실 날 |

- 검토했다가 쓰지 않은 말: "AI 도우미"(메뉴 이름에 AI를 넣으면 짧지 않다), "챗봇"(외래어), "물어보세요"(버튼이 아니라 문장이다), "다음 일정", "오늘 일정", "내 일정"(최소판 데이터로 채울 수 없다), "만기"(회원에게 금융 용어로 읽힌다), "상담"(전문 상담으로 오해).

## 2. 직원 화면 (AI 생활 비서)
| 위치 | 라벨 |
|---|---|
| 메뉴 | 대화 기록 · 넘겨받은 요청 · 도구 호출 기록 |
| 넘겨받은 요청 상태 | 새 요청 · 처리 중 · 처리 완료 |
| 넘긴 이유 (HandoffReason) | 건강 판단 · 금전 판단 · 계약 판단 · 도구 밖 질문 · 직접 요청 |
| 도구 이름 (최소판) | 코어 도구: 일정 조회 · 청구 설명 · 청구 문의 접수 / 비서 도구: 직원에게 넘기기 |
| 호출 결과 | 성공 · 권한 거부 · 데이터 없음 · 오류 |
| 행위자 | 입주자 본인 · 대리인(범위 표시) |

- "직접 요청"은 회원님이나 대리인이 [직원에게 전하기]를 직접 누른 경우와, 코어 청구 문의 기능이 없을 때 [이 금액이 이상해요]가 넘기기로 대신 가는 경우다(MEMBER_ASKED). 처음 정한 "입주자 요청"은 대리인이 누른 경우에 맞지 않아 바꿨다(2026-11-03). 누가 요청했는지는 행위자 열이 보여 준다.
- 투자 질문을 넘기면 이유는 금전 판단이다(G 기획 확정).
- 상태 세 개는 코어 확인 창 형식처럼 짧은 명사로 둔다. 처리 기한 표시는 [NEED: 운영사가 정한 회신 기한].

- 버튼 이름은 "명사 + 짧은 동작"(○○ 설명, ○○ 보기)으로 맞춘다. 직원 화면 도구 이름은 "○○ 조회", "○○ 설명", "○○ 접수"처럼 동작 명사로 맞춘다.
- 큰 버튼이 다섯 개를 넘으면 첫 화면에 자주 쓰는 것 넷과 [더 보기]만 둔다 [가설: 화면 테스트에서 확인].
