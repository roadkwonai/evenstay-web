**범위 (최소 버전)**
- 코어 도구 세 개(조회 두 개 + 청구 문의 하나)와 비서 자체 넘기기 하나(G 기획 확정, 2026-11-03).
  - **일정 조회**(`ContractQuery.keyDates`: 입주일, 계약 만료일, 최근 청구 발행일, 최근 청구 납부 기한, 다음 청구 예정일, 퇴거 예정일)
  - **청구 설명**(`BillingQuery.explainInvoice`: 항목별 `plain` 재료와 근거)
  - **청구 문의 접수**(`InquiryCommand.createInquiry`, 쓰기, P1. 코어 청구 문의 기능이 없으면 직원에게 넘기기로 대신한다)
  - **직원에게 넘기기**(비서 자체, 쓰기)
- 쓰기 두 개는 회원 확인 뒤에만 실행된다. 큰 버튼은 AI 없이 답 틀로 답한다(G 기획 확정).
- 비서가 직접 갖는 것: 대화 기록, 도구 호출 기록, 직원에게 넘긴 요청.
- 없는 것: 시설 프로그램·행사·병원 일정, 늦게 냈을 때의 처리, 시설 요청 접수, 보호자용 비서, 자산 조회.

**표기**
- 예시는 G 데모 장면이다(G prd 9절): A동 201호 이은숙 회원, 1인 계약, 데모 시계 2027-01-05. 12월 청구서: 생활비 2,100,000 + 식비 837,000(31일 × 3끼 = 93끼 × 9,000) − 드시지 않은 식사 27,000(3끼 × 9,000) = 2,910,000원. 금액은 코어 copy 3절 3월 예와 같고 달만 다르다.
- 청구 날짜는 코어 청구 일정 기본값 제안(매월 말일 발행, 발행 후 10일 납부 기한)을 12월 청구서에 적용했다: 발행 2026-12-31, 납부 기한 2027-01-10, 다음 청구 예정일 2027-01-31.
- 계약 날짜: 입주일 2026-10-01(G prd 9절), 계약 만료일 2028-09-30 [가설: 코어 시드. 승계한 계약이 이 날짜를 이어받는다]. 퇴거 예정일은 없다.
- 대화 원문 보관 기간 1년은 **[운영사 기준 초안, 법률 검토 전]**이다(G prd 12절).
- **[운영사 기준 초안]**: 법령이 아니라 운영사가 정해야 하는 규칙. 이 문서는 예시안이다.

**답의 틀** (모든 도구가 같은 틀을 쓴다. B·D·C 도구가 붙어도 바꾸지 않는다)
1. 첫 줄: 물으신 것에 대한 답 한 문장.
2. 둘째 줄부터: 사실 한 줄에 하나, 세 줄 넘지 않게.
3. 마지막 줄: `확인한 곳: ○○` (도구가 읽은 기록 이름).
4. 답 아래 버튼: 이어서 물을 것 하나 + [직원에게 전하기].

## 1. 포트폴리오 소개 (README, 면접 자료)
**제목**
> Evenstay 홈 비서: 계약과 청구 기록으로만 답하고, 판단은 사람에게 넘기는 AI 비서

**부제**
> 회원이 큰 버튼이나 말로 계약 날짜와 이번 달 청구서를 묻습니다. 비서는 코어 PMS의 API 세 개(조회 두 개, 청구 문의 하나)만 도구로 부르고, 모르는 일과 판단이 필요한 일은 회원 확인을 받아 직원에게 넘깁니다.

**문제** (한 단락)
> 시니어 레지던스 회원이 청구서 금액이나 계약 날짜가 궁금하면 프런트에 전화하거나 앱 메뉴를 찾아야 합니다. 만 55세 이상 중 AI 서비스를 써 본 사람은 30.2%로, 일반 국민(59.4%)의 절반 정도입니다. 범용 AI 비서는 회원의 계약과 청구서를 모르고, AI 안부전화는 시설 업무와 이어지지 않습니다. AI가 회원과 직접 이야기하려면 AI 기본법(2026-01-22 시행)에 따라 미리 알려야 하고, 건강·돈·계약 판단을 하지 않도록 막아야 합니다.

근거: G3 2025 디지털정보격차 실태조사(과기정통부·NIA, 2026-03-26 발표. 보도 https://www.mt.co.kr/tech/2026/03/27/2026032710093798860 ), G4 AI 기본법 제31조 사전 고지(로펌 요약 https://shinkim.com/kor/media/newsletter/3114 , 법 원문 대조 안 함 [미확인]), ai-assistant.md 2절(범용 비서·AI 안부전화. E7, E15), G5·G15·G21(판단은 사람에게). 출처 목록: `senior-lab/01-research/sources/axis9-senior-ai-assistant.md`.

**무엇을 만들었나**
1. **조회 도구 두 개, 확인한 곳이 붙는 답**
   일정 조회는 계약과 청구 날짜를, 청구 설명은 청구서 항목과 그 근거를 읽습니다. 비서는 금액을 계산하지 않고, 답마다 어느 기록에서 확인했는지 붙입니다. 큰 버튼은 AI를 부르지 않고 정해진 답 틀로 답합니다.
2. **모르면 모른다고 하고, 판단은 사람에게**
   도구 밖 질문에는 모른다고 답하고 프런트 전화를 보여 줍니다. 건강, 돈, 계약을 정해야 하는 말은 회원에게 한 번 더 묻고 직원에게 넘기며, 넘긴 이유를 남깁니다.
3. **모든 호출이 남는 기록**
   직원 화면에서 대화, 도구 호출, 권한 검사 결과, 넘긴 요청을 봅니다. 효과 수치를 주장하지 않고, 넘긴 비율과 권한 거부 건수를 이 기록으로 잽니다.

**설계에서 먼저 정한 것** (면접관용)
- 비서는 새 데이터를 만들지 않는다. 코어 API를 도구로 부르고, 권한은 코어 `Authorization`이 회원 본인·대리인 범위로 검사한다.
- 상태를 바꾸는 호출(청구 문의 접수, 직원에게 넘기기)은 회원 확인 토큰이 없으면 서버가 거부한다.
- 조회 도구 하나 = 회원 화면 큰 버튼 하나 + 답 틀 하나 + 직원 화면 기록 한 줄. 쓰기 도구 하나 = 확인 화면 하나 + 기록 한 줄. B, D, C 모듈이 붙어도 같은 틀이다.
- AI 사용 고지를 확인하기 전에는 비서를 열지 않는다. 고지 문구와 확인 기록은 D(I-42)가 갖는다.

**CTA**
> 데모 열기

**데모 안내 문구**
> A동 201호 이은숙 회원님으로 들어와 있습니다. 오늘은 2027년 1월 5일이고, 12월 청구서(2,910,000원)가 나와 있습니다. 큰 버튼 두 개를 누른 다음, 비서가 모르는 질문도 해 보세요. 마지막에 직원 화면에서 기록을 열어 보세요.

데모에서 말로 묻기는 실제 AI 대신 미리 녹화한 응답을 씁니다(G tech-design ADR-G6). 이 사실을 데모 안내 아래에 한 줄로 밝힌다: "말로 묻기는 실제 AI로 미리 받아 둔 응답을 씁니다. 진행자가 실제 AI로 바꿀 수 있습니다."

### 2-4. 청구 설명 답 ([이번 달 청구서 설명] 또는 청구서를 물었을 때)
"이번 달 청구서"는 가장 최근에 나온 청구서다. 말일에 나오므로 달 초에는 지난달 청구서다(데모 1월 5일 → 12월 청구서).

| 위치 | 문구 |
|---|---|

### 2-5. 모를 때와 못 할 때
비서는 짐작하지 않는다. 답할 수 없는 이유는 한 문장으로만 말하고, 다음에 할 일을 버튼으로 보인다.

| 상황 (회원님 말 예) | 답 | 버튼 |
|---|---|---|
| 도구 밖 질문: 프로그램 ("오늘 무슨 프로그램 있어요?") | 프로그램 일정은 제가 아직 몰라요. 프런트에 물어보시면 알려 드려요. | 프런트로 전화하기 · 직원에게 전하기 |

| 건강 ("이 약 먹어도 돼요?") | 약과 건강은 제가 답할 수 없어요. 급하시면 119나 프런트로 바로 전화해 주세요. 급하지 않으시면 직원에게 전해 드릴까요? | 네, 전해 주세요 · 프런트로 전화하기 |

### 2-7. 대리인이 쓸 때 (P1, 코어 대리인 기능 이후)

| 상세: 생활 요청으로 보내지 못했을 때 (새 요청에 더함) | 생활 요청으로 보내지 못해 이 목록에 새 요청으로 남겼습니다. 여기서 처리해 주세요. |
| 넘긴 이유가 금전 판단일 때 | 금전에 관한 요청입니다. 직원은 입주자의 돈, 통장, 카드, 비밀번호를 대신 다루지 않습니다. [NEED: D 5-3 금전 부탁 접수와 연결] |

| 넘긴 이유가 건강 판단일 때 | 건강에 관한 요청입니다. 비서는 건강을 판단하지 않았습니다. 담당 직원이 입주자를 직접 확인해 주세요. |
| 넘긴 이유가 계약 판단일 때 | 계약에 관한 요청입니다. 계약 변경은 Evenstay Core의 입주 계약 화면에서 처리합니다. |
| 행위자가 대리인일 때 | 대리인 김태호(청구서 확인, 결제)가 이은숙 입주자 대신 전한 요청입니다. |
| 청구 문의 안내 (목록 위) | 청구 문의는 이 목록에 오지 않고 Evenstay Core의 "입주자가 문의한 청구"로 갑니다. 코어 청구 문의 기능이 없을 때만 여기에 "직접 요청 · 청구서"로 옵니다. |
| 버튼 | 처리 시작 · 처리 완료 |
| 처리 완료 메모 | 처리한 내용과 입주자에게 알린 방법을 적어 주세요. |
| 메모가 비었을 때 | 처리 내용을 적어야 처리 완료로 바꿀 수 있습니다. |
| 빈 상태 | 넘겨받은 요청이 없습니다. |
| 빈 상태 (생활 요청으로 보냄) | 생활 요청으로 보낸 요청이 없습니다. |

- **생활 요청으로 보냄** (G tech-design 8-1 AST-09, US-07 9, US-08 7 [가설]): 생활 요청(N1)이 배포돼 있으면 도구 밖 질문과 직접 요청(주제 그 밖의 일)은 넘길 때 생활 요청으로 보낸다. 건강·금전·계약 판단과 대리인이 전한 요청은 보내지 않고 이 목록에서 처리한다.
- "처리할 요청"은 기본 필터로, 새 요청과 처리 중을 보인다. "생활 요청으로 보냄" 줄에는 처리 버튼이 없고 [생활 요청 보기]만 있다. 같은 일이 두 목록에 처리할 일로 함께 뜨지 않게 하려는 것이다. [생활 요청 보기]는 N1 직원 요청 상세(`senior-lab/03-copywriting/ideas/life-requests/copy.md` 4-10)로 간다.
- 회원 화면은 바뀌지 않는다. 생활 요청으로 보내도 회원은 2-6 "전한 뒤" 문구를 그대로 본다(US-07 9).
