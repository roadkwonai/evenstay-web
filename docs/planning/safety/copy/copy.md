## 1. 포트폴리오 소개 (README, 면접 자료 첫 장)
**제목**
> 안심 알림: 흩어진 안전 신호를 모아 직원에게 넘기는 허브

대안
- A. "밤사이 들어온 신호를 한곳에 모으고, 누가 무엇을 했는지 남깁니다" — 결과를 말하지만 길다.
- B. "센서는 알리고, 사람이 판단합니다" — 경계를 잘 보이지만 무엇을 만들었는지가 안 보인다.
- 고른 것: 제목은 무엇을 만들었는지, 부제에서 결과를 말한다.

**부제**
> 침대 센서, 호출벨, 출입 기록, 안부 전화의 신호를 한 화면에 모읍니다. 5분 동안 아무도 확인하지 않으면 다음 담당자에게 넘기고, 누가 언제 무엇을 했는지 남깁니다.

**문제** (한 단락)
> 간호 인력이 낮에만 머무는 시니어 레지던스가 있습니다(평창카운티 08~19시, 2025년 3월 보도). 침대 센서, 호출벨, 출입 기록, 외부 안부 전화 서비스는 각자 따로 알림을 보냅니다. 이 알림을 밤에 기기마다 따로 받으면, 누가 어떤 알림을 받았고 무엇을 했는지 한곳에 남기기 어렵습니다. 현장에서 이 때문에 신호를 놓친 사례는 아직 확인하지 못했습니다. 종사자 인터뷰로 확인할 가설입니다.

**무엇을 만들었나** (세 묶음, 묶음마다 한 가지 주장)
1. **어떤 기기든 같은 모양의 신호로**
   어댑터가 기기·업체마다 다른 형식을 하나의 신호 형식으로 바꿉니다. 기기를 바꾸거나 늘려도 직원 화면과 기록은 그대로입니다. 같은 이벤트 번호가 다시 오면 기록만 하고 알림은 다시 보내지 않습니다. 늦게 도착한 신호는 생긴 시각 순서로 다시 정리합니다.
2. **아무도 맡지 않은 알림이 남지 않게**
   사업장 규칙이 등급을 붙여 당번에게 보냅니다. 5분 동안 확인이 없으면 2차, 3차 담당자에게 차례로 넘기고, 3차도 확인하지 않으면 당번 모두를 부릅니다. 넘긴 시각과 받은 사람이 모두 남습니다.
3. **판단은 사람이, 기록은 시스템이**
   알림에는 관찰된 사실만 씁니다. 상태 판단과 119 신고는 직원이 하고, 시스템은 그 결과를 기록합니다. 결과는 회원이 건강 소식을 보여 주기로 한 보호자에게만, 직원이 조치를 기록한 뒤에 보입니다.

**설계에서 먼저 정한 것** (면접관용, 짧게)
- 신호 하나의 수명을 상태로 남긴다: 수신 → 중복 확인 → 규칙 → 알림 → 넘김 → 조치 → 보호자 알림.
- 중복 판단 기준은 출처와 업체 이벤트 번호의 조합이다. 웹훅이 다시 와도 한 건이다.
- 넘김 타이머는 알림마다 두고, 누가 확인하면 멈춘다.
- 판단 단어를 쓰지 않는다는 규칙은 화면 문구 단계에서 먼저 정했다.

**CTA**
> 데모 열기

**데모 안내 문구**
> 시뮬레이터로 침대 센서, 호출벨, 출입 기록 신호를 보내 보세요. 같은 신호를 두 번 보내도 알림은 한 번 갑니다.

### 2-5. 5분 무응답 넘김 (에스컬레이션)
넘김은 1차 → 2차 → 3차(당직 책임자) → 모두 호출 순서다. 등급마다 같은 간격(즉시 확인 5분, 확인 필요 15분)으로 넘긴다 [가설: 기획 제안값, 2026-11-03 사용자 확정].

| 위치 | 문구 |
|---|---|

### 2-11. 전화로 받은 호출 등록 (프런트 직원)
입주자가 프런트로 전화해 도움을 청하면 직원이 등록한다. 호출벨과 같은 알림으로 당번에게 가고, 넘김과 기록도 같다.

| 창 안내 | 전화한 입주자의 호실과 이름을 고르세요. 즉시 확인 알림으로 당번에게 바로 갑니다. |

### 2-12. 기기 연결과 장치 동의 (프런트 직원, 사업장 책임자)
기기, 출입 카드, 안부 전화 가입을 입주자와 잇는 화면이다. 침대 센서, 출입 기록, 안부 전화는 입주자의 동의를 기록해야 연결되고, 호출벨은 동의 없이 연결된다. 장치 동의는 보호자 동의(건강 소식)나 비상 연락처 등록 동의와 따로다.

| 위치 | 문구 |
|---|---|
| 화면 제목 | 기기 연결 |
| 화면 안내 | 침대 센서, 출입 기록, 안부 전화는 입주자의 동의를 기록해야 연결됩니다. 호출벨은 동의 없이 연결됩니다. |
| 첫 화면 할 일 | 기기 연결이 필요한 입주자 {n}명 [보기] |
| 할 일 목록 제목 | 기기 연결이 필요한 입주자 |
| 할 일 한 줄 | {호실} {이름} 입주자, {입주일} 입주, 아직 연결된 기기가 없습니다. [연결하기] |
| 할 일이 없을 때 | 기기 연결이 필요한 입주자가 없습니다. |
| 연결 목록 열 | 기기 · 호실 · 입주자 · 장치 동의 · 연결 기간 |
| 연결 한 줄 예 | 침대 센서, A동 201호, 이은숙 입주자, 동의 {날짜} {시각}(받은 직원 {이름}, 본인), {날짜}부터 |
| 끝난 연결 한 줄 예 | 침대 센서, A동 201호, 김한결 님, 계약 승계로 11월 10일에 연결이 끝났습니다 |
| 연결 목록이 비었을 때 | 아직 연결한 기기가 없습니다. [기기 연결하기] |
| 연결 창 제목 | 기기 연결하기 |
| 입력 칸 | 기기 · 입주자 · 장치 동의 |
| 장치 동의 칸 | 동의한 날짜와 시각 · 동의를 받은 직원 · 동의한 분(본인 / 대리인) |
| 장치 동의 안내 | 이 장치가 언제 직원에게 알리는지 입주자에게 설명하고 동의를 받은 뒤 적어 주세요. 회원 화면의 "내 방 장치 안내"와 같은 설명을 쓰면 됩니다. |
| 호출벨을 고르면 | 호출벨은 동의 없이 연결됩니다. |
| 저장 버튼 | 연결 저장 |
| 저장 뒤 안내 | 연결했습니다. 이제 이 기기의 신호는 {이름} 입주자의 알림으로 들어옵니다. |
| 동의가 비었을 때 | 이 장치는 입주자의 동의를 기록해야 연결됩니다. 동의한 날짜와 시각, 동의를 받은 직원, 동의한 분을 적어 주세요. |
| 이미 다른 입주자와 연결된 기기 | 이 기기는 {날짜}부터 {이름} 입주자와 연결되어 있습니다. 한 기기를 두 입주자에게 함께 연결할 수 없습니다. 사업장 책임자에게 알려 주세요. |
| 저장 실패 | 연결을 저장하지 못했습니다. 연결이 잠시 끊겼습니다. 적은 내용은 이 화면에 남아 있으니 [다시 저장]을 눌러 주세요. |
| 기기 연결이 없는 신호 (카드·기록의 입주자 칸) | 연결된 입주자 없음 |
| 위 칸을 눌렀을 때 | 이 기기에 지금 연결된 입주자가 없어 호실만 보여 줍니다. 장치 동의가 없는 기기의 신호는 알림 없이 기록에만 남습니다. [기기 연결 보기] |

| 안부 방문 동의 한 줄 예 | 안부 방문, A동 201호, 이은숙 입주자, 동의 {날짜} {시각}(받은 직원 {이름}, 본인) |
| 비상 때 도움 필요 칸 (직원 대행) | 비상 때 도움 필요 |
| 도움 필요 칸 안내 | 비상 때 대피하시려면 직원 도움이 필요하다고 입주자, 보호자, 대리인에게 들었으면 고르세요. 이유는 적지 않습니다. |
| 도움 필요 기록 칸 | 들은 사람(본인 / 보호자 / 대리인) · 들은 직원 · 들은 날짜와 시각 |
| 도움 필요 한 줄 예 | 비상 때 도움 필요 · A동 201호 · 이은숙 입주자 · {날짜} {시각} {이름} 님이 본인에게 들음 |

### 2-13. 규칙과 당번표 설정 (사업장 책임자)
사업장 책임자와 본사 관리자, 운영 매니저만 바꿀 수 있다(`tech-design.md` 6-2 `config.edit`). 규칙을 바꾸면 새 버전이 생기고, 이미 생긴 알림은 바꾸기 전 버전을 따른다.

| 위치 | 문구 |

| 화면 제목 | 규칙과 당번표 |

| 규칙 한 줄 예 | 밤 침대 떠남 30분, 침대 센서, 22:00~06:00, 즉시 확인, 넘김 5분, 버전 1 [바꾸기] |
| 규칙 칸 | 이름 · 출처 · 조건 · 시간대 · 등급 · 넘김 간격 · 보호자 문장 틀 |

| 보호자 문장 틀 안내 | 보호자 건강 소식의 첫 문장입니다. 본 것과 직원이 한 일만 쓰세요. {날짜}, {시각}, {장소}를 넣을 수 있습니다. |
| 저장 전 안내 | 저장하면 이 규칙의 새 버전(버전 2)이 생깁니다. 이미 들어온 알림은 바꾸기 전 규칙대로 남습니다. |
| 버튼 | 저장 · 취소 |
| 저장 뒤 안내 | 규칙을 저장했습니다. 지금부터 들어오는 신호에는 버전 2를 씁니다. |
| 5개가 다 찼을 때 | 규칙은 5개까지 둘 수 있습니다. 지금 5개가 있어 새로 만들 수 없습니다. 있는 규칙을 바꿔서 쓰세요. |
| 보호자 문장 틀에 쓸 수 없는 말 | 보호자 문장 틀에 쓸 수 없는 말이 들어 있습니다("{단어}"). 본 것과 직원이 한 일로 바꿔 써 주세요. |
| 칸이 비었을 때 | {칸 이름} 칸을 채워야 저장됩니다. |
| 당번표 탭 안내 | 근무 시간대마다 1차(당번), 2차, 3차 자리를 정합니다. 비워 둔 자리는 건너뛰고 다음 자리로 넘깁니다. |

| 자리 고르기 | 직원 고르기 · 비워 두기 |
| 당번표 저장 뒤 안내 | 당번표를 저장했습니다. 바꾼 사람과 시각은 변경 이력에 남습니다. |

### 2-14. 처리 실패 신호 (본사 관리자)
형식을 알 수 없어 처리하지 못한 신호의 원본을 보고 다시 처리하는 화면이다. 알림 화면의 안내는 5절 "형식을 알 수 없는 신호"를 쓴다.

| 위치 | 문구 |
|---|---|
| 화면 제목 | 처리 실패 신호 |
| 상태 라벨 | 처리 실패 |
| 한 줄 예 | 02:31, 출입 기록 업체, 처리 실패, 형식을 알 수 없음 [원본 보기] [다시 처리] |
| 원본 화면 안내 | 출입 카드 참조값과 이름은 가려서 보여 줍니다. |
| 다시 처리 확인 | 어댑터 설정을 고친 뒤 다시 처리하세요. 이미 들어온 신호와 이벤트 번호가 같으면 한 건으로 남습니다. [다시 처리] [취소] |
| 다시 처리 뒤 | 다시 처리했습니다. 신호 목록에서 확인해 주세요. |
| 다시 처리도 실패 | 이번에도 처리하지 못했습니다. 원본은 그대로 보관했습니다. 어댑터 설정을 다시 확인해 주세요. |
| 빈 상태 | 처리하지 못한 신호가 없습니다. |


### 2-15. 안부 방문 (낮·야간 직원)
안부 방문 받기에 동의한 입주자의 방에 정한 시간대 안에 들러 결과를 고른다. 상태를 판단하는 칸은 없다. 시간대가 끝날 때까지 기록이 없으면 출처 "안부 방문"의 신호가 생겨 다른 알림과 같이 넘어간다. 시간대 10:00~18:00은 시드 값이다 [가설].

| 위치 | 문구 |
|---|---|
| 화면 제목 | 안부 방문 |
| 화면 안내 | 오늘 들를 방입니다. 안부 방문 받기에 동의한 입주자만 나옵니다. 방문 시간대 10:00~18:00 |
| 진행 요약 | 오늘 {n}곳 중 {n}곳 기록함 · 남은 곳 {n}곳 |
| 목록 한 줄 (기록 전) | A동 201호 이은숙 입주자 · 아직 기록 없음 [결과 고르기] |
| 결과 선택지 | 다녀왔습니다 · 방에 계시지 않았습니다 · 입주자가 방문을 원하지 않으셨습니다 |
| 목록 한 줄 (기록 뒤) | A동 201호 이은숙 입주자, {시각} 다녀왔습니다, 기록: {이름} 님 |
| "방에 계시지 않았습니다"를 고르면 | 이 결과는 기록에만 남고 알림은 가지 않습니다. |
| 부재 중인 입주자 줄 | {호실} {이름} 입주자, 부재 중, 오늘은 들르지 않습니다 |
| 모두 기록했을 때 | 오늘 들를 곳을 모두 기록했습니다. |
| 빈 상태 | 오늘 들를 곳이 없습니다. |
| 저장 실패 | 기록을 저장하지 못했습니다. 연결이 잠시 끊겼습니다. 고른 결과는 이 화면에 남아 있으니 [다시 저장]을 눌러 주세요. |
| 출처 라벨 | 안부 방문 |
| 놓친 방문 카드 | **확인 필요** · A동 201호 이은숙 입주자 · 오늘 안부 방문 기록이 아직 없습니다. · 18:00 · 출처: 안부 방문 · 규칙: 안부 방문 놓침 · [확인하러 갑니다] |
| 놓친 방문 카드 안내 | 방에 들러 안부를 여쭌 뒤 안부 방문 화면에 결과를 골라 주세요. |

### 2-16. 병원 동행과 병원에 가신 분 (야간 직원, 아침 근무자)
조치 기록에서 "병원으로 가심"을 고르면 동행 직원과 출발 시각 칸이 열린다(2-4). 돌아오신 시각은 나중에 덧붙이고, 처음 기록은 고치지 않는다. 병원 이름, 진료 내용, 진단명 칸은 없다.

| 위치 | 문구 |
|---|---|
| 목록 제목 | 병원에 가신 분 |
| 목록 안내 | 돌아오신 시각을 기록할 때까지 이 목록에 남습니다. 근무가 바뀌어도 보입니다. |
| 목록 한 줄 | A동 201호 이은숙 입주자, 03:20 출발, 동행 박서준 님 · [돌아오셨습니다] |
| 동행 없이 가셨을 때 | A동 201호 이은숙 입주자, 03:20 출발, 동행 직원 없음 · [돌아오셨습니다] |
| 부재 중으로도 등록된 분 | A동 201호 이은숙 입주자, 부재 중, 03:20 출발, 동행 박서준 님 · [돌아오셨습니다] |
| [돌아오셨습니다]를 누르면 | 돌아오신 시각을 적어 주세요. |
| 돌아오심 기록 뒤 | {시각}, 돌아오셨습니다, 기록: {이름} 님 |
| 목록이 비었을 때 | 병원에 가신 분이 없습니다. |

### 2-17. 부재 중 표시
코어에 장기 부재가 열려 있는 입주자에게 붙는다. 그동안 침대 센서, 밤 정문 출입, 안부 방문 알림은 멈추고 신호는 기록에만 남는다. 호출벨과 프런트 전화는 그대로 알린다. 부재 이유와 종류는 받지도 보이지도 않는다.

| 위치 | 문구 |
|---|---|
| 카드·목록의 표시 | 부재 중 |
| 표시를 눌렀을 때 | 이 입주자는 지금 부재 중입니다. 침대 센서, 밤 정문 출입, 안부 방문 알림은 멈추고 신호는 기록에만 남깁니다. 호출벨과 프런트 전화는 그대로 알립니다. |
| 부재 중인 입주자 목록 제목 | 부재 중인 입주자 |
| 목록 한 줄 | {호실} {이름} 입주자 · {날짜}부터 부재 중 |
| 목록이 비었을 때 | 지금 부재 중인 입주자가 없습니다. |
| 부재 정보를 불러오지 못했을 때 | 부재 정보를 지금 불러오지 못했습니다. 그동안은 모든 알림을 평소대로 보냅니다. |


### 2-18. 호실 현황 (사업장 책임자, 직원)
호실마다 오늘 안부 방문, 부재 중, 기기별 마지막 신호 시각, 처리 중 알림 수를 한 표로 보인다. 직원 화면에만 있고 위치, 영상, 활동량, 상태 판단 칸은 없다.

| 위치 | 문구 |
|---|---|
| 화면 제목 | 호실 현황 |
| 화면 안내 | 호실마다 오늘 안부 방문, 부재 중, 기기별 마지막 신호 시각, 처리 중인 알림 수를 보여 줍니다. |
| 열 이름 | 호실 · 입주자 · 오늘 안부 방문 · 마지막 신호 · 처리 중 알림 |
| 한 줄 예 | A동 201호, 이은숙, 아직 없음, 침대 센서 02:10, 호출벨 {날짜} {시각}, 1건 |
| 오늘 안부 방문 칸 값 | 다녀왔습니다 · 방에 계시지 않았습니다 · 입주자가 방문을 원하지 않으셨습니다 · 아직 없음 · 대상 아님 |
| 부재 중인 호실 | 부재 중 |
| 마지막 신호가 없을 때 | 받은 신호 없음 |
| 처리 중 알림이 없을 때 | 없음 |
| 화면 아래 고정 문구 | 이 표는 기기 신호와 직원 기록으로 만듭니다. 입주자가 지금 어디 계신지는 보여 주지 않습니다. |
| 빈 상태 | 이 사업장에 보여 줄 호실이 없습니다. |

### 2-19. 사고·학대 보고 (알림을 맡은 직원, 사업장 책임자)
알림 상세의 더보기에서 연다. 사람이 본 것과 한 일, 보호자 통보, 신고 여부만 적는다. 학대 여부, 원인, 책임을 정하는 칸은 없다. 저장한 뒤에는 고치지 않고 덧붙인다. 보호자 건강 소식이나 다른 모듈로 나가지 않는다. 신고의무 근거는 노인복지법 제39조의6이고, 이 사업장 직원이 신고의무자에 드는지는 시설 유형에 달려 [미확인]이다(`prd.md` F27). 화면에는 표시 기호 없이 "책임자에게 확인해 주세요"로 안내한다. 신고 기관 목록은 [가설]이다(`tech-design.md` 확인할 것 23).

| 위치 | 문구 |
|---|---|
| 더보기 메뉴 | 사고·학대 보고 쓰기 |
| 화면 제목 | 사고·학대 보고 |
