# 결과 중심 로드맵 — 프로그램·시설·공지 (community)

상태: 승인(2026-11-04, 사용자 "보류된것 승인해") · 변경: 2026-11-04 시드 시작 문장 고침(사용자 재승인 2026-11-04) · 작성: 2026-11-04 · 방법: `outcome-roadmap` 스킬(만들 것 → 이루려는 결과로 바꿔 쓰기, "[누가] [무엇을] 하게 해서 [무엇이 좋아진다]", 결과를 확인할 신호와 순서·의존). 파일 이름은 이 폴더 규칙대로 `roadmap.md`
입력: `strategy.md`, `prd.md` 7·14절, `tech-design.md` 10절(모두 초안)

> 표기 규칙은 `strategy.md`와 같다. 효과 수치와 참여율을 목표로 쓰지 않는다. 포트폴리오에는 실제 이용자가 없으므로 "결과를 확인할 신호"는 데모·테스트에서 보이는 사실이다.
> 기간은 상대 기간이다. 날짜를 약속하지 않는다.

## 전략 맥락
- 비전: 모임 자리, 공용 방의 시간, 꼭 알려야 할 공지를 어느 길로 들어와도 같은 규칙으로 나누고 기록한다(`strategy.md` 1절).
- 북극성 [가설]: 중요 공지가 공지 날 전에 대상 호실 모두에서 확인되거나 직접 전해진 비율. MVP에서는 계산이 맞는지만 보인다.
- 순서 원칙: (1) 자리(정원·대기)와 방(겹침) 규칙을 먼저 단단하게 → (2) 공지 확인 → (3) 다른 모듈로 나가는 조회(D 일정·공지·생활 소식, 운영 현황 카드). 다른 모듈 변경이 필요한 결과는 그 모듈이 준비된 순서로 붙인다.
