# Pre-Mortem: Evenstay Core v1.1 (포트폴리오 MVP)

상태: 초안 · 작성: 2026-11-03 · 방법: `pre-mortem` 스킬(00-hub) · 대상: `04-planning/ideas/pms-core-billing/` prd·tech-design·handoff (v1.1 보강 반영, 재확인 대기)

**실패 가정**: 면접 날 데모가 동작하지 않거나, 동작해도 면접관([지원 회사] Tech Lead 채용)이 "문서는 많은데 백엔드 실력은 안 보인다" 또는 "운영 현실과 다르다"고 판단했다.

**전제** [사실]: 공고는 상시채용이다(`shared/target-companies.md` S2). 지원 마감이 없으니 일정은 지원자가 정한다. 코드는 아직 0줄이다. 코어 P0는 화면 9개, 기능 12개(F1~F12)다. 테스트 기준은 상태 전이·골든 청구·권한 표·격리·멱등·원장 불변·경계 CI·OpenAPI 8종이다(tech-design 11절). B·D 기획 14개 문서가 같은 코어에 기대고 있다.

## Tigers (실제 위험)

| # | 위험 | 근거 | 분류 |
|---|---|---|---|
| T1 | **기획이 커져서 4주 안에 끝나지 않는다.** v1.1에서 역할·직무, 보호자 계정, Notifier, 데모 시계, 조회 API 등 약 20건이 늘었다. 그런데 일정표(prd 14절)는 v1.0 그대로다. 프로토타입(HTML·JS)과 MVP(Next.js)를 두 번 만드는 것도 일정에 들어 있지 않다. | prd 14절 4주 표는 F1~F17만 셈. B·D·G 모듈 구현은 어느 일정에도 없음 | **Launch-blocking** |
| T2 | **면접에서 보여 줄 "한 장"이 없다.** tech-design 497줄, PRD 216줄, 스토리 250줄이다. 면접관은 5분 안에 핵심을 봐야 한다. ADR이 무엇을 왜 골랐는지 한 장으로 요약한 것이 없다. | 05-portfolio 단계가 아직 열리지 않음 | **Launch-blocking** |
| T3 | **통합 데모의 주인공이 정해지지 않았다.** 코어 시드는 201호 부부(김한결·이은숙)이고, B·D 시드는 김말순·김정희다. 코어 v1.1은 두 세트를 다 넣고 주인공을 [미정]으로 남겼다(prd 확인할 것 8). 모듈을 붙이면 데모 이야기가 둘로 갈라진다. | prd 9절 시드, A 보고 | **Launch-blocking** (모듈 데모 착수 전) |
| T4 | **Next.js 위에서 DB 수준 보장(RLS·트리거·아웃박스)을 실제로 돌릴 수 있는지 확인하지 않았다.** RLS를 쓰려면 요청마다 트랜잭션 안에서 `SET LOCAL`로 사업장 범위를 넣어야 한다. 서버리스 배포에서 커넥션 풀러를 쓰면 이 부분이 깨지기 쉽다. 아웃박스 디스패처와 대리인 만료 배치는 상시 프로세스나 크론이 있어야 돈다. | tech-design 12절 "배포 후보: 디스패처·일일 배치를 돌릴 수 있는지" [미정] | **Fast-follow**. 1주 차 스파이크로 확인. 막히면 Launch-blocking으로 올림 |
| T5 | **백엔드 직무인데 Next.js 선택을 설명하지 못한다.** "왜 Spring이나 별도 API 서버가 아니라 Next.js인가?"라는 질문이 나올 가능성이 높다. 답이 "편해서"면 감점이다. | 공고 직무: Tech Lead / Senior Backend | **Fast-follow**. 답할 논리를 ADR로 남김(프레임워크는 app/·ui/에만, 도메인은 프레임워크 중립: ADR-3) |
| T6 | **운영 규칙이 현장과 다를 수 있다.** 일할 없음, 의무식 하루 3끼, 매월 말일 발행·10일 기한은 모두 [가설]이다. 경리·프런트 검토는 [NEED] 상태 그대로다. [지원 회사] 면접관은 실제 운영을 아는 사람일 수 있다. | prd 15절 | **Track**. 데모에서 "가설이고, 바꾸면 이 설정 하나만 바뀐다"를 보여 주면 오히려 강점이 된다 |

## Paper Tigers (과한 걱정)

| 걱정 | 위험이 아닌 이유 |
|---|---|
| 동의서·고지문이 법률 검토를 받지 않았다 | 포트폴리오이고, 모든 법적 문구에 "법률 검토 전 초안"이 붙어 있다. 면접에서는 검토 목록(D copy 7절) 자체가 신중함의 증거가 된다 |
| Evenstay 상표 미확인(KIPRIS·USPTO) | 상업 출시가 아니다. [지원 회사] 상표는 쓰지 않는다. 출시를 결정할 때 확인하면 된다 |
| 성능·대량 처리 | 시드는 20호실이다. 면접에서는 "청구 생성 멱등·배치 단위" 설계 설명으로 충분하다 |
| 결제·ERP·본인 인증이 실연동이 아니다 | prd 13절에 목업이라고 밝혀 두었다. 어댑터 경계와 웹훅 멱등을 보여 주는 편이 실연동보다 설득력 있다 |
| 모듈 B·D·G를 다 구현하지 못한다 | 코어가 돌고 모듈 하나가 API로 붙는 모습만 보여도 "모듈형 모놀리스"는 증명된다. 나머지는 기획 문서로 보여 준다 |

## Elephants (아무도 말하지 않는 걱정)

| 걱정 | 확인 방법 |
|---|---|
| E1 **기획에 들어가는 시간이 코드를 잡아먹고 있다.** 2026-11-03 하루 동안 허브와 세션 7개가 문서를 서로 맞추느라 여러 차례 주고받았다(결정 기록 2026-11-03 행 참고). 모듈 기획이 늘수록 코어가 다시 흔들린다(v1.1이 그 예다) | 지금 "기획 동결"을 선언할지 사용자가 정한다. 동결 뒤 코어 변경은 MVP 중 실제로 막힐 때만 한다 |
| E2 **[지원 회사]가 원하는 것이 PMS 깊이인지 시니어 서비스 넓이인지 모른다.** 회사는 직원 4명의 신생 위탁운영사이고, PM과 함께 Discovery부터 시작한다(S1·S3) | 공고와 회사 자료를 다시 읽고, `stakeholder-map`과 `strategy-red-team`으로 면접 메시지를 점검한다(05-portfolio 착수 전) |
| E3 **지원자의 Next.js·PostgreSQL 숙련도에 맞춘 일정인지 확인하지 않았다** | 1주 차 끝에 F1·F2·격리 테스트가 실제로 통과하는지로 판정한다 |
| E4 **"2~4주"가 v1.0 기준 추정이다.** v1.1 이후로 다시 잰 적이 없다 | `sprint-plan`으로 다시 잰다(아래 A1) |
