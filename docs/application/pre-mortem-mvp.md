# Pre-Mortem: 확장된 Evenstay MVP (서비스 보완 뒤)

작성: 2026-11-03 · 허브 · 방법: `pre-mortem` 스킬(Skill 도구 호출) · 상태: 초안
앞 버전: `PreMortem-evenstay-core-2026-11-03.md`(코어만). 이 문서는 오늘 범위가 넓어진 뒤 전체를 다시 본다.

**실패 가정**: 면접 날 데모가 끝까지 돌지 않거나, 화면은 많은데 면접관이 "무엇을 설계했는지" 5분 안에 못 보거나, 소개 사이트나 문서의 주장이 사실과 달라 신뢰를 잃는다.

**근거로 본 사실** [사실]:
- 화면 정의서는 100행, Must 66 / Next 34, 따로 만들 화면 92개다(`evenstay/design/mvp-screens.md` 6-1). 보완 전에는 75행, Must 55, 화면 68개였다.
- 모듈은 코어 + 5개(안심 알림, 보호자 포털·동의, AI 생활 비서, 생활 지원 단계, 생활 요청)다. 통합 데모는 22단계다(같은 문서 5절).
- 사용자가 오늘 직접 요청한 운영 현황 대시보드(CORE-01 카드, REQ-19), 장기 부재(CORE-13), 안전 보완(SAF-12~14), 부재 소식(FAM-16·17)은 모두 **Next**로 분류됐다(6절). P1이고 데모 단계에 없다는 기준 때문이다.
- N1 생활 요청은 통합 데모 흐름에 아직 들어가지 않았다. N1 단계 0이 [시드 초기화]를 써서 앞 장면 기록을 지우는 문제가 있다(5절 머리말).
- 앞 사전 부검의 T1 조치 "기획 동결"과 `sprint-plan` 재측정은 하지 않았다. T2 "한 장 요약"(05-portfolio)도 아직 없다(`shared/idea-board.md`, 05-portfolio 폴더에 CLAUDE.md만 있음).
- 소개 사이트 계획은 화면 40개 안팎, 생성 에셋 68개, 사용자가 정할 것 20개(13 + 식사 7)다(`04-planning/ideas/evenstay-landing/`).
- 오늘 고친 기획은 모두 재승인 대기이고, 코드는 0줄이다.

## Paper Tigers (과한 걱정)
- **기능이 많아 보이면 좋은 인상이다**: 면접관은 기능 수보다 설계 판단(모듈 경계, 이벤트, 권한, 사람 개입 지점)을 본다 [추정]. 기능이 적어도 경계가 선명하면 충분하다. 그래서 오히려 T1이 위험이다.
- **법률 검토 전이라 데모를 못 보인다**: 가상 데모이고 [미확인]·[미정]을 문서에 드러냈다. 면접에서 "확인할 것" 목록 자체가 판단력을 보여 준다.
- **한국어 문장 품질**: 이미 korean-skills 검수를 한 번 거쳤고, 마지막에 한 번 더 한다. 실패 원인이 되기 어렵다.

## Elephants (아무도 말하지 않는 걱정)
- **누가 이 문서를 다 읽고 구현하나.** 기획은 세션 20여 개가 나눠 썼다. 구현은 혼자다. 문서 사이 미세한 어긋남을 구현자가 매번 판정해야 한다 → 리뷰 에이전트 결과로 확인.
- **Next 34개는 영원히 Next일 수 있다.** 사용자가 원한 대시보드가 Next에 남으면 "있다고 말한 기능"이 데모에 없다 → T2와 같이 결정.
- **승인 피로.** 오늘만 재승인 대기가 수백 줄 생겼다. 사용자가 내용을 보지 않고 "승인"하게 되면 승인의 뜻이 사라진다 → 승인 요청을 묶고 요약해서 올린다.
- **소개 사이트의 정체.** 가상 시설의 홍보 사이트가 포트폴리오에서 무엇을 증명하는지 정하지 않았다(브랜드·디자인 역량인지, 제품 이해인지) → `strategy-red-team`에서 본다.
