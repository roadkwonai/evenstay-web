# requests — 생활 요청

기준 문서: `../docs/requests/` (2026-11-03 인계, 상태: 초안. 사용자 승인 전). 시작은 `handoff.md`, 인수 조건은 `user-stories.md`, 범위·상태 전이(3절)·ADR-R1~R10은 `tech-design.md`, 화면 문구는 `copy/copy.md`.

## 범위
- 생활 요청: 고장·수리, 청소, 세탁, 외출 차량, 병원 동행, 의견·불편, 그 밖의 일. 들어오는 길은 Evenstay 홈(회원), 프런트 대신 등록, Evenstay 패밀리(D 허락 보호자), 홈 비서 넘김(G).
- 상태: 접수 → 처리 중(기다림) → 완료 → 입주자 확인, [아직이에요]는 다시 열림, 7일 뒤 확인 없이 닫힘, 취소, 하지 않음, 안심 알림으로 옮김, (보호자 비용 요청) 회원 답 기다림.
- 담당 팀 배정(프런트, 시설, 청소·세탁, 운전, 생활 지원), 종류별 처리 기한(직원 화면만), 정기 작업 회차(청소·점검), 유료 요청의 코어 청구 넘김, 운영 현황 `ServiceRequestQuery.openCount`.

## 꼭 지킬 규칙
- 스키마는 `requests`만 쓴다. import는 `core/api`, `safety/api`, `platform`만. `requests/api`는 다른 모듈 `api/`를 import하지 않는다. 정책은 `requests.*`만 등록한다(보호자 두 행동 `requests.request.view_as_guardian`·`create_as_guardian`은 "D 동의로 연다"고 선언하고 D가 연다, ADR-R6). 보호자는 요청을 취소하지 않는다.
- 입주자·직원·부재·요금을 저장하지 않고 매 요청 코어 `api/`로 읽는다. 장기 부재 이벤트를 구독하지 않고 회차 생성 때 `AbsenceQuery.absenceOf`를 읽는다.
- 직원의 [완료]는 확인 기다림이다. 입주자 확인(본인 또는 직원 대신 기록, 들은 직원·시각 필수)이나 7일 뒤 SYSTEM 닫힘으로만 끝난다(ADR-R3).
- 모든 전이는 한 트랜잭션에 전이 기록 1줄 + 코어 `AuditWriter` WRITE 1줄. 동시 수정은 `row_version`. 허용되지 않은 전이는 409.
- 처리 기한·기한 지남·담당 팀·직원 메모는 회원·보호자 DTO에 필드 자체가 없다. 회원·보호자 화면에서 처리 시간을 약속하지 않는다.
- 요청 내용을 읽어 종류·담당·급함을 시스템이 가르지 않는다. [안심 알림으로 옮기기]는 직원이 누르고, B `registerFromRequest`가 성공해야 닫는다. B에 요청 글을 넘기지 않는다(ADR-R7).
- 병원 동행은 날짜·시각, 가실 곳, 돌아올 때 동행만. body·done_note·hold_note는 null(CHECK), 한 일은 선택지, [아직이에요] 의견 없음, 진료 과목·증상 칸 없음. 가실 곳은 별도 테이블, 생활 지원·운전 팀과 책임자만, 열 때 SENSITIVE_READ, 이벤트·문자·알림·감사 전후 값에 넣지 않는다(ADR-R10).
- 비용 있는 요청은 확인 뒤 아웃박스로 코어 `ServiceChargeCommand.record`(요청 ID 멱등, 회원에게 안내한 요금표 버전). 금액을 저장하지 않고, 넣을 청구 기간은 코어가 정한다(ADR-R4). 코어 명령이 준비되기 전에는 이 기능을 끈다.
- `openCount`는 `requests.summary.read`를 CHECK로 검사한다(숫자 카드는 열람 기록 없음).
- 홈 비서 넘김은 직접 요청(주제가 청구서·계약이 아닌 것)과 도구 밖 질문만 "분류 전"으로 받는다. 종류는 프런트가 정한다(ADR-R5).
- 보호자에게 직접 문자를 보내지 않는다. `ServiceRequestStatusChanged`를 내고 D가 보낸다.
- 화면 용어: 직원 화면 "입주자"(들어온 곳 "Evenstay 홈"), 회원 "회원님", 보호자 화면 "이은숙 회원님". 금지어(낙상, 쓰러짐, 응급, 위험, 배회, 미납, 연체, 퇴소, 판정, 노인, 직원 화면의 "회원")는 CI에서 검사한다. 문구는 `copy/copy.md`를 그대로 쓰고 없는 문구는 만들지 않는다(`prd.md` 12절 `[NEED: 카피]`).
- 데모 초기화: `requests/seed`의 `reset(state)`는 AFTER_SUCCESSION, G_START, C_AFTER_DISCHARGE마다 시작점을 정한다(`prd.md` 9절). 유료 요청은 시드에 넣지 않는다.

## 하지 않을 것
- 요청 자동 분류·자동 옮기기(AI, 낱말 규칙), 처리 시간 약속
- 진료 과목·증상·진료 내용 받기, 진료 예약, 의료 판단
- 안전 신호 대신하기, 금전 부탁 처리(D), 비서의 건강·금전·계약 판단 넘김 받기(G 화면)
- 시설 관리 전체(자산 대장, 법정 점검 서류, 협력 업체 계약·정산)
- 요금 계산, 코어 청구 항목 직접 쓰기, 보호자 허락 저장, 보호자 문자 발송
- 만족도 점수, 직원 평가, 처리 시간 순위, 효과 수치 주장
- 다른 모듈 데이터 복사
