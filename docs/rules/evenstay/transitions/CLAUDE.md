# transitions — 생활 지원 단계 (Evenstay Transitions)

기준 문서: `../docs/transitions/` (2026-11-03 승인). 시작은 `handoff.md`, 인수 조건은 `user-stories.md`, 범위·상태 전이(3-1)·ADR-T1~T8은 `tech-design.md`, 화면 문구는 `copy/copy.md`.

## 꼭 지킬 규칙
- 단계는 사람이 정한다. 시스템은 판정·추천하지 않는다. 평가·제안·설명·결정은 따로 기록한다(ADR-T1).
- 제안자와 결정자는 다른 사람이다. 정책, 애플리케이션, DB(복합 FK + CHECK) 세 겹으로 막는다. 결정자는 SITE_MANAGER 또는 HQ_MANAGER [가설](ADR-T2).
- 거처 상담은 입주자 의견 없이 결정하지 못한다. 단계는 양쪽으로 바뀐다(위아래 없음).
- 단계가 바뀌어도 코어 계약·청구는 그대로다. 요금 묶음이 다르면 C 안에 계약 변경 요청을 남기고, 경리 "확인할 일"은 `app/`이 `TransitionsInboxQuery`를 붙여 보여 준다(ADR-T3).
- 단계 정의는 판으로 두고 결정은 그 판을 기록한다. 단계 코드는 고정, 라벨은 바꿀 수 있다(ADR-T4).
- 보호자에게는 결정된 변경만 D `HealthFeedCommand.post`로 간다(CARE_STAGE_CHANGE, EXTERNAL_CARE_START). 평가 내용·회원 의견·결정 전 제안은 보내지 않는다(ADR-T6).
- 화면 이름은 번호 없이 쓴다. 직원: 기본 서비스 / 생활 지원 추가 / 외부 돌봄 병행 / 거처 상담. 회원: 기본 서비스 / 생활 지원 더하기 / 다른 기관 돌봄 함께 / 지낼 곳 함께 의논. 금지어(판정, 단계 뜻의 등급, 하향·상향, 퇴소, 단계 번호)는 CI에서 검사한다.
- 다른 모듈은 `core/api`, `family/api`로만 쓴다. 스키마는 `transitions`만 쓰고, 정책은 `transitions.*`만 등록한다.

## 하지 않을 것
- 장기요양 등급 판정(공단 결과를 옮겨 적는 칸만), 요양 급여 청구, 의료 판단(진단명·진료 결과·처방 입력 칸 없음), 퇴거 결정·퇴거 요청
- 단계 판정·추천(점수, 규칙 엔진, AI), 화면의 단계 번호
- 요금 계산·자동 반영, 코어 계약·청구 직접 변경
- 보호자 화면·문자·동의 저장(모두 D), 보호자에게 평가 내용·기억·판단 기록·회원 의견·결정 전 제안 보내기
- 외부 돌봄 기관·통합돌봄 시스템 연동, 외부 전문가 의견 원문·퇴원 서류 저장
- 효과 수치 주장
