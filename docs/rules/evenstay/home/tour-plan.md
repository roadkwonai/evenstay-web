# 프로토타입 안내 기획

작성: 2026-11-05. 사용자 요청을 허브가 전달했다. 승인을 기다리지 않고 이어서 만든다.

사용자 요청: 도움말이 너무 빨리 끝난다. 프로토타입의 모든 기능과 페이지 기능을 권한별로 소개하고 안내한다. 실제 요소를 밝혀 보이는 지금 방식은 그대로 쓴다.

## 1. 안내 네 종류

| 종류 | 언제 뜨나 | 무엇을 보이나 | 자료 파일 |
|---|---|---|---|
| 시작 안내 | 처음 들어왔을 때 한 번 자동 | 서비스, 쓰는 사람, 주요 도구 6단계 | `strings/help.json` `ui.tour` |
| 전체 안내 | 도움말의 고르는 창 | 모든 공통 기능. 아래 2절 목록을 빠짐없이 | `strings/tour/common.json` `all` |
| 권한별 안내 | 고르는 창, 메인 홈 권한별 화면 | 권한 11개마다 하는 일, 메뉴, 대표 업무 순서. 실제 화면을 옮겨 다닌다 | `strings/tour/roles.json` |
| 화면별 안내 | 고르는 창, [이 화면 설명], 화면을 옮긴 뒤 뜨는 제안 | 페이지 75개와 경로 화면 2개. 영역, 버튼, 탭, 상태 | `strings/tour/<모듈>.json` |

## 4. 단계 형식

```json
{
  "t": "단계 제목", "b": "두세 문장 설명", "why": "왜 이렇게 설계했는지 한 문장(중요한 단계만)",
  "as": "계정", "go": ["화면 ID", { "파라미터": "값" }], "at": "2026-11-12T02:10:00",
  "do": [{ "click": "탭 글자" }, { "sel": "CSS" }],
  "fresh": true,
  "pop": "tools", "popNarrow": "tools", "guide": true,
  "bar": "막대 쪽 CSS 선택자", "sel": "화면 안 CSS 선택자", "text": "화면 안 글자", "within": "찾을 범위",
  "note": true, "covers": "guide.open",
  "seed": [{ "push": "core.inquiries", "value": {} }]
}
```

- `as`, `go`, `at`, `pop`, `guide`는 뒤 단계로 이어진다. 다음 단계가 바꾸기 전까지 그대로다.
- `seed`는 시연에서 지나간 기록을 임시 자료에 더한다. 안내 전체(최상위)나 단계에 둘 수 있고, 뒤 단계로 이어지며 닫으면 사라진다.
- `do`는 탭을 열거나 창을 여는 준비 동작이다. 쌓여서 이어지고, `go`나 `fresh`가 나오면 비워진다. 저장, 전송 버튼은 넣지 않는다. 강조만 한다.
- 대상은 `bar`, `sel`, `text` 가운데 하나다. 없으면 강조 없는 설명 단계이고, 그때는 `"note": true`를 적는다.
- 폭에 따라 요소가 다르면 `sel`에 쉼표로 둘 다 적는다. 보이는 쪽을 고른다.
- 화면별 파일은 `{ "화면 ID": { "as", "go", "start", "steps", "variants": { "권한 id": { "as", "steps" } } } }`다. `start`는 `end`(기본) 또는 시연 순서 번호다.
- 화면별 안내의 첫 단계는 `strings/help.json`의 목적과 쓰는 사람, 마지막 단계는 다음 흐름에서 자동으로 만든다. 파일에는 그 사이 단계만 쓴다.

## 5. 동작 규칙

- 권한별, 화면별 안내는 시연을 마친 자료(`data/end-state.json`)나 지정한 시연 순서의 자료를 잠시 불러 보여 준다. 안내 중에는 저장하지 않는다.
- 닫으면 안내 전 시연 자료로 돌아오고 지금 화면에 남는다. 권한별 안내에서 바꾼 권한은 그대로 둔다.
- 시연 시각이 달라야 하는 단계는 시계만 잠시 옮긴다. 시간이 지나 생기는 일은 일어나지 않는다.
- 찾는 요소가 없으면 강조 없이 설명하고 "지금 화면에는 보이지 않습니다"를 적는다. 없는 곳을 가리키지 않는다.
- 어디까지 봤는지 기억한다. 고르는 창 맨 위에 이어 보기가 나온다. 끝까지 보면 지운다.
- 화면을 옮기면 위 오른쪽에 작게 "이 화면 안내 보기"가 잠시 뜬다. 자동으로 안내를 열지 않는다.

## 6. 문구 원칙

- 근거: `design/mvp-screens.md`, 각 `docs/<모듈>/prd.md`, `copy/copy.md`, 실제 화면, `strings/help.json`. 없는 기능을 쓰지 않는다.
- 처음 보는 면접관이 읽는다. 한 단계 두세 문장. 합쇼체. 화면 이름은 실제 글자와 같게 쓴다.
- 쓰지 않는 말: 시험, 남은 일, MVP, 판단 단어(낙상, 쓰러짐, 응급, 위험, 배회), 이모지, "판". 시스템이 의료를 판단한다고 읽히는 문장은 쓰지 않는다.
- "입주자"(직원 화면), "회원님"(회원 화면 인용), 권한, 시연 같은 기준 용어는 `docs/glossary.md`를 따른다.
