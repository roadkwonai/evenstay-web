# core — 계약·청구 코어 (Evenstay Core)

기준 문서: `../docs/core/` (2026-11-03 승인). 시작은 `handoff.md`, 인수 조건은 `user-stories.md`, 모델·상태 전이·청구 계산·ADR은 `tech-design.md`, 화면 문구는 `copy/copy.md`.

## 코어가 갖는 것
운영사, 소유주, 사업장, 동, 호실, 사람, 입주자, 보호자 관계(관계만), 대리인, 계약, 요금표, 식사 기록, 청구 원장(청구 항목·청구서·수납·조정·보증금), 문의, 계정·역할, 변경 이력, 아웃박스.

## 꼭 지킬 규칙
- 계약 상태는 6개: 작성 중 → 입주 예정 → 거주 중 → 승계됨 / 퇴거 예정 → 정산 완료(`tech-design.md` 3절).
- 청구 규칙은 3개(정기 요금, 식비, 결식 감면). 일할 계산 없음: 입주 월은 1개월분, 승계는 다음 달 1일부터, 퇴거는 그 달 말일까지. 요금표는 체결 때 버전으로 고정.
- 원장은 추가만 한다. 발행이 확정 시점이고, 발행 뒤 정정은 다음 청구서의 조정 전표로만 한다. DB 트리거로 발행 항목 수정·삭제를 막고, 사업장 격리는 RLS로 이중 방어한다.
- 청구 계산은 시드 골든 테스트로 고정한다(201호 10월 4,947,000원, 1인 31일·결식 3끼 2,910,000원).

## 하지 않을 것
- 장기요양 급여 청구, 요양시설 업무, 회계 장부(분개는 ERP 내보내기 목업까지)
- 법적 판단(행위능력, 후견 필요성, 사망 판정). 증빙을 확인한 사실과 권한 범위만 기록
- 입주자 자산 조회, 이체 대행, 금융상품 연결
- 건강·돌봄 정보 저장, 응급 대응(safety 몫), 보호자 동의 정책과 보호자 화면(family 몫)
- MVP에서 공과금, 선납, 몰취, 보증금-월비 교환, 일할 계산, 실제 결제·ERP 연동
