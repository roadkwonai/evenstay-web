# community — 프로그램·시설·공지

기준 문서: `../docs/community/` (2026-11-04 인계, 상태: 승인 2026-11-04, 고친 곳은 재승인 대기). 시작은 `handoff.md`, 인수 조건은 `user-stories.md`, 범위·상태 전이(3절)·계산(4절)·ADR-M1~M10은 `tech-design.md`, 화면 문구는 `copy/copy.md`.

## 범위
- 프로그램과 회차: 반복 프로그램 등록, 4주 앞 회차 생성, 정원, 신청·대기, 마감(전날 18:00 [가설]) 전 자동 승급, 마감 뒤 직원 전화 승급, 취소, 출석 체크(온 분만). 이번 버전은 무료 프로그램만.
- 공용 시설 예약: 예약 받는 방, 비어 있는 시간, 이용 규칙, 회원 예약·직원 대신 예약, 바꾸기, 시간 막기, 사업장 취소.
- 공지: 쓰기·게시·예약 게시·내리기, 대상(전체·동·층), 중요 공지의 [읽었어요]와 직원의 직접 전함, 확인 현황, 보호자에게도 보이기(공지마다, 기본 끔).
- 들어오는 길: Evenstay 홈(회원), 프런트·직원 대신 신청·예약·취소. 나가는 길: D 일정·레지던스 공지·생활 소식 재료 조회, 운영 현황 카드 후보 `CommunityBoardQuery.todayOf`.

## 꼭 지킬 규칙
- 스키마는 `community`만 쓴다. import는 `core/api`와 `platform`만. `community/api`도 다른 모듈 `api/`를 import하지 않는다(D가 `community/api`를 import한다). 정책은 `community.*`만 등록한다. `community.enrollment.view_as_guardian`(D가 SCHEDULE 허락으로 엶)과 `community.notice.view_as_guardian`(D가 보호자 관계만으로 엶)은 "D 동의로 연다"고 선언한다. N2 정책은 이 두 행동에 ALLOW를 주지 않는다(ADR-M6).
- 입주자·호실·동·직원·장기 부재를 저장하지 않고 매 요청 코어 `api/`로 읽는다. 장기 부재 이벤트를 구독하지 않고 승급·명단 표시 때 `AbsenceQuery.absenceOf`를 읽는다. 부재로 신청을 자동 취소하지 않는다(ADR-M7).
- 같은 장소의 회차·예약·막은 시간은 PlaceBooking 한 테이블에 있고 `EXCLUDE USING gist (place_id WITH =, period WITH &&) WHERE active`로 겹침을 막는다. 앱 검사로 대신하지 않는다(ADR-M1).
- 한 회차의 쓰기(신청, 취소, 승급, 정원 바꾸기)는 회차 행을 `FOR UPDATE`로 먼저 잠근다. 대기 순서는 (queued_at, seq)이고 아무도 바꾸지 못한다(ADR-M2). 회원은 [기다리기]를 골라야 대기에 들어간다(신청 intent가 ENROLL인데 자리가 없으면 409 FULL, 행 없음). 대기가 있는 회차의 빈자리는 새 신청이 아니라 승급으로만 채운다.
- 마감 전 취소·정원 늘림은 같은 트랜잭션에서 대기 맨 앞을 승급하고 문자를 아웃박스에 쓴다. 마감 뒤에는 승급하지 않고 진행 직원 알림, 직원 승급은 맨 앞 행만(아니면 409)(ADR-M3).
- 출석은 ATTENDED·WALK_IN 행만 저장한다. "오지 않음" 행, 입주자별 참여 횟수·비율 조회를 만들지 않는다. 출석을 다른 모듈 신호로 보내지 않는다(ADR-M4).
- 공지 대상은 게시 때 NoticeRecipient(ID만)로 정한다. 확인은 ACKED와 DELIVERED_IN_PERSON 두 길뿐이고 열람은 기록하지 않는다(ADR-M5).
- 회차 화면 상태(신청 받는 중, 정원 참, 마감, 신청 없음, 마침)는 저장하지 않고 시계·숫자로 계산한다. 시드 행도 시계 기준으로 보인다(ADR-M8).
- 모든 쓰기는 한 트랜잭션에 코어 `AuditWriter` WRITE 1줄(+ 필요하면 아웃박스 행). 모든 쓰기는 `Idempotency-Key`를 받는다.
- 회원·보호자 DTO에 오지 않음, 출석 횟수, 장기 부재 표시, 직원 메모가 없다(대신 넣은 직원 이름은 copy 2-12대로 보인다). 보호자 일정 응답에는 확정 신청(과 쉬게 된 회차)만 있고 대기·시설 예약·출석이 없다.
- 보호자에게 직접 문자를 보내지 않는다. 문자는 링크 없이 프런트 번호(`Notifier`).
- 화면 용어: 직원 화면 "입주자"(합쇼체), 회원 "회원님"(해요체), 보호자 화면 "이은숙 회원님". 금지어(고립, 외로움, 활동량, 참여율, 결석, 불참, 노쇼, 미확인자, 낙상, 쓰러짐, 응급, 위험, 배회, 미납, 연체, 퇴소, 판정, 노인, 직원 화면의 "회원", "마감 임박", "인기")는 CI에서 검사한다. 문구는 `copy/copy.md`를 그대로 쓰고 없는 문구는 만들지 않는다(`prd.md` 12절 `[NEED: 카피]`).
- 사업장마다 켜는 기능(`community_features`: 공지, 프로그램, 시설)을 설정으로 정한다. 자산 유형으로 분기하는 코드를 두지 않는다(ADR-M10).
- 데모 초기화: `community/seed`의 `base()`는 COM-03 "기본"(처음 배포) 시드를 넣는다. 통합 데모는 이 초기화 한 번 뒤 시계만 옮기므로, 시드 행(신청 queued_at, 예약 created_at)은 시계보다 뒤면 조회에서 뺀다. `reset(state)`는 AFTER_SUCCESSION, G_START, C_AFTER_DISCHARGE마다 시작점을 정한다(`prd.md` 9절). 청구에 닿는 데이터는 없다(코어 골든 금액 불변).

## 하지 않을 것
- 프로그램 효과 주장, 참여 인원·참여율, 추천, 권유·전날 안내 문자
- 출석으로 입주자 평가·순위·신청 제한, "오지 않음"을 회원·보호자에게 보이기, 노쇼 기록
- 비용이 드는 프로그램과 코어 청구 연결(다음 버전), 강사 관리, 외부 회원 모집
- 건강 상태를 짐작하게 하는 프로그램(재활, 치료, 인지 훈련)
- 보호자의 신청·예약, 보호자 허락 저장, 보호자 문자(D)
- 공지 열람 추적
- 시설 관리 전체(정기 청소·점검은 `requests`)
- 다른 모듈 데이터 복사
