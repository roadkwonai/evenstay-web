# assistant — 생활 비서 최소판 (Evenstay 홈 비서)

기준 문서: `../docs/assistant/` (2026-11-03 승인). 시작은 `handoff.md`, 인수 조건은 `user-stories.md`, 범위·ADR-G1~G9는 `tech-design.md`, 화면 문구는 `copy/copy.md`.

## 꼭 지킬 규칙
- LLM은 의도를 고르는 라우터로만 쓴다. 답 문장은 서버가 답 틀에 도구 결과를 채워 만들고, 도구 결과는 LLM에 보내지 않는다. 큰 버튼은 LLM을 부르지 않는다(ADR-G1).
- 쓰기(청구 문의 접수, 직원에게 넘기기)는 회원이 [네, 전해 주세요]로 받은 확인 토큰이 있어야 한다. 토큰 기한 5분 [가설](ADR-G3).
- 대상 회원은 로그인한 사람으로 고정한다. 도구 인자에 회원 ID를 받지 않고, 항상 로그인한 행위자 권한으로 코어 `authorize()`를 거친다(ADR-G4).
- 납부는 코어 `paymentState`만 읽는다. "미납"·"연체"를 말하지 않고 낸 기록의 유무만 말한다(ADR-G8).
- 고지 게이트는 서버에서 검사하고 실패하면 닫는다. 회원·대리인 모두 D의 MEMBER 판(ASSISTANT 목적)을 사람마다 확인해야 비서가 열린다(ADR-G5).
- 대화 원문은 1년 뒤 지운다. 음성은 저장하지 않는다. 회원 말의 숫자 4개 이상은 저장 전에 가리되, 금액·날짜 단위가 붙은 숫자는 남긴다 [가설](ADR-G9).
- 평가 세트 안전 기준 4개는 CI에서 100%여야 한다: 민감 문항 도구 호출 0건과 넘김 제안, 다른 회원 데이터 0건, 출처 없는 사실 줄 0건, 확인 없는 쓰기 0건(`prd.md` KR1).
- 다른 모듈 데이터는 복사해 두지 않고 매 요청 `core/api`, `family/api`로 읽는다. 스키마는 `assistant`만 쓴다. 최소판은 이벤트를 발행·구독하지 않는다.

## 하지 않을 것
- 건강·약·응급 판단, 금전 판단·이체 조언, 계약 변경 결정(회원 확인 뒤 직원에게 넘김)
- 투자 추천, 주문, 증권·자산 조회
- 금액 계산, 도구 결과 밖의 사실 말하기, LLM이 쓴 문장을 회원에게 보이기
- "미납", "연체" 판정과 독촉
- 회원 확인 없는 쓰기, 비서가 직원에게 직접 연락
- 말벗·긴 대화, 보호자용 비서, 시설 일정·시설 요청 접수
- 음성 원본 저장, 도구 결과 복사 저장
- 비서용 서비스 계정·넓은 권한
