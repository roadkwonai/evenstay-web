## 도식

- 프로젝트 로컬 Archify로 5장 finalize 통과. validate·deliver·strict check·실제 브라우저 검증이 포함된다.
- stack-diagram 5장, diagram-design 6장을 기존 생성기로 다시 만들었다.
- 16장 접촉 시트로 전체 구성을 보고, arch-doc·arch-signal·dd-roadmap·stack-a1을 확대 확인했다. 나머지 도식의 작은 글씨를 개별 확대 판독하지는 않았다.
- diagram-design 원본 자체 검사는 6장 모두 `non-fragment CSS url() is not allowed` 한 항목으로 종료 1이었다. 기존 프로젝트가 요구하는 로컬 Pretendard 참조 때문이다. 이를 통과로 바꾸거나 검사기를 고치지 않았다.
- 별도 프로젝트 검사에서 해당 6장의 CSS URL이 도식 내부 조각 또는 지정한 로컬 Pretendard 파일만 참조하는지 확인했고, 실제 WOFF2 파일과 브라우저 렌더를 검증했다.
- 설치된 도식 스킬 3종의 파일 해시가 설치 기록과 일치한다. Archify 3.2.0 업데이트 알림은 기록만 하고 설치본 3.0.1을 유지했다.

## 재검토와 공개 검사

- 독립 재검토에서 범용 실행 테이블·전역 이벤트 버전 강제는 제외했다. 마지막에 발견한 늦은 신호 문장의 의미 불일치와 회사명 마스킹 링크 오류를 수정하고 재확인했다.
- 깨진 마스킹 링크를 회귀 검사로 재현한 뒤 수정해 검사 통과를 확인했다.
- 공개 문서에서 지원 회사 이름과 사용자 절대 경로를 가리고, 도식 delivery/finalize 진단 JSON은 내보내지 않는다.
- 공개 텍스트 562파일 및 0.1.0 기준본 아카이브에서 `.envrc`의 활성 비밀 값 8개와 대조한 결과 노출 0건이었다. 이는 검사 범위의 결과이며 보안 감사는 아니다.
- GitHub 접근은 사용자 지정 `.envrc`의 GH_TOKEN을 사용했다. 토큰은 릴리즈 파일에 기록하지 않았다.
