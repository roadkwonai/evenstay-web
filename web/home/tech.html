프로토타입 열기

기술과 스킬

프로토타입에 쓴 기술과 설계만 한 기술을 나누어 적었습니다. 기획과 디자인에 쓴 스킬도 단계별로 정리했습니다.

프로토타입에 쓴 것

이 프로토타입에 들어간 13가지입니다.

  • HTML

    앱 틀(위쪽 막대와 화면 창을 겹쳐 놓은 app.html, 화면을 그리는 screen.html)과 소개 사이트 11쪽입니다. 빌드 없이 파일을 그대로 엽니다.

    있는 곳 design/prototype/app.html, design/prototype/screen.html, design/prototype/site/*.html

  • CSS(일반 CSS, Tailwind 없음)

    DESIGN.md 값을 옮긴 proto.css 위에 앱 규칙(app.css)과 시연 틀(stage.css)을 얹었습니다. 소개 사이트는 따로 css 폴더를 씁니다.

    있는 곳 design/prototype/css/proto.css, app.css, stage.css, design/prototype/site/css/

  • JavaScript(ES 모듈, 빌드 없음)

    38개 파일, 약 9,000줄입니다. 틀·저장·시계·진행기(lib)와 모듈별 상태·화면·시연 단계(modules)로 나눴습니다. 상태는 브라우저 localStorage에 남습니다. 서버와 DB는 없습니다.

    있는 곳 design/prototype/js/main.js, js/lib/, js/modules/

  • JSON 시드와 문구 파일

    가상 시드 JSON 12개(data/)와 화면 문구 JSON 9개(strings/)입니다. 코드 안에는 한글이 없고, 문구는 strings 파일에서만 고칩니다.

    있는 곳 design/prototype/data/, design/prototype/strings/

  • Lucide 아이콘

    아이콘 경로를 icons.js에 담아 인라인 SVG로 그립니다. 패키지를 설치해 쓰지는 않았습니다.

    있는 곳 design/prototype/js/lib/icons.js

  • Pretendard 가변 글꼴

    woff2 파일을 저장소에 두고 @font-face로 불러옵니다. 바깥 서버에서 받지 않습니다.

    있는 곳 design/prototype/assets/fonts/PretendardVariable.woff2, design/fonts/pretendard/

  • Node.js 시험 스크립트 + puppeteer-core + 내 컴퓨터의 Chrome

    시험 파일 8개입니다. 그중 7개가 Chrome을 띄워 전 단계를 누르고, 1개(check-strings)는 문구 파일만 검사합니다. 흐름 진행, 전체 경로 방문, 설명 창, 막대 배치, 시작 상태, 끼니 수, 소개 사이트 방문을 봅니다.

    있는 곳 design/prototype/test/*.mjs, design/site/src/*.mjs(화면 캡처와 측정)

  • python3 -m http.server

    프로토타입을 로컬에서 여는 서버입니다. 배포하지 않았습니다.

    있는 곳 design/prototype/README.md

  • Python 생성기

    소개 사이트 보드를 만들고(build.py), 같은 내용을 정적 페이지로 내보내며(build_static.py), 문구가 문서와 같은지 대조합니다(check_strings.py, copycheck.py). 정적 사이트는 design/prototype/site/에 생성됩니다.

    있는 곳 design/site/src/build.py, build_static.py, check_strings.py, copycheck.py

  • DESIGN.md + Node 생성 스크립트

    디자인 시스템 원본은 DESIGN.md(google-labs-code/design.md 형식)입니다. npx @google/design.md lint로 오류·경고를 확인하고, build.mjs로 theme.css, tokens.css, globals.css를 만듭니다. theme.css는 Tailwind v4 형식이고 컴파일이 되는지만 확인했습니다. 프로토타입 화면은 이 CSS를 쓰지 않고 proto.css를 씁니다.

    있는 곳 DESIGN.md, design/system/build.mjs, design/system/

  • 로고 SVG 생성 스크립트(Node)

    Pretendard Bold 글자 윤곽선으로 운영, 홈, 패밀리 로고를 라이트, 다크, 흑, 백 색으로 만듭니다.

    있는 곳 design/brand/logo/src/build.cjs, design/brand/logo/

  • 아트보드(Design 캔버스)

    모든 화면을 데스크톱과 모바일 보드로 만든 캔버스입니다. 보드 487개(앱), 소개 사이트는 별도 캔버스입니다. 클릭형 프로토타입의 앞 단계 결과물입니다.

    있는 곳 design/mvp-screens.md, design/canvas-notes.md, design/site/src/canvas.py

  • gpt-image, gpt-image-api(gpt-image-2.5-sunburst), higgsfield CLI(minimax_h3, kling4_0)

    소개 사이트의 사진, 일러스트, 영상을 만들었습니다. 사진과 일러스트는 webp, 영상은 mp4입니다. 생성한 프롬프트와 모델을 ID마다 기록했습니다. 모든 인물과 장소는 가상입니다.

    있는 곳 design/site/assets/prompts.md, design/site/assets/

설계만 한 것

설계 문서에서 정했고 이 프로토타입에는 쓰지 않은 11가지입니다. 구현한 것으로 읽히지 않게 따로 모았습니다.

  • Next.js 16 (화면)

    운영, 홈, 패밀리 화면을 만드는 틀입니다. app/과 ui/ 폴더에만 들어오고, 코어와 모듈의 도메인 코드는 이 틀을 모릅니다. 컨테이너 1개로 시작하는 설계안입니다. 프로토타입에는 쓰지 않았습니다.

  • shadcn/ui, Tailwind CSS

    화면 부품의 설계 기준입니다. DESIGN.md가 Tailwind v4용 theme.css와 shadcn 변수(globals.css)를 내보내고 컴파일이 되는 것까지만 확인했습니다. 프로토타입 화면에는 쓰지 않았습니다.

  • Java 25 + Spring Boot 4.1 (업무 코어)

    계약, 청구, 권한 같은 업무 코드를 맡는 백엔드 설계안입니다. 같은 이미지로 API와 작업자를 띄웁니다. 후보 8개를 점수로 비교했고 Spring이 3.90점으로 앞섰습니다. 점수는 판단이고 측정값이 아닙니다. 만들지 않았습니다.

  • Spring Modulith 2.1 (모듈 경계)

    모듈 사이 의존을 코드로 검사하고 이벤트 기록을 남기는 도구입니다. 설계의 모듈 경계 규칙(다른 모듈은 api/만 쓴다)을 지키는 수단으로 골랐습니다. 이 도구는 코드 의존만 보고 DB 권한은 보지 않습니다.

  • PostgreSQL 18 (RDS)

    모듈별 스키마, 행 단위 보안(RLS), 발행 항목 보호 트리거, 기간 겹침 방지 제약, JSON 칸을 한 DB에서 맡는 설계입니다. 1단계는 Single-AZ와 가상 데이터, 실제 데이터 전에는 Multi-AZ가 필요하다고 적었습니다. 프로토타입은 DB 없이 localStorage와 JSON 시드만 씁니다.

  • AWS 서울 (ECS Express Mode, ALB, CloudWatch)

    1단계 컨테이너 3개(화면, API, 작업자)와 DB 하나를 올리는 설계안입니다. 월 고정비 약 261달러(1단계), 약 546달러(2단계), 약 567달러(3단계)는 공식 가격으로 계산한 값이고 실제로 쓴 비용이 아닙니다. 배포하지 않았습니다.

  • Amazon Bedrock 서울 (Claude Sonnet 5 제안)

    AI는 질문의 뜻을 고르는 데만 쓰고 답 문장은 기록을 틀에 채워 만든다는 원칙(ADR-G1) 아래, 1단계에서 API가 어댑터로 부르는 안입니다. 시연에서는 미리 녹화한 응답을 기본으로 쓰고 프로토타입에는 모델 호출이 없습니다.

  • 2단계 FastAPI + Pydantic v2 + PydanticAI, Taskiq + Valkey

    Python 라이브러리가 필요해질 때 AI 서비스를 따로 떼는 안입니다. 넘어가는 신호가 나타나기 전에는 더하지 않습니다. 이 서비스는 업무 DB에 직접 닿지 않고, Spring이 권한 검사를 거친 칸만 넘깁니다.

  • JobRunr (PostgreSQL 기반 작업 큐)

    타이머, 월 청구, 알림 발송을 도는 작업자의 후보입니다. 코어의 아웃박스는 그대로 두고, 비교 전까지는 이 안을 기본으로 봅니다. 아직 고르지 않았습니다.

  • 3단계 후보 (Kubernetes, OpenSearch, Langfuse, dlt+Dagster, LangGraph, LiteLLM)

    개발자가 10명을 넘거나 외부 전달이 늘어나는 등 신호가 나타날 때만 더하는 후보입니다. 신호가 없으면 넘어가지 않는다고 못박았습니다. 이미지를 서비스별로 맞춰 두면 ECS에서 옮길 수 있다는 점만 처음부터 지킵니다.

  • 외부 연동 어댑터 (결제, ERP, 문자, 알림톡, 호출벨 기기, 본인 확인)

    어댑터 뒤에 목업으로 둔다는 설계입니다. 프로토타입에서는 보낸 문자 보기 창과 시뮬레이터로 대신했고 실제 연동은 없습니다.
