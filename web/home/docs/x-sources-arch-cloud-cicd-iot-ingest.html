1. CI/CD, 환경 구성, IaC

Takeaway

GitHub Actions OIDC로 정적 키 없이 AWS에 들어가고, ECS는 2025-07부터 내장 blue/green이 있어 CodeDeploy가 필수가 아니다. OpenTofu 상태는 S3 한 곳(네이티브 잠금)으로 충분하다. 다만 이미지 스캔, SBOM, Flyway 무중단 이행의 공식 문서는 이번에 열지 못했다.

Cited Findings

  • [사실] GitHub 공식 문서는 AWS OIDC에 공급자 URL https://token.actions.githubusercontent.com, 대상(audience) sts.amazonaws.com을 쓰고, 신뢰 정책에 sub 조건을 최소 하나 두라고 한다. 브랜치(repo:ORG/REPO:ref:refs/heads/BRANCH)나 환경(repo:ORG/REPO:environment:prod) 단위 범위를 권한다. 워크플로에는 permissions: id-token: write가 필요하다. 와일드카드 repo:ORG/REPO:*는 가장 넓은 범위다. — GitHub Docs: OIDC in AWS · 접근 2026-11-04 · 직접
  • [사실] 같은 페이지는 2026-07-15 이후 만든 저장소(또는 옵트인한 저장소)가 소유자·저장소 ID가 들어간 새 sub 형식(repo:octo-org@123456/octo-repo@456789:...)을 쓴다고 한다. 신뢰 정책을 예전 형식으로 쓰면 새 저장소에서 맞지 않을 수 있다. AWS는 사용자 지정 OIDC 클레임을 지원하지 않는다. — 위와 같음 · 직접
  • [사실] 문서 예시는 aws-actions/configure-aws-credentials를 커밋 SHA로 고정한다. 페이지는 이 SHA가 어느 릴리스인지는 밝히지 않는다. — 위와 같음 · 직접
  • [사실] ECS 내장 blue/green: 새 서비스 리비전을 테스트 트래픽으로 검증한 뒤 운영 트래픽을 옮기고, 베이크 타임 동안 이전(blue) 리비전을 살려 두어 롤백이 쉽다. 수명주기 훅은 Lambda 또는 일시정지 지점을 쓴다. 배포 중 리소스가 일시적으로 두 배가 될 수 있다. NLB를 쓰면 트래픽 이동 단계에 10분이 더 붙는다. 로드밸런서·Service Connect·VPC Lattice가 있는 서비스는 트래픽 이동을 ECS가 관리하고, 로드밸런서 없는(headless) 서비스는 작업만 교체하고 트래픽 이동은 관리하지 않는다. — ECS 개발자 가이드: blue/green · 접근 2026-11-04 · 직접
  • [사실] 내장 blue/green 발표일은 2025-07-17이고 ALB·NLB·Service Connect 서비스를 대상으로 한다. CloudWatch 경보와 배포 서킷 브레이커로 실패를 감시한다. 이전에는 CodeDeploy가 필요했다. — AWS What's New 2025-07 · 접근 2026-11-04 · 검색요약
  • [미확인] CodeDeploy의 ECS 지원이 폐기 예정이라는 글이 있으나 AWS 공식 확인은 못 찾았다. — 위 검색 결과 · 제3자
  • [사실] OpenTofu S3 백엔드는 use_lockfile=true로 DynamoDB 없이 S3 조건부 쓰기(If-None-Match)로 잠근다. 문서는 이를 권장 방식으로 설명하고, dynamodb_table은 폐기 예정이 아니며 둘 다 지원한다고 한다. S3 버전 관리를 켜라고 강하게 권한다. 도입 버전은 이 페이지에 없다. — OpenTofu S3 backend · 접근 2026-11-04 · 직접
  • [사실] Control Tower는 서울(ap-northeast-2)을 지원 리전에 포함한다. 홈 리전은 만든 뒤 바꿀 수 없다. 통제 중 예방형은 전역 동작하고 탐지형·사전형은 지원 리전에서만 동작한다. — Control Tower: Regions · 접근 2026-11-04 · 직접
  • [사실] 비밀 저장 가격(서울): Secrets Manager 비밀 1개당 월 $0.40, API 1만 건당 $0.05. Systems Manager 고급 파라미터는 개당 월 $0.05, 고급 파라미터 API 1만 건당 $0.05. — Secrets Manager 서울 가격표(게시 2026-09-11), Systems Manager 서울 가격표 · 접근 2026-11-04 · 직접
  • [사실] ECR 저장 $0.10/GB-월(서울). — ECR 서울 가격표(게시 2026-09-11) · 직접
  • [사실] Spring Modulith 2.1.1 문서: ApplicationModules.of(Application.class).verify() 한 줄 호출이 순환 의존, 내부 패키지 접근, allowedDependencies 위반을 검사한다. detectViolations()로 걸러서 볼 수 있다. 문서는 CI 실행을 따로 말하지 않는다. — Spring Modulith 검증 · 접근 2026-11-04 · 직접
  • [사실] Spring Boot 4.1.2 문서: PostgreSQLContainer에 @ServiceConnection을 달면 JDBC·R2DBC 연결 정보가 자동 연결된다. 컨테이너를 @Bean으로 두면 캐시된 컨텍스트마다 한 번 만들어진다. @Testcontainers+@Container 방식은 컨텍스트 캐시를 깰 수 있다고 경고한다. — Spring Boot Testcontainers · 접근 2026-11-04 · 직접
  • [사실] 커뮤니티 글들은 Flyway를 파드 기동 때 실행하면 롤링 배포에서 경합이 생기니 별도 작업(Job)으로 먼저 돌리라고 하고, 확장→코드 배포→축소를 서로 다른 릴리스로 나누라고 한다. 공식 Flyway 문서는 못 열었다. — 예: tech-holder 블로그 2026-03 · 접근 2026-11-04 · 제3자(검색요약)

Inferences

  • [추정] 이 팀은 계정 3개(관리, 스테이지, 운영)에 OIDC 역할을 환경별로 두고, 운영 역할의 sub를 environment:prod로 좁히면 정적 키 없이 승인 게이트까지 걸 수 있다. GitHub 환경의 보호 규칙(승인자, 허용 브랜치)과 짝이다.
  • [추정] 작업자(HTTP 없음) 서비스는 내장 blue/green이 트래픽을 옮기지 않으므로 사실상 롤링 교체다. 안심 타이머를 쥔 작업자는 교체 중 중복 실행·누락을 막는 설계(리스, 멱등)가 필요하다. 이 부분은 ECS 문서로 확인한 사실이 아니라 허브 설계 쪽 판단이다.
  • [추정] 1단계 Single-AZ ALB 한 개로도 blue/green이 동작하지만, 배포 중 작업이 두 배라 Fargate 시간이 잠시 늘어난다(문서의 “리소스 두 배” 근거).
  • [가설] 마이그레이션은 이미지 내 Flyway를 앱 기동 대신 CI에서 ECS 일회성 작업(run-task)으로 먼저 돌리고, 파괴적 변경은 두 릴리스로 나눈다.
  • [가설] 프리뷰 환경은 PR마다 ECS 서비스를 만들기보다 스테이지 하나와 Testcontainers 통합 테스트로 대체한다. 이유는 ALB($0.0225/시간, 월 약 $16.43)와 DB 비용이다(계산: 0.0225 × 730).

2. 서울 리전 모니터링, 로그, 온콜, 안전 경로 감시

Takeaway

Spring Boot 4.1 공식 경로는 Micrometer + OTLP이고 Java 에이전트·OTel 스타터는 커뮤니티 지원이다. 서울에는 CloudWatch(Application Signals 포함), Managed Prometheus, Managed Grafana의 서울 가격이 모두 있어 데이터를 서울 밖으로 보내지 않는 구성이 가능하다. Opsgenie는 2027-04-05 지원 종료라 새로 쓰면 안 된다.

Cited Findings

  • [사실] Spring Boot 4.1.2 문서는 OTel 지원 경로를 셋으로 나눈다. Java 에이전트와 OpenTelemetry Spring Boot 스타터는 OTel 커뮤니티 지원이고, Boot 자체의 Micrometer+OTLP 내장 지원이 “Spring 팀이 공식 지원”하는 방식이다. 트레이스는 Micrometer Tracing이 있을 때 OTLP로 자동 설정된다. 메트릭은 OtlpMeterRegistry(management.otlp.metrics.export.*)로 내보낸다. 로그는 OtlpLoggingAutoConfiguration으로 OTLP 내보내기가 가능하나 로그 브리지는 서드파티가 필요하다. 소개문은 Boot가 OTel 메트릭·로그를 자동 내보내지 않는다고 적어 본문과 어긋난다. — Spring Boot Observability · 접근 2026-11-04 · 직접(요약기 경유, 문서 내부 모순 있음)
  • [사실] 같은 문서에서 management.opentelemetry.enabled=false면 SDK가 no-op이 된다. 일부 OTEL_* 환경변수는 Boot 속성으로 매핑된다. — 위와 같음 · 직접
  • [미확인] 이 페이지에는 spring-boot-starter-opentelemetry라는 이름이 나오지 않는다. 스타터 아티팩트의 존재 여부는 확인 못 했다. — 위와 같음
  • [사실] CloudWatch Application Signals를 ECS에서 쓰려면 CloudWatch 에이전트와 ADOT를 직접 설치하는 맞춤 설정이다. Fargate는 사이드카 방식만 된다(daemon 방식은 Fargate 불가). ECS에서는 서비스 이름이 자동 발견되지 않아 직접 지정해야 한다. — CloudWatch Application Signals on ECS · 접근 2026-11-04 · 직접
  • [사실] CloudWatch 서울 가격: Application Signals 수집 $0.35/GB(첫 10TB), 사용자 지정 로그 수집(표준 등급) $0.76/GB, 로그 저장 $0.0314/GB-월, Logs Insights 스캔 $0.0076/GB, 경보 $0.10/개·월, Synthetics 캐너리 실행 $0.0019/회(첫 100회 무료). — CloudWatch 서울 가격표(접근 2026-11-04) · 직접
  • [사실] Managed Prometheus 서울 가격: 샘플 4천만 건까지 무료 후 1천만 건당 $0.90(20억 건까지), 저장 10GB까지 무료 후 $0.03/GB-월, 쿼리 처리 10억 샘플당 $0.10. Managed Grafana 서울: 편집자 $9/월, 뷰어 $5/월, 엔터프라이즈 플러그인 $45/월. — Prometheus 서울 가격표(게시 2026-10-14), Grafana 서울 가격표(게시 2026-09-11) · 직접
  • [추정] 두 서비스의 서울 가격 항목(APN2-...)이 있으므로 서울에서 제공된다고 본다. 공식 리전 가용성 목록 페이지는 열지 못했다(Regional Services API는 접속 실패, 마케팅 표 페이지는 스크립트 렌더링). — 위 가격표
  • [사실] 자체 호스팅 Sentry 최소 사양: 4코어, RAM 16GB + 스왑 16GB(권장 32GB), 디스크 20GB 이상(고IOPS 권장), Docker 19.03.6+ / Compose 2.32.2+. Debian·Ubuntu 권장, Alpine 미지원. 보증·전담 지원 없음, Kafka 등 구성요소를 한 대에서 돌린다. 결제, 스파이크 보호, 데이터 위치 선택 같은 SaaS 기능은 없다. 이벤트 보존일은 SENTRY_EVENT_RETENTION_DAYS로 줄인다. — Sentry 자체 호스팅 문서 · 접근 2026-11-04 · 직접
  • [사실] Opsgenie: 신규 판매 종료 2025-06-04, 지원 종료 2027-04-05. Jira Service Management 또는 Compass로 이전할 수 있고, 지원 종료 시 미이전 데이터는 삭제된다는 설명이 있다. — Atlassian Opsgenie 이전 안내(검색 결과) · 접근 2026-11-04 · 검색요약. 이전 시작 120일 뒤 종료 규칙은 제3자 글에만 있고 Atlassian 본문에서 확인 못 했다 [미확인].
  • [사실] CloudTrail 서울 가격표에는 데이터 이벤트 기록 $0.000001/건, Lake 질의 스캔 $0.005/GB 항목이 있다. 관리 이벤트 기본 보존의 가격 행은 이 필터에서 못 봤다. — CloudTrail 서울 가격표(게시 2026-11-02) · 직접

계산 (서울 가격표, 730시간 또는 30일)

  • [추정] 개인정보를 서울 밖으로 못 보내는 제약에서는 CloudWatch(Application Signals 포함) 또는 Managed Prometheus/Grafana가 SaaS보다 먼저 후보다. 1명 운영이면 CloudWatch 하나가 부품이 가장 적다.

  • [가설] 안전 경로(넘김 타이머, 신호 끊김)의 “조용한 실패” 감시: ① 작업자가 분마다 찍는 하트비트 메트릭, ② 이 메트릭이 없으면 경보가 울리게(누락 데이터를 이상으로 처리) 하는 설정, ③ 앱과 다른 곳(예: 캐너리가 운영 URL의 /health/safety를 호출)에서 보는 독립 점검, ④ 경보 수신 경로를 두 갈래(문자·전화 + 메신저)로. 경보 누락 처리 옵션은 이번에 문서로 확인하지 않았다.

3. 네트워크·보안 기본선, 백업, 재해 복구, 인증

Takeaway

VPC 엔드포인트는 NAT보다 항상 싸지 않다. 엔드포인트 5개를 2개 AZ에 두면 월 $94.90으로 NAT 2대($86.14)보다 비싸다. 서울에는 다른 한국 리전을 찾지 못했으므로 “한국 안” DR은 같은 리전 안 계정·볼트 분리와 불변 백업으로 만들어야 한다. ISMS-P는 AWS 쪽 인증이 있고 고객 인증용 컨포먼스 팩이 있지만 2021 자료라 현행 기준과 맞는지 확인이 필요하다.

Inferences

  • [추정] 1단계는 NAT 1대(약 $43)로 시작하고 트래픽이 커지면 엔드포인트를 더한다. 다만 NAT를 한 AZ에 두면 그 AZ 장애 때 외부 호출이 끊기므로, 안전 경로가 외부 호출(알림 발송)에 의존하면 Multi-AZ 시점에 2대로 늘린다.
  • [추정] “한국 안 DR”은 (a) 같은 서울 리전에서 별도 계정의 컴플라이언스 모드 백업 볼트(교차 계정 복사), (b) RDS PITR로 5분 단위 시점 복구, (c) IaC로 다른 AZ에서 재생성하는 순서가 된다. 이 방식은 리전 전체 장애를 막지 못한다 — 한국 안에 다른 리전을 못 찾았기 때문이다.
  • [가설] RPO는 PITR 로그 업로드 주기를 근거로 약 5분 이내를 목표로 둘 수 있다. RTO는 복원이 새 인스턴스를 만들고 블록을 지연 로드하므로 AWS 문서에 숫자가 없다. 복원 훈련으로 직접 측정해야 한다 [미확인].
  • [추정] 컴플라이언스 모드 볼트 락은 되돌릴 수 없고 계정 종료 시에도 90일 뒤 삭제되므로, 실제 데이터 이전에는 거버넌스 모드로 시작해 보존 기간을 확정한 뒤 올리는 편이 안전하다.
  • [추정] CSAP는 공공기관이 클라우드 서비스를 도입할 때의 제도다. 민간 SaaS 사업자가 공공에 판매할 때 SaaS 자체의 CSAP 필요 여부는 이번에 확인 못 했다. [지원 회사] 같은 민간 운영사의 내부 PMS라면 직접 관련이 작을 것으로 보이나 근거는 없다.

Gaps

  • ISMS-P 인증기준 101개(또는 현행 개정) 중 인프라에 대응하는 항목 목록: KISA 원문을 못 열었다. 컨포먼스 팩 매핑표 원문도 열지 못했다.

4. IoT·출입 이벤트 수집 (건물 약 400세대, 10곳 이상)

Takeaway

서울에서 AWS IoT Core(MQTT, X.509 기기 인증서, 규칙)와 Greengrass가 모두 쓸 수 있다. 가격은 메시지 단위라서 센서 하나하나가 매분 직접 보내면 월 약 $30, 건물 게이트웨이가 묶어 보내면 약 $2 수준이다(가정 아래 계산). 업체 웹훅 수집은 이벤트가 적으면 API Gateway+SQS가 월 $2.5 내외로 더 단순하고, 기기 하트비트까지 받으면 IoT Core와 비용이 거의 같아진다. 건물마다 VPN을 두면 연결당 월 $36.50라 10곳이면 $365로 가장 비싸다.

공통 가정 [가설]: 400세대 건물, 기기 400대(세대당 1대), 각 기기가 분당 1회 하트비트(월 43,200회), 이벤트는 기기당 하루 100건(월 3,000건), 메시지는 모두 5KB 이하, 30일.

  • 하트비트 400 × 43,200 = 17,280,000건. 이벤트 400 × 100 × 30 = 1,200,000건. 합계 18,480,000건.

A. 기기가 IoT Core에 직접 연결(MQTT) — 연결 400 × 43,200분 = 17,280,000분

  • 연결 17.28 × $0.096 = $1.66
  • 메시지 18.48 × $1.20 = $22.18
  • 규칙 발동 18.48 × $0.18 = $3.33, 동작 실행 18.48 × $0.18 = $3.33 (규칙 1개·동작 1개 가정)
  • 합계 약 $30.49/월. 구독자 배달 메시지(수신 쪽 과금)는 포함하지 않았다.

B. 건물 게이트웨이 2대가 묶어서 전송(MQTT) — 게이트웨이당 분당 1회 묶음 하트비트 + 이벤트는 개별 전송

  • 메시지 2 × 43,200 + 1,200,000 = 1,286,400건. 연결 2 × 43,200분 = 86,400분 → $0.008
  • 메시지 1.2864 × $1.20 = $1.54, 규칙 $0.23, 동작 $0.23
  • 합계 약 $2.02/월. Greengrass를 쓰면 코어 기기 2대 × $0.16 = $0.32 추가(서울 단가 미확인, 첫 3대 1년 무료).
  • 10곳(곳마다 게이트웨이 1대, 이벤트 같은 양)으로 늘리면 메시지 10 × (43,200 + 1,200,000) = 12,432,000건. 연결 10 × 43,200분 × $0.096/M = $0.04. 메시지·규칙·동작 12.432 × (1.20 + 0.18 + 0.18) = $19.40. 합계 약 $19.44/월.

C. 업체 웹훅 → API Gateway(HTTP API) → SQS → 작업자 — 이벤트만(1,200,000건)

  • API Gateway 1.2 × $1.23 = $1.48
  • SQS: 이벤트당 전송·수신·삭제 3요청 가정 = 3,600,000건, 무료 100만 건 제외 2.6 × $0.40 = $1.04
  • 합계 약 $2.52/월. S3 원문 보관 PUT·저장 비용은 S3 서울 단가를 열지 않아 포함하지 않았다 [미확인].
  • 하트비트까지 HTTP로 받으면 요청 18.48M × $1.23 = $22.73(API Gateway만). A와 거의 같다.

D. 건물마다 Site-to-Site VPN — 연결 $0.05 × 730 = $36.50/월 × 10곳 = $365.00/월(데이터 전송 제외, 이중 터널 공유기·장비 별도).

Inferences

  • [추정] 가격 차이를 만드는 것은 프로토콜이 아니라 메시지 개수다. 건물 안에서 모아 보내거나 변화가 있을 때만 보내면 두 방식 모두 월 몇 달러 수준이다. 서울 단가 기준으로 소규모에서는 수집 비용이 고정비 중 의미 있는 항목이 아니다.
  • [추정] 안전 경로(신호 끊김 감지)에는 MQTT가 유리하다. 문서가 HTTPS는 연결 끊김 감지가 없다고 밝히기 때문이다. 웹훅만으로는 “조용해진 기기”를 서버가 시간 기준으로 직접 세야 한다.
  • [추정] 웹훅 수집은 외부 공급사 쪽이 이벤트를 밀어 주는 구조라서, 공급사가 재시도하지 않거나 서명 방식이 제각각일 때 원문 보관(S3)과 SQS 사이에 끼는 얇은 수신기가 필요하다. API Gateway의 29초 제한과 10MB, SQS 1MiB 한도 안에서는 문제가 없다.
  • [추정] 사이트마다 VPN을 두는 방식은 비용도 크지만 장비·키 관리 부담이 크다. 바깥으로만 나가는 TLS MQTT(또는 WebSocket) 연결이 열린 인바운드 포트 없이 가능해서 건물 쪽 방화벽 협의가 쉽다. 이 방화벽 사정은 현장 확인 전에는 [가설]이다.
  • [추정] EMQX를 직접 운영하면 BSL과 다중 노드 라이선스 파일을 따져야 한다. 1단계에서는 IoT Core 같은 관리형이 라이선스·운영 면에서 가볍다. 반대로 AWS에 묶이는 대가가 있다 — 장치 인증서·규칙·토픽 구조가 IoT Core 전용이다.
  • [가설] 기기 군(群) 관리와 OTA는 Greengrass(AWS 안)나 Mender(자체 호스팅 오픈소스) 중 하나다. 1단계에는 사이트 게이트웨이가 없을 수 있으므로(허브: 조건부) 나중에 고르면 된다.

Gaps

  • Mosquitto, ThingsBoard, Home Assistant, balena, Mender, Tailscale 공식 요구사항과 가격: 못 열었다.
  • AWS IoT SiteWise 불필요 여부: 조사 못 함(산업용 시계열 도구라는 점은 일반 지식이며 확인 안 함).
  • Greengrass 서울 단가, S3 서울 저장·요청 단가, ALB 앞 웹훅 수신(ALB 직접 대상 그룹) 방식의 원문 보관 사례: 못 찾음.
  • IoT Core 수명주기 이벤트(연결·끊김 알림)와 “마지막 유언(LWT)” 문서, Device Defender 가격(서울 가격표 404): 못 열었다.
  • 한국 출입통제·호출벨 업체의 실제 연동 방식(MQTT/웹훅/전용 프로토콜): 이번 범위에서 못 찾음.
