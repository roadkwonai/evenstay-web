이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

표기 규칙은 strategy.md와 같다. 효과 수치와 참여율을 목표로 쓰지 않는다. 포트폴리오에는 실제 이용자가 없으므로 "결과를 확인할 신호"는 데모·테스트에서 보이는 사실이다. 기간은 상대 기간이다. 날짜를 약속하지 않는다.

전략 맥락

  • 비전: 모임 자리, 공용 방의 시간, 꼭 알려야 할 공지를 어느 길로 들어와도 같은 규칙으로 나누고 기록한다(strategy.md 1절).
  • 북극성 [가설]: 중요 공지가 공지 날 전에 대상 호실 모두에서 확인되거나 직접 전해진 비율. MVP에서는 계산이 맞는지만 보인다.
  • 순서 원칙: (1) 자리(정원·대기)와 방(겹침) 규칙을 먼저 단단하게 → (2) 공지 확인 → (3) 다른 모듈로 나가는 조회(D 일정·공지·생활 소식, 운영 현황 카드). 다른 모듈 변경이 필요한 결과는 그 모듈이 준비된 순서로 붙인다.

Now — MVP P0 (1~3주, 코어 위)

만들 것 (output) 결과 (outcome) 결과를 확인할 신호
자원·회차·신청 모델, 회차 생성(F1), 회원 신청(F4), 대기·자동 승급(F5), 마감(F6), 취소(F7) 회원이 앱에서 신청하고 자리가 없으면 순서를 받게 해서, 자리가 나면 다시 누르지 않아도 순서대로 신청이 되게 한다 통합 장면 M4·M6. 동시 신청 테스트에서 정원 초과 0, 순서 = 받은 시각(KR2 가·다)
대신 신청·명단(F8), 승급 문자(F15 일부) 프런트가 전화 신청을 그 자리에서 넣게 해서, 앱 신청과 전화 신청이 같은 줄에 서게 한다 M6 명단의 들어온 곳 표시, 회원 화면 "대신 신청했어요"
출석 체크(F9) 진행 직원이 온 분만 1분 안에 체크하게 해서 [가설], 출석이 다음 회차 준비와 생활 소식 재료로 남게 한다 M3·M11. 오지 않음 행 0, 입주자별 합계 API 0(KR3)
시설 예약과 겹침(F10) 회원과 프런트가 비어 있는 시간 중에서 고르게 해서, 같은 방이 두 사람이나 프로그램과 겹치지 않게 한다 M5. 배제 제약 테스트에서 겹침 0(KR2 나)
공지·확인·직접 전함(F13·F14) 책임자가 꼭 알려야 할 일이 어느 호실에 닿았는지 보게 해서, 앱을 쓰지 않는 분께도 직원이 전한 기록이 남게 한다 M1·M2·M9. [읽었어요] 멱등, 확인 현황 숫자가 시드와 맞음
권한·감사(F21) 모든 쓰기가 누가 언제 했는지 남게 해서, 면접관이 경계와 기록을 따라가게 한다 쓰기 1번 = AuditLog WRITE 1줄, import 경계 CI 통과

Now — MVP P1 (3~4주, 다른 모듈이 준비된 것부터)

만들 것 결과 결과를 확인할 신호 의존
보호자 일정의 신청 프로그램(F16) 멀리 있는 보호자가 회원이 허락한 범위에서 부모님의 모임 날짜를 알게 한다 M8. 대기·예약·출석이 응답에 없음 D 동의 행동 정책(SCHEDULE), D 일정 화면 [N2-D1]
보호자 레지던스 공지(F17) 사업장이 보호자에게도 알릴 공지를 직원이 골라 보이게 한다 M8. 보이기 끈 공지가 보이지 않음 D 첫 화면 칸 [N2-D2]
생활 소식 출석 재료(F18) 생활 소식의 프로그램 줄이 시드가 아니라 기록에서 나오게 한다 11/23 통합 11단계의 프로그램 줄 D 어댑터 교체와 문장 맞추기 [N2-D3]
운영 현황 조회(F19) 책임자가 오늘 할 일(출석 체크 전, 확인 전 공지)을 숫자로 보게 한다 M10 코어 카드 결정 [N2-C2]
장기 부재 반영(F20) 부재 중인 대기자에게 자리가 가서 비는 일을 막는다 M3 표시, 승급 건너뜀 테스트 코어 AbsenceQuery(있음)
바꾸기·쉬기·막기·설정(F2·F3·F11·F12), 나머지 문자(F15) 담당과 책임자가 운영 중 생기는 변경을 화면에서 처리하게 한다 회차 쉬기 때 신청·대기 모두 알림, 막기 때 예약 취소 한 트랜잭션 Notifier(있음)
