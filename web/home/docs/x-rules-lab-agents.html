이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

ChatGPT, Codex, Gemini처럼 Claude Code가 아닌 AI가 이 프로젝트의 진행 상황을 확인하고 검토할 때 읽는 문서다. 규칙의 원본은 CLAUDE.md이고, 이 문서는 무엇을 어떤 순서로 확인할지, 아키텍처 페이지와 도식을 어떻게 만드는지, 어떤 스킬을 설치하고 썼는지 정리한다. 2026-11-05 사용자 요청으로 추가했다.

1. 프로젝트 한눈에 보기

  • 시니어 하우징 회사 지원용 포트폴리오다. 결과물은 기획 문서, 아트보드, 클릭형 프로토타입, 아키텍처 설계안까지다. MVP는 만들지 않는다.
  • 저장소가 둘이다. senior-lab/은 리서치와 기획, evenstay/는 디자인과 프로토타입이다. 같은 폴더에 있는 senior-lab과 evenstay다.
  • 두 폴더 모두 git 저장소가 아니다. 변경 이력이 없어서 덮어쓰면 되돌릴 수 없다. 같은 파일을 두 AI가 동시에 고치지 않는다.

확인하지 못한 내용은 '미확인'이라고 쓰고, 없는 수치와 회사 내부 사정을 지어내지 마세요.

5. 검토할 때 확인할 것

사실과 근거

  • 문장마다 [사실] [추정] [가설] [미정] [미확인]이 내용과 맞는가.
  • 통계, 정책, 회사 정보에 출처 URL과 기준 날짜가 있는가. 없는 수치, 인터뷰, 회사 내부 사정이 들어가지 않았는가.
  • 법령은 시행일과 개정 여부를 확인했는가. 법적 결론을 단정하지 않았는가.
  • 자주 바뀌는 값을 지금 기준으로 다시 봤는가. 프레임워크 버전, 클라우드 단가, Bedrock 모델의 서울 처리 범위가 해당한다.

내용이 서로 맞는지

  • 단계, 비용, 도입 기준, 마일스톤, 영역별 로드맵이 절끼리 맞는가.
  • 설계안, strings/architecture.json, 도식 16장의 내용이 같은가.
  • shared/decisions.md의 결정과 어긋나지 않는가.

지켜야 할 원칙

  • 호출 접수는 건물 안에서 끝나고, 클라우드가 멈춰도 호출은 동작한다.
  • 의료, 응급, 금전, 계약 판단은 사람이 한다. 금전을 실행하는 AI 도구를 만들지 않는다.
  • 회원에게 보이는 답은 기록을 틀에 채워 만든다. 건강 소식이 보호자에게 가는 경로는 family 하나다.
  • 입주자와 보호자에게는 전화, 문자, 직원 대행, 보호자 대행 같은 앱 밖 경로가 있다.
  • 건강과 돌봄 정보는 민감정보로 다룬다. 수집은 최소로 하고 동의와 열람 권한을 설계한다.
  • 화면에 회사 이름, 이모지, 판단 단어(낙상, 응급, 위험 등)를 쓰지 않는다.

한국어

  • 용어가 evenstay/docs/glossary.md와 맞는가. "쓰지 않는 말"이 남아 있지 않은가.
  • 번역투와 한국 개발 문서에서 쓰지 않는 말이 없는가. 원본 문서는 한다체, 웹 문장은 합쇼체다.

6. 함께 작업할 때 지킬 것

할 수 있음 사용자에게 물어야 함 하지 않음
파일 읽기, 검토 노트 쓰기, 공식 자료 대조 승인 문서 내용 변경, 범위 변경, 결정 번복 상태: 승인 표시, shared/ 수정, MVP 구현
  • 승인은 사용자만 한다. shared/는 허브 세션(00-hub/)이 고친다.
  • 검토 결과는 원본을 고치지 말고 senior-lab/00-hub/reviews/<주제>-<AI 이름>-<날짜>.md에 쓴다. 예: architecture-chatgpt-2026-11-06.md. 노트 맨 위에 읽은 파일과 조회일을 적는다.
  • 사용자가 직접 수정을 맡기면 고치기 전에 고칠 파일을 말한다. 다른 세션이 쓰는 중인지 사용자에게 확인한다.
  • 방법: 줄과 보고에는 실제로 한 일만 적는다. Claude Code 스킬은 Claude Code에서만 호출된다. 다른 AI는 방법: ChatGPT 검토처럼 쓴다.
  • 외부 AI에 파일을 올리는 일은 사용자가 정한다. 데모 인물과 수치는 모두 가상이고, 실제 개인정보를 넣지 않는다.

허브에 요청하는 절차

사용자가 승인했거나 shared/, 다른 단계 문서의 수정이 필요할 때 쓴다. 허브에 요청은 사용자가 승인하거나 지시한 뒤에만 한다.

  1. 사용자가 승인하면 대상 문서의 상태: 줄을 상태: 승인(날짜)로 바꾼다. 다른 AI는 이 줄을 고치지 않고 요청 파일에 적는다.
  2. 요청에 아래 내용을 적는다.
    • 사용자 말을 그대로 인용한 승인 또는 지시
    • 승인 대상 파일과, 승인이 포함하지 않는 것
    • shared/decisions.md에 남길 내용(날짜, 결정, 이유, 근거)
    • shared/idea-board.md에서 바꿀 내용이 있으면 그 내용
    • 다른 문서의 보강 요청(파일, 절, 무엇이 없는지)
    • 근거 파일
  3. 요청을 보낸다.
    • Claude Code 세션: 허브 세션에 SendMessage로 보내고, 세션 공유 노트가 있으면 같은 내용을 남긴다.
    • 다른 AI: 세션 메시지를 보낼 수 없다. senior-lab/00-hub/reviews/hub-request-<주제>-<AI 이름>-<날짜>.md에 쓰고, 사용자에게 허브에서 처리를 지시해 달라고 한다.
  4. 보낸 것과 처리된 것을 구분해 보고한다. 허브의 처리 결과는 shared/decisions.md와 허브 보고로 확인한다.

8. 아키텍처 페이지 제작

통합웹 페이지는 design/prototype/home/architecture.html이고 생성물이다. 아래 순서로 만든다. 2026-11-05 작업을 기준으로 적었다.

  1. 내용 확정. senior-lab/01-research/outputs/senior-housing-architecture-design.md를 먼저 고친다. 나머지는 이 문서를 따라간다.
  2. 페이지 문장. design/prototype/strings/architecture.json을 고친다. 문장은 합쇼체이고 [[용어]]로 감싸면 용어집 단추가 된다. 감싼 말은 docs/glossary.md의 "아키텍처 용어"에 있어야 한다.
  3. 페이지 틀. 새 절이나 항목을 더할 때만 design/home/build.mjs의 pageArchitecture와 design/prototype/home/assets/home.css를 고친다.
  4. 도식. 아래 표의 원본을 고치고 도구별 명령으로 다시 만든다. 결과는 design/prototype/home/architecture/에 html과 png로 쌓인다.
  5. 빌드. node design/home/build.mjs로 페이지와 문서 페이지를 다시 만든다.
  6. 문장표. node design/home/architecture/sync-text.mjs --list로 docs/project.md 15절을 새로 쓴다.
  7. 검사. 7절의 두 명령과 sloplint를 돌리고, 데스크톱과 375px 폭을 브라우저로 본다.

스킬 도식 출처와 설치 위치

  • archify는 라벨이 겹치거나 상자가 좁으면 빌드가 멈춘다. finalize 결과만으로 원인이 안 보이면 임시 사본의 renderers/<유형>/render-<유형>.mjs를 직접 돌리면 메시지가 나온다. 시퀀스는 참여자 7개까지 기본 폭에 맞는다.
  • 도식의 내용 기준은 설계안이다. design/home/architecture/brief.md는 처음 만들 때의 지시서라 옛 값이 남아 있다.
  • 웹 도식의 프레임 높이는 strings/architecture.json의 figs.<id>.h다. 도식 내용이 길어지면 함께 고친다.
  • 페이지 디자인은 hallmark를 쓴다. DESIGN.md가 잠긴 시스템이라 테마를 새로 뽑지 않고 앱 범위로 돌린다. 끝낼 때 sloplint로 FAIL 0을 확인한다.
  • 한국어 검수는 grammar-checker(맞춤법), style-guide(어조와 용어), humanizer(번역투) 순서로 한다.

9. 설치하고 사용한 스킬

Claude Code 스킬은 Claude Code에서 Skill 도구로만 호출된다. 다른 AI는 호출할 수 없으니 이 표로 어떤 방법을 썼는지 파악한다.

호출 횟수는 evenstay/design/home/history/skills.json의 집계다(2026-11-04 22:37 기준, 호출 ID로 중복 제거). 2026-11-05 아키텍처 작업은 집계 전이고, 이때 쓴 stack-diagram, archify, diagram-design은 숫자가 없다.

기획과 PM 스킬. 폴더마다 필요한 스킬만 npx skills add로 설치했다. 출처는 폴더별 skills-lock.json에 있다.
