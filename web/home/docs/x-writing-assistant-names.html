이름은 확정돼 있어 product-name 스킬은 쓰지 않았다. 회원 화면은 Evenstay 홈 비서, 직원 화면은 AI 생활 비서다(../pms-core-billing/names.md v3 조합 1, 2026-11-02 확정. 직원 화면 이름은 2026-11-03에 한글로 바꿨다). 여기서는 화면 안 라벨만 정한다.

라벨 원칙

  • 회원 화면에서 영문 이름은 첫 화면 제목에만 쓰고 한글 읽기를 붙인다. 메뉴와 버튼은 "비서"라고만 쓴다.
  • 회원 화면 버튼은 회원님이 하는 동작이나 묻는 말로 쓴다("계약·청구서 날짜", "이번 달 청구서 설명").
  • 조회 도구 하나 = 큰 버튼 하나. 쓰기 도구(청구 문의 접수, 직원에게 넘기기)는 확인 화면 하나를 갖는다. 모듈이 붙으면 같은 꼴의 버튼을 더한다(3절).
  • 직원 화면은 업무 용어(대화 기록, 넘겨받은 요청, 도구 호출)를 쓰고, 입주자를 "입주자"로 부른다.

1. 회원 화면 (Evenstay 홈 비서)

위치 라벨 이유
앱 홈의 메뉴 비서 2음절, 하는 일이 바로 보인다. "AI 비서"는 메뉴 이름에 넣지 않고 첫 화면과 답마다 AI임을 보인다(AI 사용 안내는 D 고지)
첫 화면 제목 Evenstay(이븐스테이) 홈 비서 코어 names.md v3 회원 화면 원칙: 영문 이름은 첫 화면에만, 한글 읽기와 함께
큰 버튼 1 (일정 조회) 계약·청구서 날짜 버튼이 보여 주는 것을 그대로 쓴다. 최소판 날짜는 계약·청구 날짜 여섯 가지뿐이라 시설 프로그램이나 병원 날짜를 기대하게 하는 "다음 일정", "오늘 일정"은 채울 수 없는 약속이 된다. 시설 일정 도구가 붙으면 "오늘 일정"을 따로 둔다
일정 답 아래 버튼 계약 날짜 보기 일정 답은 청구서 날짜부터 보이고, 계약 날짜는 이 버튼으로 나눠 한 답이 세 줄을 넘지 않게 한다(copy.md 답의 틀)
큰 버튼 2 (청구 설명) 이번 달 청구서 설명 코어 회원 화면 "이번 달 청구서"에 "설명"만 더했다
큰 버튼 3 (넘기기) 직원에게 전하기 "상담 요청", "문의 접수"는 딱딱하다. 회원님이 하는 동작 그대로
큰 버튼 4 (앱 밖 길) 프런트로 전화하기 앱 밖의 길을 늘 같은 자리에 둔다
말하기 버튼 말로 묻기 음성은 보조 채널이라 큰 버튼 아래에 둔다(ai-assistant.md 0절)
말하는 중 듣고 있어요
지난 대화 지난 대화
답 아래 한 줄 확인한 곳: ○○ 코어 "근거를 보인다"를 대화로 옮김. "출처", "근거"는 회원에게 딱딱하다
가린 숫자 표시 (회원·직원 화면 같음) [가린 번호] 무엇을 가렸는지 한눈에 보이고, 화면 읽기 프로그램도 "가린 번호"로 읽는다. "●●●●"이나 "***"는 무엇인지 알기 어렵다. 가림 규칙은 G ADR-G9
답 옆 AI 표시 AI 비서 답마다 사람이 아닌 AI가 답했다는 것을 보인다. 고지 문구 자체는 D 3절을 쓴다
확인 버튼 (넘기기, 청구 문의 전) 네, 전해 주세요 · 아니요 상태를 바꾸는 일은 회원 확인 뒤에만(ai-assistant.md 5절 원칙 2). 청구 문의도 회원님에게는 "직원에게 전하기"와 같은 말로 묻는다. 확인 버튼 말이 하나면 배울 것이 줄어든다
대리인 호칭 ○○ 님 (대리하는 회원은 "○○○ 회원님") 대리인은 회원이 아니라 "회원님"으로 부르지 않는다. 범위는 코어 copy 3절 "대신 처리하실 수 있는 일"과 같은 말
AI 사용 안내 메뉴 AI 사용 안내 D 용어집 AiNotice와 같은 말

keyDates 라벨 (일정 조회 답에서 쓰는 말)

코드 직원 화면 회원 화면

2. 직원 화면 (AI 생활 비서)

위치 라벨
메뉴 대화 기록 · 넘겨받은 요청 · 도구 호출 기록
넘겨받은 요청 상태 새 요청 · 처리 중 · 처리 완료
넘긴 이유 (HandoffReason) 건강 판단 · 금전 판단 · 계약 판단 · 도구 밖 질문 · 직접 요청
도구 이름 (최소판) 코어 도구: 일정 조회 · 청구 설명 · 청구 문의 접수 / 비서 도구: 직원에게 넘기기
호출 결과 성공 · 권한 거부 · 데이터 없음 · 오류
행위자 입주자 본인 · 대리인(범위 표시)
  • "직접 요청"은 회원님이나 대리인이 [직원에게 전하기]를 직접 누른 경우와, 코어 청구 문의 기능이 없을 때 [이 금액이 이상해요]가 넘기기로 대신 가는 경우다(MEMBER_ASKED). 처음 정한 "입주자 요청"은 대리인이 누른 경우에 맞지 않아 바꿨다(2026-11-03). 누가 요청했는지는 행위자 열이 보여 준다.
  • 투자 질문을 넘기면 이유는 금전 판단이다(G 기획 확정).
  • 상태 세 개는 코어 확인 창 형식처럼 짧은 명사로 둔다. 처리 기한 표시는 [NEED: 운영사가 정한 회신 기한].
