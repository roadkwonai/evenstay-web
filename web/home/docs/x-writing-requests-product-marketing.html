Product Overview

One-liner: 입주자가 말한 생활의 부탁(고장, 청소, 세탁, 외출 차량, 병원 동행, 불편한 점)을 한 줄로 받아 담당 직원에게 나누고, 마칠 때까지의 기록과 입주자 확인을 남기는 모듈. What it does: 입주자, 허락받은 보호자, 직원, Evenstay 홈 비서가 요청을 올린다. 종류별로 담당 직원에게 배정하고 접수 → 처리 중 → 완료 → 입주자 확인까지 상태를 남긴다. 주 2회 청소나 월 점검 같은 정기 작업은 사업장 일정에서 자동으로 만든다. 비용이 드는 요청은 코어 청구 항목으로, 열린 요청 수는 운영 현황 대시보드로 보낸다 [사실: 허브 요약과 coverage review 4-1 N1 행]. Product category: 시니어하우징 PMS의 작업 지시(work order)·입주자 요청 기능 [사실: 해외 입주자 앱의 기본 기능, R10·R11·R12]. 국내에서 찾는 말로는 "민원 접수", "AS 신청", "세대 요청" [추정]. Product type: Evenstay 코어 위에 붙는 모듈. 직원 화면(Evenstay), 회원 화면(Evenstay 홈), 보호자 화면(Evenstay 패밀리)에 모두 걸친다. Business model: 포트폴리오에서는 해당 없음.

Target Audience

Target companies: 시니어하우징(노인복지주택)과 임대주택을 위탁 운영하는 회사 [사실: 코어와 같음]. Decision-makers: 사업장 책임자(시설장), 운영 매니저(U5). 기술 판단은 Tech Lead. Primary use case: 입주자가 전화나 지나가는 말로 한 부탁이 메모에서 사라지지 않고 담당자에게 가서 끝까지 처리되었는지 남긴다. Jobs to be done:

  • 입주자: 고장이나 불편을 한 번 말하면 누가 맡았고 언제 끝났는지 알고 싶다.
  • 현장 직원: 오늘 내가 할 요청이 무엇인지, 어느 호실에 언제 가야 하는지 한 목록에서 보고 싶다.
  • 책임자: 열린 요청이 쌓이지 않는지, 정기 청소와 점검이 빠지지 않았는지 보고 싶다. Use cases:
  • 회원이 앱에서 "화장실 전등이 안 켜져요"를 올림 → 시설 담당 배정 → 교체 → 회원이 "고쳐졌어요" 확인
  • 회원이 프런트에 전화로 세탁을 부탁 → 프런트 직원이 대신 올림 → 수거·전달 → 비용이 청구 항목으로 감
  • 비서 대화에서 "직원에게 전하기" → 생활 요청 목록에 "홈 비서"에서 온 요청으로 들어옴
  • 사업장 정기 작업(A동 매주 화·금 청소)이 매주 자동으로 만들어지고, 회원이 "이번 주 청소 쉬기"를 고름
  • 딸(보호자)이 "엄마 방 에어컨이 이상하대요"를 Evenstay 패밀리에서 올림(회원이 "생활 요청"을 허락한 경우, 사용자 "추천대로" 2026-11-03)

Problems & Pain Points

Core problem: 국내 시설에서 입주자가 말로 한 요청(전등, 수리, 식사 변경)을 요청 큐로 넘기는 구조가 확인되지 않아 직원이 전화로 받아 적는다 [추정: P-052, 신뢰도 근거 G12·G16]. Evenstay에도 요청 접수 → 배정 → 처리 → 완료 확인 흐름이 없고, 비서의 "직원에게 넘기기"가 갈 곳도 없다 [사실: coverage review S18 행]. Why alternatives fall short:

  • 프런트 전화와 종이 메모: 누가 맡았는지, 끝났는지가 남지 않는다 [추정].
  • 아파트 관리 앱의 민원 접수: 시니어 레지던스의 청소·세탁·동행처럼 사업장이 제공하는 생활 서비스와 청구 연결이 없다 [추정].
  • 해외 입주자 앱(Touchtown, LifeLoop)과 시설 관리 SW(TELS): 작업 지시는 있으나 한국어·국내 계약·청구 구조에 맞지 않는다 [사실: 기능은 R10·R11·R12, 맞지 않음은 추정]. What it costs them: 같은 부탁을 다시 하는 시간, 빠진 정기 청소, 비용이 드는 서비스의 청구 누락 [추정. NEED: 현장 직원 인터뷰의 실제 사례]. Emotional tension: 입주자는 "또 말하기 미안하다"와 "말했는데 왜 안 되지" 사이에 있고, 직원은 누가 무엇을 들었는지 확인할 길이 없다 [추정].

Competitive Landscape

Direct: 해외 시니어 리빙 입주자 앱의 작업 지시(Touchtown R10, LifeLoop R11) — 한국어와 국내 시설 운영 방식에 맞지 않는다 [추정]. Secondary: 시설 관리 SW(TELS R12), 국내 아파트 관리 앱의 민원 기능 — 시니어 생활 서비스와 청구 연결이 없다 [추정]. Indirect: 프런트 전화, 종이 메모, 단체 메신저 방 — 기록과 배정, 입주자 확인이 없다 [추정].

Differentiation

Key differentiators:

  • 요청이 들어오는 길이 넷(Evenstay 홈, Evenstay 패밀리, 프런트 전화를 직원이 대신 올림, 홈 비서)이어도 같은 목록, 같은 상태로 모인다.
  • 직원이 "완료"를 눌러도 입주자가 확인해야 닫힌다. 입주자가 "아직이에요"를 누르면 다시 열린다.
  • 정기 작업은 일정에서 자동으로 만들어지고, 회원이 한 번 쉬기를 고를 수 있다.
  • 비용이 드는 요청은 끝난 뒤 코어 청구 항목이 되어 청구서에 근거가 붙는다.
  • 몸이 불편하다는 말은 생활 요청으로 다루지 않고 안심 알림으로 보낸다. 시스템이 알아서 가르지 않고 직원이 옮긴다. How we do it differently: 화면보다 요청의 상태 전이와 출처, 배정, 기한을 먼저 정한다 [가설: 기획에서 설계]. Why that's better: 누가 언제 무엇을 했는지 남아서 입주자에게도 보호자에게도 기록으로 답한다 [추정]. Why customers choose us: [NEED: 실제 도입 근거 없음. 포트폴리오에서는 설계 근거로 대신한다]

Objections

Objection Response
전화로 받으면 되는데 앱이 필요한가 전화는 그대로 받는다. 직원이 대신 올리는 버튼이 첫 화면에 있고, 기록만 한곳에 남긴다
입주자가 앱을 못 쓴다 앱은 여러 길 중 하나다. 프런트 전화, 지나가는 직원, 홈 비서로도 올릴 수 있고 확인도 직원이 대신 기록할 수 있다
급한 일이 요청 목록에 묻히면 어떡하나 요청 화면마다 "급한 일이나 몸이 불편하실 때는 호출벨·프런트 전화"를 고정한다. 직원이 요청 내용을 보고 안심 알림으로 옮길 수 있다
처리 시간을 약속해야 하지 않나 회원에게 시간을 약속하지 않는다. 처리 기한은 사업장이 정하는 직원용 값이다 [미정: 종류별 기한]
Anti-persona: 시설 관리 전체(자산 대장, 법정 점검 서류, 협력 업체 계약)를 원하는 운영사. 이 모듈은 정기 작업 일부만 다룬다 [사실: coverage review S56 "외부 시설관리 SW 영역", N1은 일부만].

Switching Dynamics

Push: 전화 메모, 다시 묻는 부탁, 빠진 정기 청소 [추정]. Pull: 맡은 직원 이름과 상태가 보이는 요청, 끝나면 입주자가 확인하는 흐름. Habit: 프런트 전화, 지나가는 직원에게 말로 부탁하기. 이 습관은 없애지 않고 직원이 대신 올리는 길로 받는다. Anxiety: 직원 입장에서 "일이 하나 더 는다", 회원 입장에서 "앱으로 하라고 하면 어쩌나" [추정].

용어 메모

  • "작업 지시"는 코드와 면접 자료에서만 쓴다. 화면에는 "생활 요청"과 "정기 작업"만 쓴다.
  • 직원 화면에서 회원 본인이 앱으로 올린 요청의 들어온 곳은 "Evenstay 홈"이라 쓴다. 회원이라는 말을 피하려는 것이다.
  • "의견·불편"은 일반 민원(소음, 서비스 불만, 이웃)을 받는 종류다 [사실: coverage review S39]. 청구 문의는 코어(A) 청구 문의로, 소식 문의는 D "내용이 이상해요"로 간다. 이 모듈이 그 둘을 대신 받지 않는다.

Brand Voice

코어 목소리(차분하다, 존중한다, 근거를 보인다, 기록이 남는다)를 그대로 쓴다 [사실: senior-lab/03-copywriting/ideas/pms-core-billing/product-marketing.md]. 이 모듈에서 더하는 것만 적는다.

Attribute Means Doesn't mean Example line
맡은 사람이 보인다 상태 옆에 담당 직원 이름을 붙인다 직원을 탓하거나 재촉하는 말 "한도윤 직원이 맡았어요."
약속하지 않는다 처리 시간을 말하지 않고, 회원이 고른 날짜만 다시 말한다 "곧", "바로 처리해 드려요" "11월 20일 오전 10시로 요청하셨어요."
다른 길을 늘 둔다 앱이 어려우면 프런트, 직원, 비서로 앱만 쓰라는 말 "앱이 어려우시면 프런트 02-000-0000 (가상 번호)으로 전화하시거나 직원에게 말씀해 주세요. 직원이 대신 요청해 드려요."

Tone by context:

  • 회원 화면: 해요체, 한 화면에 한 가지 일, 큰 버튼. 종류는 그림과 글자를 같이 둔다.
  • 보호자 화면: 해요체, "○○○ 회원님", 허락 범위 표시 한 줄을 위에 둔다(D와 같은 틀).
  • 직원 화면: 합쇼체·명사형 라벨. 상태와 다음 행동을 함께.
  • 오류: 무엇이 안 됐는지 → 왜 → 무엇을 하면 되는지. 탓하지 않는다.
  • 포트폴리오 소개: 문제 → 설계 판단 → 데모. Terms we own: Evenstay(운영), Evenstay 홈(회원), Evenstay 패밀리(보호자), Evenstay 홈 비서 [사실: names.md v4]. 모듈 이름은 names.md 1절. Never use (and why):
  • "빠르게 처리해 드립니다", "24시간 안에" — 처리 시간을 측정하거나 약속한 근거가 없다.
  • "AI가 알아서 접수" — 비서는 직원에게 전할 뿐이고 종류와 담당은 직원이 정한다.
  • 병원 동행에서 "진료", "증상", "어디가 아프신지" 묻기 — 이 모듈은 일정과 이동만 받는다.

Theme Proof (데모에서 보일 것)
들어오는 길이 달라도 한 목록 회원 앱, 보호자, 프런트 대신 등록, 비서에서 온 요청이 같은 목록에 출처와 함께 보임
입주자가 확인해야 닫힘 직원 완료 → 회원 "아직이에요" → 다시 처리 중 → 회원 "다 됐어요" → 닫힘, 모든 전이가 기록됨
정기 작업 자동 생성 매주 화·금 청소가 일정에서 만들어지고 "이번 주 쉬기"가 반영됨
청구 연결 세탁 요청 완료 → 코어 청구 항목 생성 → 회원 청구서에 근거와 함께 보임
경계 몸이 불편하다는 요청을 직원이 안심 알림으로 옮기는 버튼
