한 줄 요약

시니어 레지던스 회원이 가족마다, 항목마다 보여 줄 범위를 정하고, 가족은 그 범위 안에서 생활 소식·일정·청구서·건강 소식을 한곳에서 보는 보호자 화면. 거두면 다음 요청부터 막히고 모든 열람이 기록된다. B·G·C가 이 동의 체계를 family/api로 쓴다.

대상

  • 정하는 사람: 회원(입주자). 판단이 어려우면 MANAGE_GUARDIAN_ACCESS 대리인
  • 보는 사람: 보호자(회원 화면 "함께 보실 분")
  • 돕는 사람: 프런트 직원(대신 입력, 금전 부탁 접수), 생활지원 직원(생활 리포트 검토·발송)
  • 확인하는 사람: 본사 운영 매니저(열람 기록, 금전 부탁·건강 소식 올리지 않기 주간 확인, AI 고지 현황), 사업장 책임자(자기 사업장의 열람 기록과 주간 확인 [가설])

핵심 흐름 (MVP)

  1. 동의: 함께 보실 분(시드 연결) → 항목별 보여 주기(회원 직접, 또는 직원 대신 입력 → 회원 확인) → 건강 소식 별도 동의 → 보호자 화면이 다르게 보임 → 그만 보여 주기 즉시 반영 → 열람 기록
  2. 생활 소식: AI 사용 고지 확인 → AI 초안(어댑터) → 직원 검토(근거, 건강 낱말 경고) → 발송 → 보호자 화면 확인 표시
  • 항목 5개: 생활 소식, 일정, 청구서, 건강 소식, 생활 요청(P1, 2026-11-03 N1 결정, 사용자 재승인 2026-11-04. 요청 데이터와 보호자 화면은 N1). B 결과 알림은 건강 소식 안에 들어간다
  • 넓힘은 회원(또는 대리인) 확인으로만, 좁힘은 누가 입력해도 즉시
  • 데모 5단계와 시드: prd.md 9절
  • P1 추가(2026-11-03, 사용자 재승인 2026-11-04): 장기 부재 소식(F18, 코어 부재 이벤트를 받아 생활 소식 허락 보호자에게만 자리를 비우신 소식·돌아오신 소식, 이유·병원 없음), 사업장 동의 현황 숫자(F19, app/ 대시보드 D1이 읽기만)
