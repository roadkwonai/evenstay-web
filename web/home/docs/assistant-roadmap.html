전략 맥락

  • 비전: 기록으로만 답하고 판단은 사람에게 넘기는 비서(strategy.md 1절).
  • 이 로드맵의 원칙: 도구가 늘어도 틀은 그대로다. 새 판마다 바뀌는 것은 도구 정의, 답 틀, 큰 버튼, 평가 문항이고, 대화·도구 호출·확인 토큰·넘김 구조는 바뀌지 않는다(tech-design.md ADR-G2).
  • 핵심 가정: 회원이 비서에게 실제로 묻는다(H1), 민감한 말을 빠짐없이 넘긴다(H3).

Now — 최소 버전 (코어 MVP 직후 2~4주)

출력 (기능) 결과 문장 지표
고지 게이트(F1), 첫 화면(F2) 회원이 AI가 하는 일과 하지 않는 일을 먼저 듣고 비서를 쓰게 해서, 운영사가 AI 기본법 사전 고지를 기록으로 증명한다 고지 미확인 상태의 도구 호출 0건
일정 조회(F3), 청구 설명(F4), 답 틀(F10) 회원이 큰 버튼 하나로 자기 청구서 날짜와 금액의 이유를 확인한 곳과 함께 듣게 해서, 비서의 답이 원장 밖으로 나가지 않는다 출처 없는 사실 줄 0건(KR1 ③)
말로 묻기·라우터(F5), 모를 때(F6), 평가 세트(F11) 회원이 말로 물어도 판단이 필요한 말은 도구가 아니라 사람 쪽으로 가게 해서, 판단 대행 사고를 막는다 민감 문항 도구 호출 0건(KR1 ①), 도구 선택 90% 이상 [가설](KR2)
넘기기·확인 토큰(F7), 넘겨받은 요청(F8), 기록(F9) 직원이 회원이 허락한 요청만, 무엇을 물었고 비서가 어디까지 답했는지와 함께 받게 해서, 처음부터 다시 묻지 않는다 확인 없는 쓰기 0건(KR1 ④), 넘김 처리 완료까지 걸린 시간(기록만)
P1: 청구 문의(F12), 납부 갈래(F14), 대리인(F13), 지난 대화(F15), 보관 정리(F16) 회원과 대리인이 청구 이의를 경리에게 바로 보내고 낸 기록을 함께 듣게 해서, 청구 문의가 한 곳(코어)에 모인다 비서 경로 문의 수, 범위 밖 대리 호출 거부 수

Next — 모듈이 붙는 동안 (각 1주 안팎, 도구 하나씩) [가설]

출력 (도구 후보, 이름은 각 모듈 기획 후) 결과 문장 지표 의존
D: 금전 넘김을 D 금전 부탁으로 직접 열기(MoneyRequestCommand) 금전 의심 연락을 말한 회원의 요청이 직원 손으로 옮겨 적히지 않고 D 금전 부탁 기록으로 바로 가게 해서, 금전 경계(I-31) 처리가 한 곳에 남는다 손으로 옮긴 금전 넘김 0건 D F13(P1), D MoneyRequestCommand.open({residentId, sourceRef, note})(종류는 직원이 고름, 회원 본인만. HUB-9 반영, 재승인 2026-11-03). 대리인이 넘긴 돈 이야기는 계속 G 넘김으로 남아 이 지표에서 뺀다
D: "누가 내 소식을 보나" 조회(FamilyConsentQuery.viewersOf) 회원이 자기 소식을 누가 보는지 비서로 듣게 해서, 동의 화면을 찾지 않아도 된다 해당 질문의 도구 답 비율 D API(초안)
B: 내 호출 처리 상태 조회(읽기) 회원이 호출벨을 누른 뒤 직원이 오는 중인지 비서로 듣게 해서, 불안해서 거는 전화가 줄어든다 [가설] 해당 질문의 도구 답 비율 B 공개 API(B 기획)
C: 내 생활 지원 단계와 단계가 바뀌는 때 설명(읽기, transitions/api CareStageQuery.memberView) 회원이 단계 변화의 이유를 쉬운 말로 듣게 해서, 단계 결정은 사람이 하되 설명은 비서가 돕는다 단계 질문 넘김 비율 C 기획 HUB-G2. 고영향 AI 해당 여부 다시 검토 [법률 검토](G5)
N1: 내 요청 보기(읽기), 요청 올리기(쓰기, 확인 토큰) (N1-G4) 회원이 생활 요청을 비서로 올리고 진행을 듣게 해서, 고장 신고와 질문을 한 창구에서 한다 요청 올리기 중 회원 확인 비율 100% N1 기획(조회·명령 이름)
N2: 프로그램 일정 읽기 (2026-11-04 허브 지시) 회원이 "오늘 일정"을 비서로 듣게 해서, 원래 구상(ai-assistant.md 1절)에 가까워진다 답에 확인한 곳이 붙은 비율 100% N2 기획(조회 이름)
자연 문장 답 + 출처 검사기 답이 덜 딱딱하게 들리되 숫자·날짜는 여전히 도구 결과에서만 나오게 해서, 자연스러움과 정확성을 같이 지킨다 검사기 거부율, 출처 없는 숫자 0건 평가 세트 확장
회신 기한·새 요청 알림(직원) 넘긴 요청이 늦게 처리되지 않게 해서, 회원이 기다리지 않는다 기한 넘긴 요청 수 [NEED: 운영사 회신 기한], 코어 Notifier

Later — 실서비스에 가까워지기

출력 결과 문장 지표
전화 채널(같은 대화 API), 읽어 주기(TTS) 앱이 어려운 회원도 전화나 듣기로 같은 비서를 쓰게 해서, 대안 경로가 기록 안으로 들어온다 채널별 질문 수
보호자용 비서(D 동의 범위 안) 보호자가 회원이 허락한 범위 안에서만 묻고 듣게 해서, 동의 밖 정보가 새지 않는다 동의 밖 답 0건
법률 검토 반영(고지 문구, 보관 기간, 음성 인식 위탁) 실서비스 전에 법적 문구와 보관 규칙을 확정해서, 운영사가 그대로 쓸 수 있다 검토 완료 항목 수
(별도 프로젝트) 자산 조회·설명 L1 senior-lab 밖에서 다룬다. 모의투자 서버·가상 데이터 시연만, 추천·주문 없음 [초안 결정, ai-assistant.md 4절] —

순서와 의존

  • 코어 MVP(P0) → G 최소 버전 Now P0. G의 P1은 코어 P1에 묶인다: F12 ↔ 코어 F15, F13 ↔ 코어 F13, F14 ↔ 코어 F16(납부 상태 노출은 HUB-1로 코어에 반영됨).
  • D 고지 v2(D F10, P0)가 G보다 먼저 있어야 한다. D가 늦으면 고지 목업으로 데모한다(prd.md 13절).
  • Next의 도구는 각 모듈 기획이 끝나고 공개 API가 정해진 뒤 붙인다. 기획 순서상 C는 G 다음이다.
  • 자르는 선: prd.md 14절(확인 토큰 테스트가 2주 차에 통과하지 않으면 LLM 라우터를 미룬다).
