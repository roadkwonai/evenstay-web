3. 섹션별 명세

각 섹션은 목적 · 문구 자리 · 에셋 자리 · 상호작용 · 데스크톱/모바일 · 접근성 · 애니메이션 의도 순서로 적는다. 애니메이션은 의도만 적고 값은 emil 단계에서 정한다. 모든 섹션 공통으로 스크롤 등장은 "투명도 0 → 1, 아래에서 12px 위로, 한 번만"을 기본 의도로 하고, prefers-reduced-motion: reduce에서는 이동 없이 투명도만 160ms로 남긴다 [가설: DESIGN.md Motion 움직임 줄이기 규칙을 따름].

LND-00 상단 바

  • 목적: 어디서든 상담 신청과 전화로 갈 수 있게 한다.
  • 문구 자리: 페이지 메뉴 8개(소개, 시설, 숙소, 생활, 식사, 안심·건강 지원, 오시는 길, 입주 상담. 식사는 최상위 메뉴다(U-18). 사이트맵 prd.md 9절) [NEED: 카피 C-01, C-19]. 1024px 이상 상단 링크 4개는 숙소, 생활, 식사, 오시는 길이고 나머지는 전체 메뉴에 둔다 [사실: 카피 정한 것 3]. 전화 라벨은 "전화 상담 02-000-0000 (가상 번호)"다 [사실: 카피 정한 것 2]. 주 버튼 라벨은 C-04와 같다. 모든 페이지가 같은 머리를 쓴다.
  • 에셋 자리: Evenstay 가로형 로고 evenstay/design/brand/logo/evenstay-logo-light.svg(기존, 생성 없음).
  • 상호작용: 메뉴는 각 페이지로 이동하고, 지금 페이지에 표시(aria-current="page", 굵기 + 밑줄). 주 버튼은 메인에서는 LND-10, 다른 페이지에서는 /consult SITE-CON-01로 가서 첫 입력에 포커스. 스크롤을 내리면 바가 위에 붙는다 [가설].
  • 데스크톱/모바일: 1024px 이상 로고 · 링크 4개 · 전화 · 주 버튼. 아래에서는 로고 · 전화(아이콘 + "전화" 글자) · 메뉴(글자 "메뉴" + 아이콘). 메뉴는 전체 화면 시트, 항목 높이 56px [가설].
  • 접근성: nav에 이름, 건너뛰기 링크("본문으로"), 포커스 링 유지. 메뉴 시트는 포커스를 가두고 Esc로 닫는다.
  • 애니메이션 의도: 붙을 때 아래 1px 선만 나타남. 메뉴 시트는 ease-drawer 280ms 이하.

LND-01 히어로(순차 영상)

  • 목적: 첫 화면에서 건물과 숙소를 먼저 보여 주고 그 안의 "편히 쉬는 하루"로 이어 가며, 상담 신청과 전화를 바로 보이게 한다.

  • 문구 자리:

    • 제목 [NEED: 카피 C-02]. 참고 방향: 브랜드 3안 "함께 보는 기록"과 6-1 가치 제안 문장(prd.md). "건강이 나빠져도 계속 사실 수 있어요", "24시간 지켜 드려요"는 쓰지 않는다 [사실: C·B value-prop "쓰지 않기로 한 문장"].
    • 부제 한두 문장 [NEED: 카피 C-03].
    • 주 버튼 라벨 [NEED: 카피 C-04](상담 신청 뜻). 보조: 전화번호 02-000-0000 + "가상 번호".
    • 현재 영상 설명 6개, 순서 표시(예: 2 / 6), 이전·다음 화살표 이름, 일시정지·재생 버튼 라벨 [NEED: 카피 C-05].

  • 영상 구성 [사실: U-02 사용자 변경, 6편·편당 5초, 2026-11-04]:

    항목 정의

    소리 없음. 파일에서 소리 트랙을 지운다(muted만으로 두지 않음)

    불러오기 지금, 이전, 다음 영상만 받는다. 화면 밖으로 나가면 멈추고, 돌아오면 이어서(사용자가 멈춘 경우 제외)

    지속 시간 띠 영상별 6칸 띠. 1024px 이상은 제목 칸 오른쪽부터 오른쪽 여백까지, 아래는 영상 맨 아래 전체 폭이다. 보이는 줄 4px, 칸마다 누르는 영역 높이 56px. 지금 칸이 약 4초 동안 왼쪽에서 오른쪽으로 차고, 지난 칸은 찬 채로, 다음 칸은 빈 채로 둔다. 칸을 누르면 그 영상으로 간다. 멈추면 띠도 멈춘다 [사실: 새 캔버스 메인 보드, evenstay/design/canvas-notes.md]
    양쪽 화살표 영상 좌우 가장자리 세로 가운데, Lucide chevron-left/chevron-right. 글자 없는 아이콘 버튼이고 소개 사이트 예외다. 보이는 크기 48px, 누르는 영역 56px. 이전·다음 영상으로 가고, 띠는 그 칸 처음부터 다시 찬다. 첫 영상에서 이전을 누르면 마지막 영상으로, 마지막에서 다음을 누르면 첫 영상으로 간다. 멈춘 상태에서 누르면 영상만 바뀌고 멈춘 상태는 유지한다 [사실: 새 캔버스 메인 보드, evenstay/design/canvas-notes.md]
    현재 영상 설명 1024px 이상 영상 오른쪽 아래, 640px 아래 영상 오른쪽 위. 단색 bg-canvas 작은 카드에 순서(2 / 6)와 설명 한 줄. 영상이 바뀌면 글자도 페이드로 바뀐다 [사실: 사용자 말, 2026-11-04]
    키보드 일시정지, 화살표, 띠 칸은 button이고 포커스 링을 유지한다. Enter와 Space로 누른다. 포커스가 히어로 안에 있으면 왼쪽·오른쪽 방향키로 이전·다음 영상으로 간다
    터치 일시정지, 화살표, 띠 칸의 누르는 영역은 56px. 영상을 좌우로 쓸어도 이전·다음으로 간다. 세로 스크롤을 막지 않게 가로 이동이 더 클 때만 넘긴다
    움직임 줄이기 / 데이터 절약 prefers-reduced-motion: reduce 또는 Save-Data면 영상을 받지 않는다. KEY-BLDG 한 장을 보이고, 화살표나 띠 칸을 누르면 해당 포스터로 바뀐다(160ms 페이드). 확대와 자동 넘김, 일시정지 버튼은 없고, 띠는 차오르지 않고 지금 칸만 표시한다
    재생 실패 포스터를 그대로 두고 일시정지 버튼과 띠는 숨긴다. 화살표는 포스터를 바꾼다. 오류 문구는 보이지 않는다 [가설]

  • 상호작용: 주 버튼 → LND-10 이동 후 첫 입력 포커스. 전화 → 데모에서는 걸지 않고, 가상 번호라 연결되지 않는다는 뜻의 안내를 보인다 [NEED: 카피 C-05] [가설: 02-000-0000이 실제 번호로 걸리는 것을 막음].

  • 데스크톱(1024px 이상): 영상이 가로 전체, 높이 clamp(420px, 100svh - 230px, 600px), 가운데 기준으로 자른다. 제목만 영상에 겹친다: 영상 왼쪽 아래 종이색 칸에 제목을 두고(그림자 없음), 부제, 주 버튼, 전화는 영상 바로 아래에 둔다. 멈추기와 AI 표기는 제목 칸 위, 현재 영상 설명은 오른쪽 아래, 띠는 제목 칸 오른쪽이다 [사실: 새 캔버스 메인 보드, evenstay/design/canvas-notes.md].

  • 모바일(640px 아래): 390폭 첫 화면에서 스크롤 없이 주 버튼이 보여야 한다 [사실: 아트보드 검수, 사용자 "다른건 다 추천으로 해", 2026-11-04]. 순서는 영상 → 제목 → 주 버튼 → 부제 → 전화이고, 모바일에서는 제목도 영상 아래다. 영상은 4:5로 가운데 자르되 높이는 화면의 절반(50svh)을 넘지 않는다. 현재 영상 설명은 영상 오른쪽 위, 멈추기와 AI 표기는 영상 왼쪽 아래, 띠는 영상 맨 아래다 [사실: 새 캔버스 메인 보드, evenstay/design/canvas-notes.md]. 640~1023px도 같은 순서이고 영상은 16:9다. 그래서 IMG-H는 인물을 가운데 1/3에 두도록 만든다(asset-plan.md).

  • 접근성: 영상 영역은 section + 이름([NEED: 카피 C-05]). 영상은 aria-hidden이고 현재 영상 설명이 뜻을 전한다. 설명은 화살표를 눌렀을 때만 읽어 주고 자동 넘김 때는 읽지 않는다. 화살표의 접근성 이름은 카피 C-05 "이전 영상", "다음 영상"을 쓴다. 띠 칸은 현재 영상 설명을 이름으로 쓰고 지금 칸에 aria-current를 둔다. 5초 넘게 움직이므로 일시정지 필수(WCAG 2.2.2). 제목 칸 대비 AA 이상(본문 AAA 목표). 깜빡임 없음(3회/초 미만, WCAG 2.3.1).

  • 애니메이션 의도: 첫 화면 글자는 페이지 열 때 한 번 나타남(이동 8px 이하). 교차 전환은 차분하게, 장면이 "넘어간다"기보다 "바뀐다". 확대는 눈에 띄지 않을 만큼만 쓴다. 지속 시간 띠는 선형.

LND-13 도움이 필요하실 때(안심·건강 지원)

LND-10 상담·전화·방문

  • 목적: 다음 걸음을 하나로 모은다. 상담 신청이 주 행동, 전화가 앱 밖 경로, 방문 상담은 상담 방법의 선택지 [가설]. **실제 접수 기능은 [미정]**이고 첫 버전은 보내지 않는 목업이다.

  • 문구 자리: 제목, 안내, 입력 라벨, 동의 문구, 보내기 버튼, 접수 뒤 안내, 데모 안내 [NEED: 카피 C-15]. 동의 문구는 [법률 검토 전 초안] 표시를 단다(코어 copy의 표기 관례).

  • 입력 항목 [가설: 최소 수집]:

    항목 형식 필수
    신청하시는 분 라디오: 본인 / 가족(대신 신청) 예
    성함 글자 예
    연락처 전화번호 예

  • 상태: 입력 중 → 오류(빈 필수 칸: 아이콘 + 글자 + aria-invalid, 칸 바로 아래, 사용자 탓 하지 않음) → 보내는 중(버튼 안 스피너, 움직임 줄이기 대안) → 접수 뒤 안내(목업: 보내지 않았다는 데모 안내를 함께) [가설: DESIGN.md 오류·스피너 규칙].

  • 에셋 자리: Lucide 아이콘(U-08). 오른쪽 칸에 KEY-TONE(16:9, AI 생성 표기 캡션) [사실: 메인 아트보드, 2026-11-04]. 접수 뒤 안내에 MAS-1(두칸, U-07). 말풍선·대사 없음, 장식(alt="").

SITE-SAFE-03 병원에 가셔야 할 때

  • 목적: 병원에 가셔야 할 때 직원이 하는 일과 가족 연락을 미리 안다.
  • 내용 [사실: B prd.md F8·12절, B value-prop 3]: 119 신고는 현장 직원이 한다. 병원으로 모실 때 직원이 급할 때 연락할 분(비상 연락처)에게 순서대로 전화한다. 닿지 않으면 문자로 알리고 다시 전화할 일을 남긴다(P1, B F18). 한 일은 기록되고, 회원님이 건강 소식을 보여 주기로 한 가족은 Evenstay 패밀리에서 본다. 비상 연락처 전화는 건강 소식 동의와 따로다.
  • 병원 동행 기록 [사실: B prd.md F21, P1]: 병원으로 모실 때 동행한 직원(없을 수 있음)과 출발 시각을 남기고, 돌아오신 시각을 덧붙인다. 돌아오심을 기록하기 전까지 교대 뒤에도 직원 화면에 남는다. 병원 이름·진료 내용은 받지 않는다. 사이트는 "직원이 동행한다"고 약속하지 않고 기록이 이어진다는 것만 쓴다(동행 여부는 U-17). 미리 잡은 병원 외래 동행은 생활 요청의 "병원 동행"이다 [사실: N1 prd.md 1절]. 이것도 운영 확인 전까지 사이트에 쓰지 않는다(카피 정한 것 6).
