1. 너스콜·비상호출 벤더와 외부 인터페이스

Takeaway

[추정] 국내 너스콜 시장은 코맥스 같은 월패드 제조사와 다수의 중소 전문업체가 나눠 갖고 있는 것으로 보인다. 공개 자료에서는 벤더 쪽 외부 연동 사양(RS-485, TCP/IP, 접점, API)이 하나도 확인되지 않았다. 확인된 것은 "PC 화면에 호출 위치 표시" 수준의 자체 소프트웨어와 유선 서브스테이션 구성뿐이다.

Cited Findings

  • [사실] 코맥스 공식 사이트 제품 메뉴에 'Nurse Call', 'Wall Pad/Video Phone', 'IoT Device', 디지털 도어락, 로비폰 등이 따로 나열돼 있다. 같은 페이지에 API 언급은 없다. — COMMAX, 접근 2026-11-04, 직접(요약기를 거친 본문)
  • [사실] 코맥스는 'A.I. Open Collaboration'과 '개방형 클라우드 플랫폼'을 내세우지만 이는 홍보 문구이고(회사 주장), 구체적 API·SDK 문서는 이 페이지에 없다. — COMMAX, 접근 2026-11-04, 직접
  • [사실] 코맥스 JNS 계열 간호호출은 마스터 스테이션 1대가 서브 스테이션을 최대 32개까지 맡고, 서브 스테이션은 공통선 4가닥으로 연결되며, 병실 서브에 재실 스위치 1개·비상 스위치 2개·복도등 1개가 붙는 구성으로 소개된다. 매뉴얼 연도는 확인하지 못했다. — manualmachine JNS-4CM 등 검색결과, 접근 2026-11-04, 검색요약(원문은 403으로 못 엶)
  • [사실] 코맥스 구형 자료(약 2007년으로 요약됨)에는 IP 전화 연동과 호출 시 환자 정보 표시가 나오지만 현행 모델 사양과 같은지는 확인되지 않았다. — 위와 같은 검색결과, 검색요약
  • [사실] 씨스콜(SYSCALL, (주)엔티티웍스)의 너스콜 소프트웨어는 병실·응급실·수술실·화장실 호출 시 PC 화면에 위치와 내용을 표시하고 백업 기능과 맞춤 제작을 제공한다고 소개된다. 페이지에 외부 시스템 연동, LAN/RS-485 같은 통신 방식 언급은 없다. — 엔티티웍스 영상자료실, 접근 2026-11-04, 직접(회사 주장)
  • [사실] 큐필드(㈜)는 자사 카카오 채널 게시물에서 RF 무선·네트워크·DID·Wi-Fi 방식의 너스콜을 개발·납품한다고 밝히고, 병원 요청에 맞춰 수신기(D104CL) 표시 문구를 바꾼 사례를 올렸다. 연동 사양은 없다. — 큐필드 카카오채널 게시물, 접근 2026-11-04, 검색요약(회사 주장)
  • [사실] 메디전자(㈜)는 Daum 카페 게시글에서 신축병원 너스콜 수신기·무선 수신기·복도등 시공 사례를 올렸다. 게시 시기는 확인하지 못했고 오래된 글로 보인다. — Daum 카페 게시글, 접근 2026-11-04, 검색요약
  • [미확인] jungangsmc.com 제품 페이지(JNS-4CM 주수신기, JNS-36/24/12 콘솔 등)는 TLS 인증서 오류로 열지 못했다. 모델명이 코맥스 JNS 계열과 같아 코맥스 제품의 유통·OEM 관계일 가능성이 있으나 확인되지 않았다. — jungangsmc, 검색요약
  • [주의] nursecall.co.kr(검색에서 '일진메가텍 너스콜 전문업체'로 나온 도메인)은 2026-11-04에 열어 보니 너스콜 내용이 아니라 도박성 사이트였다. 도메인이 넘어간 것으로 보이며 이 벤더 정보는 근거로 쓰지 않는다. — nursecall.co.kr, 접근 2026-11-04, 직접
  • [사실] 해외 비교: 허니웰 systevo의 IP 모듈, Zettler/Tyco Medicall 800의 TCP/IP 게이트웨이 보드처럼 해외 대형 너스콜은 IP 연동 모듈을 제품으로 따로 판다. 국내 벤더 사례는 못 찾았다. — Honeywell systevo SEM-IP, BEC Zettler TCP/IP gateway, 접근 2026-11-04, 검색요약(제품 제목 수준)
  • [사실] 국내 너스콜 제조사 목록을 시장보고서(giikorea 등)에서는 얻지 못했다. 보고서에 나오는 업체는 해외(Ascom, Rauland, Honeywell 등)다. — GII Korea 보고서 목록, 접근 2026-11-04, 검색요약

Inferences

  • [추정] 국내 호출 시스템 다수는 폐쇄형 유선 버스(서브 4선 공통선 구성)와 자체 수신반·PC 표시기로 끝나는 구조라, 외부 시스템이 받을 수 있는 출구는 수신반의 접점 출력이나 제조사 맞춤 개발일 가능성이 높다. 근거가 되는 공개 사양은 없어 [가설]에 가깝다.
  • [가설] 해외처럼 IP 게이트웨이 모듈을 파는 국내 벤더가 있을 수 있으나 이번 조사에서는 못 찾았다.

Gaps

  • 코콤·현대HT(현대통신)·삼성SDS·유비벨록스의 너스콜/비상호출 제품 자체를 못 찾았다(제품 카탈로그 PDF를 열지 못함).
  • RS-485·TCP/IP·접점·HL7 출력 여부를 밝힌 국내 벤더 자료는 없었다.
  • 노인복지주택·요양시설의 호출설비 설치 의무를 규정한 법령 조문을 확인하지 못했다(노인복지법 시행규칙 별표를 검색 결과로만 짚었다).

2. 월패드·홈네트워크

Takeaway

[사실] 국내 공동주택 홈네트워크는 고시로 세대단말기-홈게이트웨이-단지네트워크장비-단지서버 구조가 정의되고, 2022년 이후 단지망과 세대망 분리 및 보안 요건이 붙었다. 외부 앱 연동은 월패드 제조사가 창구를 열어줘야 가능한 구조로 보이며, 제조사 공개 API는 못 찾았다. 외부 연동은 대기업 플랫폼(LG 씽큐, 삼성 스마트싱스·홈닉)과의 제휴 방식으로만 보인다.

Cited Findings

  • [사실] 고시 「지능형 홈네트워크 설비 설치 및 기술기준」의 한 판본(과기정통부고시 제2020-24호, 2020-06-15 일부개정, 시행 2021-01-01)을 열람했다. 세대단말기(제7조)는 세대 내 기기와 단지서버 간 연동 기능을 갖추도록 하고, 단지서버(제9조)는 집중구내통신실 또는 방재실에 두며, 홈게이트웨이(제6조)는 단지서버와 연동한다. 이 판본에는 방범·비상 기능을 항목별로 나열한 조문이 없고, 제14조의2(보안)와 망 분리 조항도 없다. — ulex 고시 사본, 접근 2026-11-04, 직접(제3자 사본, 아래 개정 이후 판본이 아님)
  • [사실] 과기정통부·국토부·산업부가 2021-12-31 이 고시를 개정했고 2022-07-01부터 시행되며, 시행 이후 주택건설사업 승인을 받는 공동주택부터 적용된다. 주요 내용은 세대별 망의 물리적·논리적 분리, 기밀성·인증·접근통제 등 보안요구사항 충족 장비, 정보보호 인증 기기 권고, 고시 제14조의2 제2항(구성장비 보안 요건)이다. — 뉴시스 2022-07-31, 보안뉴스 2022, 접근 2026-11-04, 검색요약(제3자 보도)
  • [사실] 2022-07 보도에 따르면 KISA '홈네트워크 보안 가이드'는 장비를 홈게이트웨이·세대단말기·단지네트워크장비·단지서버로 나눴고, 업계가 홈게이트웨이 정의와 VPN 위주 서술을 문제 삼았으며, KISA는 연말 최종본을 내겠다고 했다. 최종본 내용은 확인하지 못했다. — 뉴시스 2022-07-31, 검색요약(제3자 보도)
  • [사실] 2024년 KISA가 전국 단지를 방문해 홈네트워크 장비 보안점검을 했다는 보도가 있다(요약에는 204개 단지라고 나옴). 기축 아파트는 고시 적용 대상이 아니어서 자율점검 사업을 벌였다. — 바이라인네트워크 2024-05-28, 접근 2026-11-04, 검색요약
  • [사실] 용인시는 2019-12 자체 심의기준에 단지망·세대망 분리 조항을 먼저 넣었다. — 스마트시티코리아, 접근 2026-11-04, 검색요약
  • [사실] LG전자는 현대HT, 코콤, 코맥스, HDC랩스, 경동나비엔 등과 월패드-씽큐 연결을 넓혀 왔고 올해 1분기 적용 30만 가구를 넘겼다고 보도됐다. 삼성 스마트싱스는 2022-10 기준 18개 건설사 112개 단지로 확대됐다. — 세계일보 20260817, 삼성뉴스룸, 접근 2026-11-04, 검색요약
  • [사실] 삼성물산 '홈닉' 앱(2024-07-09 발표)은 Matter 기반으로 브랜드가 다른 기기를 한 앱에서 제어하고, 아카라라이프(Matter 인증 스마트 허브 등 공급)와 업무협약을 맺었으며, 발표 시점 16개 단지에 적용됐다. 기사는 월패드와의 연동을 설명하지 않고 허브 방식과 대비한다. — 아시아경제 영문판 2024-07-09, 접근 2026-11-04, 직접
  • [사실] 사용자 포럼에는 "월패드 제조사가 연동 창구를 열어야 스마트싱스 연동이 되고, 개방 여부는 제조사가 정한다"는 글이 있다. 개인 의견이다. — 삼성 커뮤니티, 접근 2026-11-04, 검색요약(제3자 의견)
  • [사실] 스마트홈산업협회는 2022 고시 개정 때 세대별 망 분리 의무화가 과하다는 입장이었다고 보도됐다. 협회가 공개한 외부 연동 표준 API는 못 찾았다. — 뉴시스, 검색요약
  • [사실] TTA가 제안한 RS-485 유선 기반 피제어 홈기기용 통신 프로토콜이 KS 표준화를 추진 중이라는 2014년경 논문 서술이 있다. 이 표준이 KS X 4506인지는 확인하지 못했다. — KoreaScience 논문, 접근 2026-11-04, 검색요약(URL 대응은 추정, 약 12년 된 자료)

Inferences

  • [추정] 월패드 앱 연동은 "월패드 제조사 ↔ 대기업 플랫폼" 쌍방 제휴로 이뤄지고, 제3자 소프트웨어가 쓸 수 있는 공개 API는 없는 구조로 보인다. 다만 이번에 제조사 개발자 포털을 직접 못 확인해서 "없다"고 단정하지는 못한다.
  • [추정] 단지망-세대망 분리와 보안 요건 때문에, 시니어 레지던스 PMS 클라우드가 월패드/단지서버에 직접 붙는 설계는 규제·보안 협의 부담이 크다. 신규 시니어 하우징이 공동주택 고시 적용 대상인지(노인복지주택 해당 여부)는 확인하지 못했다.
  • [가설] 월패드의 세대 내 비상호출은 단지서버/경비실로 가는 폐쇄 경로이고, PMS가 필요로 하면 단지서버 쪽 접점이나 제조사 맞춤 연동을 거쳐야 할 것이다.

Gaps

3. 출입통제 (슈프리마, 보안업체, 호텔 도어록·PMS)

Takeaway

[사실] 공식 문서로 확인된 유일한 국내 벤더 연동 면은 슈프리마 BioStar의 서버 단위 REST API다. 이벤트 조회는 POST로 당겨오는 방식이고, 실시간은 WebSocket 샘플이 있다. 웹훅(서버가 외부로 푸시)은 문서에서 찾지 못했다. 호텔 도어록은 해외(VingCard VConnect)가 중간 허브로 PMS와 잇는 구조가 확인되지만, 국내 도어록·객실제어 벤더의 인터페이스 사양은 못 찾았다.

Cited Findings

  • [사실] BioStar 2 API는 서버 단위 RESTful API로, 서버에서 데이터를 조회하고 사용자 생성, 출입그룹·시간 스케줄 같은 제어 속성을 다룬다. Swagger UI로 문서가 제공된다. — 슈프리마 웨비나 소개 문서, 수정 2021-12-08, 접근 2026-11-04, 직접

Inferences

  • [추정] PMS가 BioStar 이벤트를 받으려면 (a) 같은 현장에 둔 어댑터가 events/search를 주기 조회하거나 (b) WebSocket 샘플 방식으로 구독하는 두 가지가 공식적으로 보이는 길이다. 슈프리마가 PMS 쪽으로 서명된 웹훅을 쏘는 방식은 문서로 확인되지 않는다.
  • [추정] 이 구조에서는 "서명"의 주체가 벤더가 아니라 어댑터(현장 게이트웨이 또는 PMS 수집기)가 되어야 한다.
  • [가설] 호텔형 인터페이스(PMS→키 발급)는 PMS가 주도하는 방향이고, 반대로 도어 이벤트를 PMS가 받는 방향은 도어록 벤더 맞춤 협의가 필요할 가능성이 있다.

Gaps

  • BioStar 웹훅 부재의 직접 확인(전체 API 레퍼런스 열람)을 못 했다. Swagger 문서를 내려받아 확인해야 한다.
  • 국내 호텔 도어록 제조사와 PMS 간 실제 인터페이스 사양, RCU 벤더 목록을 못 찾았다.

가정 판정

  • [추정] "벤더가 서명된 웹훅을 보낸다"는 가정은 국내 공개 자료로는 뒷받침되지 않는다. 가장 근접한 공식 문서(슈프리마)도 조회(REST)와 WebSocket 샘플이며, 푸시 웹훅은 없다. 나머지 설비는 공개 연동 면 자체를 못 찾았다.
  • [추정] 현실에 가까운 설계는 현장 어댑터(게이트웨이)가 접점·RS-485·REST 조회·WebSocket을 정규화된 이벤트로 바꾸고, PMS 쪽 규격으로 서명해 올리는 구조다. 벤더가 서명한다는 가정 대신 "어댑터가 서명하고, 벤더별 연동은 계약·맞춤 개발 가능성으로 표시"하는 편이 안전하다.
  • [가설] 포트폴리오 문서에는 "벤더 웹훅"을 확정 사실처럼 쓰지 말고, "벤더 연동 면 미공개(확인 필요)"라고 명시하는 쪽이 사실 근거에 맞다.
