한 줄 요약

시니어 레지던스 회원이 큰 버튼이나 말로 계약·청구 날짜와 청구서 금액의 이유를 묻고, 비서가 코어 기록에서 읽은 사실만 "확인한 곳"과 함께 답하는 AI 비서. 판단이 필요한 일은 회원이 [네, 전해 주세요]를 누른 뒤에만 직원에게 넘기고, 모든 도구 호출이 남는다. LLM은 의도를 고르는 라우터로만 쓰고, 답 문장은 서버가 답 틀에 도구 결과를 채워 만든다.

대상

  • 묻는 사람: 회원(입주자). P1: 대리인(코어 Representative, 범위 안에서만)
  • 넘겨받는 사람: 프런트·생활지원 직원(직원 화면 "AI 생활 비서")
  • 청구 문의를 받는 사람: 사업장 경리(코어 화면, P1)
  • 점검하는 사람: 사업장 책임자, 본사 운영 매니저

핵심 흐름 (MVP)

  1. 묻고 답 받기: D 고지 v2 확인(서버 게이트) → 큰 버튼(일정 조회, 청구 설명, LLM 없음) 또는 말로 묻기(규칙 → LLM/녹화 라우터) → 도구 등록부가 대상 회원 고정·코어 권한 검사·호출·기록 → 답 틀(답 → 사실 세 줄 이내 → 확인한 곳 → 버튼)
  2. 넘기기: 민감 의도(건강·금전·계약)나 도구 밖 → 확인 화면(전할 말 원문) → 확인 토큰 → 넘김 NEW → 직원 처리 시작·완료(메모 필수) → 감사. 도구 밖·직접 요청은 N1이 있으면 생활 요청으로 보내고 FORWARDED
  • 도구: 코어 도구 3개 core.keyDates, core.explainInvoice(P0), core.createInquiry(P1, 코어 F15) + 비서 자체 assistant.handoff(P0)
  • "이번 달 청구서" = 가장 최근 발행(ISSUED) 청구서. 형식 오류 = UNCLEAR, LLM 오류 = "AI 답 만들기 실패"
  • 보여 준 조회 1건마다 코어 감사 READ 1줄(코어 확인할 것 14)
  • 데모 7단계와 시드: prd.md 9절(2027-01-05, 이은숙 12월 청구서 2,910,000원)
