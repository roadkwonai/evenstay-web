이 파일은 다섯 가지를 정한다. 1절 모듈 이름(직원 화면, 회원·보호자 화면), 2절 프로그램과 회차, 3절 신청과 출석, 4절 공용 시설 예약, 5절 공지. 브랜드(Evenstay, Evenstay 홈, Evenstay 패밀리, Evenstay 홈 비서)는 이미 확정이라 다시 고르지 않았다 [사실: 코어 names v4]. 맨 끝 "정한 것"에 사용자 결정 다섯 개를 적었다(사용자 "모두 추천대로" 2026-11-04).

라벨을 고른 기준

  1. 다른 모듈과 같은 결. 직원 화면 모듈 이름은 한글 업무 명사다: 안심 알림, 보호자 포털·동의, AI 생활 비서, 생활 지원 단계, 생활 요청 [사실: 코어 names v3 변경, N1 names 1절].
  2. 소개 사이트와 같은 말. /life는 "여가 프로그램"이라 부르고 수채화, 가벼운 체조, 텃밭 가꾸기를 예로 든다 [사실: SITE-LIFE-03, 프로그램 이름은 그 문서에서 [가설]]. 앱에서도 "프로그램"과 같은 프로그램 이름을 쓴다.
  3. 평가하지 않는다. 출석, 신청, 공지 확인 라벨이 회원의 성향이나 상태를 말하지 않는다. 고립, 참여율, 활동량, 적극적, 결석, 불참, 노쇼, 미확인자는 쓰지 않는다. "미확인"은 문서의 근거 태그와 헷갈려 화면에 쓰지 않고 "확인 전"으로 쓴다.
  4. 재촉하지 않는다. "마감 임박", "인기", "놓치지 마세요"를 쓰지 않는다. 남은 자리와 대기 순서를 숫자로만 보인다.
  5. 직원 화면에서 "회원"을 쓰지 않는다 [사실: 코어 Glossary 규칙]. 회원 화면은 해요체 문장, 직원 화면은 짧은 명사. 외래어(커뮤니티, 클래스, 슬롯, 웨이팅, RSVP)는 코드와 면접 자료에서만 쓴다.

  • "오지 않음"은 회원에게 알리지 않고 보호자에게도 보이지 않는다. "결석", "불참", "노쇼"는 쓰지 않는다.

4-1. 데모 시설 (모두 [가설: 기획 시드에서 확정])

  • 이용 규칙은 사업장이 정한다. 위 내용은 자리표시다 [NEED: 사업장 이용 규칙].
  • 프로그램 회차(수채화, 1층 모임방 목 오후 2시~3시 30분)도 같은 방 일정을 쓴다. 그 시간에는 예약이 들어가지 않는다.

4-2. 예약 상태 (FacilityReservation)

CANCELLED (입주자) 취소 · 입주자 예약을 취소하셨어요. 누가 취소했는지 남긴다 —

BLOCKED (직원이 막은 시간) 이용 안 함 · 이유 이 시간에는 쓸 수 없어요. 점검·청소 시간 사용 불가
  • 회원이 오지 않은 예약을 기록하지 않는다(노쇼 기록 없음).
  • 겹침 오류 문구는 copy.md 7절이다. 다른 선택지(비어 있는 시간)를 항상 같이 보인다.

5-1. 공지 종류와 상태

5-2. 대상 (Audience)

전체 · A동 · B동 · 층(예: A동 2층). 회원 화면에는 대상을 보이지 않는다. 보호자에게도 보이기는 공지마다 직원이 고르고, 기본값은 끔이다(사용자 "모두 추천대로" 2026-11-04).

5-3. 확인 (NoticeAck, 중요 공지만)

코드 직원 화면 회원 화면 고른 이유 버린 후보
ACKED 확인함 · 09:30 읽었어요. (버튼을 누른 뒤 "읽으셨어요. 11월 18일 오전 9시 30분") 회원이 한 일을 그대로 동의(내용에 동의한 것처럼 읽힘), 알겠어요(이해까지 약속)
PENDING 확인 전 [읽었어요] 버튼 탓하지 않는 말 미확인, 미열람
DELIVERED_IN_PERSON 직접 전함 · 최민수 · 전화 최민수 직원이 전화로 전해 드렸어요. 앱을 쓰지 않는 회원도 빠지지 않게. 전한 직원과 방법을 남긴다 대면 확인
  • 회원 버튼은 읽었어요 하나다. 누르지 않아도 불이익이 없다. "확인 전" 목록은 직원이 직접 전하려는 것이고, 회원을 평가하는 데 쓰지 않는다.
  • 회원이 공지를 열어 본 기록(열람)은 직원 화면에 보이지 않는다 [가설: 열람 기록을 남길지 기획에서].

정한 것 (2026-11-04, 사용자 "모두 추천대로")

번호 정한 것 결정 고르지 않은 안
1 모듈 이름 직원 화면 프로그램·시설·공지, 회원 화면 이름 셋(프로그램, 시설 예약, 공지). 세 이름은 첫 화면 묶음 타일 아래 묶음 화면(COM-09)에 있다(결정 14) 직원 화면 "여가·공지"(짧지만 시설 예약이 이름에서 빠짐)
2 보호자가 일정을 보는 길 D 허락 항목 일정의 설명에 "신청하신 프로그램"을 더한다. 허락 항목은 다섯 개 그대로(허브 결정 2026-11-04). 대기 중인 신청과 시설 예약은 보이지 않는다. D 문서 반영은 D 몫이다 새 허락 항목 "프로그램"(여섯째 항목. 허브 결정 "다섯 개"와 어긋남)
3 대기에서 올라가는 방식 취소가 생기면 대기 첫 번째를 바로 신청으로 올리고 문자로 알린다. 마감 뒤에 생긴 자리는 올리지 않고 직원이 대기 순서대로 전화한다. 마감 시각(전날 오후 6시)은 [가설] 자리가 났다고 알리고 회원이 [신청하기]를 다시 누른 사람 순서(회원이 문자를 못 보면 자리를 놓친다)
4 비용이 드는 프로그램 이번 버전은 무료 프로그램만 다룬다. 재료비와 코어 청구 연결은 다음 버전(청구 연결 데모는 N1 세탁이 이미 보인다) 재료비 칸과 신청 때 비용 안내, 참여 확인 때 코어 청구 항목 생성
5 공지를 보호자에게 보일지 공지마다 직원이 "보호자에게도 보이기"를 고르고 기본값은 끔. 보호자 첫 화면 레지던스 공지에만 보이며 허락 항목과 묶지 않는다(회원 개인 기록이 아니어서) 보호자에게 공지를 보이지 않음
