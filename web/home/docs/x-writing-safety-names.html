이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

모듈 이름은 이미 확정됐다(senior-lab/03-copywriting/ideas/pms-core-billing/names.md v3): 직원 화면과 회원 화면 모두 안심 알림(직원 화면 이름은 Evenstay Safety에서 2026-11-03 한글로 바꿈). 보호자에게 가는 결과는 Evenstay 패밀리의 건강 소식으로 들어간다(D와 맞춤, 2026-11-03). 그래서 product-name 스킬은 쓰지 않았다. 이 파일은 화면 안의 작은 라벨(알림 등급, 상태, 결과 선택지)만 정한다.

라벨을 고른 기준

  1. 판단하지 않는다. 등급 이름이 입주자의 상태를 말하면 안 된다("응급", "위험", "낙상"). 등급은 "직원이 얼마나 빨리 봐야 하는지"만 말한다.
  2. 직원 화면은 짧은 업무 명사(코어와 같은 합쇼체·명사형 라벨). 회원·보호자 화면은 해요체 문장.
  3. 외래어는 직원 화면에서도 줄인다. "에스컬레이션"은 코드와 면접 자료에서만 쓴다.
  4. 코어 용어집과 겹치는 말(입주자, 사업장, 변경 이력)은 코어 표기를 그대로 쓴다. 직원 화면에서는 "입주자"로 부르고("302호 김○○ 입주자") "회원"을 쓰지 않는다. 회원 본인에게는 "회원님", 보호자 알림에서는 "○○○ 회원님"이다(2026-11-03 확정).

1. 알림 등급 (Severity)

규칙이 붙이는 등급이다. 입주자의 상태를 판단한 결과가 아니다.

코드 직원 화면 색·모양 알림 방식 고른 이유 버린 후보
IMMEDIATE 즉시 확인 진한 빨강 + 원 안 느낌표 아이콘 당번 휴대폰 알림, 5분 타이머 시작 해야 할 행동만 말한다 응급(판단), 위험(판단), 긴급(공포감), 1등급(뜻이 안 보임)
CHECK 확인 필요 주황 + 삼각형 당번 알림, 15분 타이머 [가설: 기획 제안값, 2026-11-03 사용자 확정] 즉시 확인과 한눈에 구분되면서 가볍다 주의(입주자 상태처럼 읽힘), 경고
LOG_ONLY 기록만 회색, 아이콘 없음 알림 없이 목록에만 남음 알림 홍수를 줄이는 등급이라는 것이 이름에 드러난다 참고(무엇을 하라는지 모호), 정보
  • 색만으로 구분하지 않는다. 아이콘과 글자를 같이 둔다(색각 이상, 야간 화면 밝기).
  • 회원·보호자 화면에는 등급을 보이지 않는다. 회원에게 "즉시 확인"은 불안만 키운다.

2. 알림 상태 (AlertStatus)

코드 직원 화면 회원 화면 고른 이유 버린 후보
OPEN 접수 직원에게 알렸어요 신호가 들어와 담당자에게 간 상태. 짧고 익숙하다 신규, 미처리(탓하는 느낌)
ACKNOWLEDGED 확인 중 · 담당자 이름 직원이 가고 있어요 누군가 맡았다는 것을 이름과 함께 보인다 처리 중(범위가 넓음), 수락
ESCALATED 2차 호출 · 3차 호출 · 모두 호출 다른 직원에게도 알렸어요 몇 번째 사람에게 넘어갔는지가 숫자로 보인다. 3차 뒤에는 당번 모두를 부른다는 것이 말 그대로 보인다. 응답하지 않은 직원을 탓하지 않는다 에스컬레이션(외래어), 미응답(탓함), 상향(뜻이 흐림)
RESOLVED 조치 완료 직원이 다녀갔어요 직원이 조치를 기록해야만 이 상태가 된다 해결(결과를 단정), 종료, 이상 없음(결과는 상태가 아니라 조치 기록에 둔다)
  • 2차 호출 뒤 누가 확인하면 상태는 다시 확인 중이 되고, 넘긴 이력은 기록에 남는다.
  • 회원 화면의 "직원이 가고 있어요"는 직원이 [확인하러 갑니다]를 누른 뒤에만 보인다. 누르기 전에는 "직원에게 알렸어요"다. 지키지 못할 말을 먼저 하지 않는다.
  • 3차 호출 대상은 당번표 셋째 자리의 당직 책임자(없으면 사업장 책임자)다. 3차도 확인하지 않으면 모두 호출: 오늘 밤 당번 모두에게 다시 알리고, 누가 맡을 때까지 같은 간격으로 다시 알린다 [가설: 기획 제안값, 2026-11-03 사용자 확정]. 시스템은 119에 신고하지 않는다.

3. 신호 처리 표시

코드 직원 화면 고른 이유
DuplicateEvent 중복 수신 n건 같은 이벤트가 다시 왔다는 사실만 말한다. "오류"가 아니다
RelatedSignals 같은 입주자 신호 n건 같은 입주자에게서 30분 안에 다른 신호가 오면 한 카드 아래 묶어 보인다 [미정: 묶는 시간 범위]
DeviceSilent 신호 끊김 기기에서 정해진 시간 동안 아무 신호가 없을 때. "이상 없음"으로 보이지 않게 따로 표시한다

코드 직원 화면 회원 화면
BED_SENSOR 침대 센서 침대 센서 (처음 한 번 "침대에 계신지 알려 주는 장치"로 풀어 쓴다)
CALL_BELL 호출벨 호출벨
ACCESS_LOG 출입 기록 출입 기록
CHECK_IN_CALL 안부 전화(외부) 안부 전화
FRONT_CALL 프런트 전화 (표시 안 함, 회원 화면은 호출 상태만)
VISIT 안부 방문 안부 방문
REQUESTS (생활 요청에서 옮긴 호출) 생활 요청에서 옮김 (표시 안 함, 회원 화면은 호출 상태만)

5. 조치 기록 선택지 (ActionRecord)

직원이 한 일만 고른다. 입주자의 진단명이나 상태 판단은 선택지에 두지 않는다.

만남

  • 입주자를 만났습니다
  • 아직 만나지 못했습니다 (찾는 중)

한 일 (여러 개 선택)

  • 이상 없음을 직접 확인
  • 직원이 도와 드림
  • 간호 담당에게 연락
  • 119에 신고함
  • 병원으로 가심
  • 비상 연락처에 전화함
  • 기기 점검 요청

보호자 알림 (조치 완료 직전)

  • 보내기
  • 올리지 않기: 이유는 두 가지만 고른다(직접 적기 없음). 운영 매니저가 매주 확인한다.
    • ① 입주자(또는 대리인)가 이번 일은 알리지 말아 달라고 함: 들은 직원과 시각 필수, 입주자 화면에 표시
    • ② 건강과 무관한 신호: 다른 입주자의 신호가 잘못 붙음 · 같은 일이 이미 올라감 · 기기 시험
    • 119 신고나 병원 이송이 기록된 일은 ①만 고를 수 있다.
  • 건강 소식을 보여 주기로 한 보호자가 없으면 직원이 고르기 전에 자동으로 보내지 않고 기록한다(copy.md 2-8).

6. 보호자 알림 머리말

  • 문자·알림톡 첫 줄: [Evenstay 패밀리]
  • 이유: 보호자가 같은 회원의 소식을 두 이름으로 받지 않게 한다(D와 통일, 2026-11-03). 사칭 문자와 구분하는 것은 링크와 내용을 넣지 않고 프런트 번호를 적는 방식으로 한다(보이스피싱 P-039).

바뀔 수 있는 것 [미정]

  • 등급별 넘김 시간: 즉시 확인 5분, 확인 필요 15분으로 정했다 [가설: 기획 제안값, 2026-11-03 사용자 확정]. 현장 검토로 바뀔 수 있다.
  • 같은 입주자 신호를 묶는 시간 범위(30분은 임시값).
