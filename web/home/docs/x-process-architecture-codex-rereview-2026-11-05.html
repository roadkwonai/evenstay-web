기준과 사용자 지시

사용자 지시: “보완할 내용은 다시한번 검토해서 반영해줘”, “아키텍처 도식화스킬들도 모두 설치해서 진행해야해 환경확인하고 보완할 내용도 다시 한번 검토해줘”.

기준 문서는 architecture-codex-2026-11-05.md와 아키텍처 설계안이다. 원래 검토는 수정 전 문서의 해시와 행 번호를 가진 과거 기록으로 보존한다. 보완 전 공개 상태는 v0.1.0으로 기록하고 보완분은 v0.1.1에 넣는다. 기존 승인 표시를 보완분 승인으로 바꾸지 않는다. [사실]

재검토 결과

초기 제안 전부를 그대로 반영하지 않는다. 기존 정본 API 조회·업무별 멱등·모듈별 처리 완료 표가 해결하는 일에는 새 공통 테이블이나 전역 버전 필드를 더하지 않는다. [가설]

항목 재검토 판정 반영 범위
Next.js 보안 특정 새 버전으로 단순 치환하지 않는다 도입 시 공식 공지를 확인한 지원 패치 고정, 민감 응답 공유 캐시 제외, 다중 인스턴스 배포·캐시 규칙
공유 철회 원본 파기와 분리한다 해당 보호자 조회·예정 발송·캐시 차단. 모델 투입 철회와 보존 만료의 처리는 목적별로 구분
RLS 기존 운영사 격리 결정을 구체화한다 운영사·허용 사업장·주체 문맥과 문맥 누락 거부, API·작업자·연결 풀 시험
늦은 신호 오래됐다는 이유로 종료했다고 보지 않는다 현장 종료·진행·확인 전 상태를 대사. 벤더 규격은 미정 유지
사업장 반복 작업 범용 실행 결과 테이블은 추가하지 않는다 한 사업장 실패 후 나머지 계속 처리, 실패한 사업장만 재시도, 기존 업무 명령 멱등
자동이체 최신 코어의 잠금·늦은 결과·예외 처리를 중복 작성하지 않는다 확인할 것 32를 닫거나 CMS를 비활성화하는 운영 전환 조건과 상태 조합 시험
이벤트 순서 모든 이벤트의 aggregate_version을 강제하지 않는다 정본 재조회 유지. 상태 스냅샷의 기존 revision과 소비자별 재시도 시험
RDS 견적 엔진 지원과 주문 가능한 조합을 구분한다 서울·엔진·클래스·스토리지·Multi-AZ 주문 옵션 확인 뒤 비용 재산정. 기존 계산값은 미검증 전제로 유지
오프라인 사본 새로운 민감정보 수집을 추가하지 않는다 수집 설계가 없는 알레르기 제외. 기존 최소 항목, 생성 시각·만료·열람 범위·복구 후 파기
문서 일치 최신 0~5단계와 모듈 소유권을 기준으로 맞춘다 개관·공통 지침·모듈 원본과 사본·웹 문장·도식 원본·생성 웹 동기화

위 표는 설계 변경의 범위이며 실제 운영 기능을 구현했다는 뜻이 아니다. [사실]

스킬과 환경

  • 검토 스킬: 00-hub/.agents/skills/architecture-patterns, pre-mortem.
  • 도식 스킬: evenstay/.agents/skills/archify, stack-diagram, diagram-design. 기존 설치본을 프로젝트 범위에 복사하고 파일별 SHA-256과 출처를 기록했다.
  • Node 26.13.0, Python 3.15.2, Chrome 156.0.8078.81, 로컬 Pretendard를 확인했다. 도식 빌드는 전역 Claude 스킬 경로 대신 프로젝트 로컬 스킬을 사용한다.
  • Archify 설치본은 3.0.1이며 업데이트 알림은 3.2.0을 가리켰다. 이번 작업에서는 업데이트하지 않았다.
  • diagram-design 자체 검사에는 로컬 글꼴 CSS URL을 외부 URL과 구분하지 못하는 기존 제한이 있다. 이를 통과로 기록하지 않고, 프로젝트가 요구한 로컬 Pretendard를 유지한 채 브라우저 렌더와 넘침 검사로 보완한다.
