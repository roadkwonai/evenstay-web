한 줄 요약

시니어 레지던스의 침대 센서, 호출벨, 출입 기록(안부 전화는 P1) 신호를 한곳에 모아 당번 직원에게 알리고, 5분 동안 아무도 확인하지 않으면 다음 담당자에게 넘기며, 누가 언제 무엇을 했는지 남기는 모듈. 시스템은 판단하지 않는다. 결과는 회원이 허락한 보호자에게 D(Evenstay 패밀리)의 "건강 소식"으로 올라간다.

대상

  • 주 이용자: 야간 직원(당번·2차), 사업장 책임자(3차, 기록 검토)
  • 결과를 보는 사람: 보호자(D 화면, 회원이 건강 소식을 허락한 경우만)
  • 신호의 당사자: 회원(안심 알림 화면은 P1). 도움은 호출벨이나 방 전화로 부르고, 앱은 부른 뒤 보는 곳

핵심 흐름 (MVP)

  1. 신호 → 사람: 수신 어댑터가 올린 신호 받기(원본 먼저 보관, 데모는 형식 시뮬레이션) → 어댑터 정규화 → (출처, 업체 이벤트 번호) 중복 확인 → 입주자 찾기 → 규칙·등급(즉시 확인 / 확인 필요 / 기록만) → 당번 알림 → 넘김(5분/15분, 1차 → 2차 → 3차 → 모두 호출) → [확인하러 갑니다] → 조치 기록
  2. 결과: 보호자 알림 미리보기(D viewersOf로 볼 보호자, 이름은 코어 GuardianQuery.guardiansOf, 문자 시각은 D nextSendAt) → [보내기]면 조치 완료 + 아웃박스 → D HealthFeedCommand.post(볼 보호자 0명이어도 올림) / [올리지 않기]는 회원 요청(MEMBER_REQUEST) 또는 건강 소식이 아님(NOT_A_HEALTH_EVENT)만 → D withhold. 직원 재량 버튼은 없다. 119·병원 이송 때는 맡은 직원이 코어 비상 연락처(EmergencyContactQuery, actor 전달)를 열어 전화하고 통화 결과를 남긴다
  • 데모 5단계와 시드: prd.md 9절. 통합 데모 주인공 A동 201호 이은숙(2026-11-10 승계 뒤, 데모는 2026-11-12 새벽), 딸 김지민(건강 소식 보호자, 비상 연락처 1순위), 대리인 아들 김태호(청구서·결제), 당번 김하진 · 2차 박서준 · 3차 최영미(SITE_MANAGER)

화면 목록

prd.md 8절. P0: 지금 처리할 신호, 알림 상세, 조치 기록, 보호자 알림 미리보기, 알림 기록, 시뮬레이터 + 직원 휴대폰 패널, (D 의존) 건강 소식 목업. P0 확장: 알림 기록의 걸린 시간(F20), 첫 화면의 야간 당번 보기 한 줄(F24). P1: 기기 상태, 회원 안심 알림, 기기 연결·장치 동의, 규칙·당번표 설정, 안부 방문 기록(화면 ID 제안 SAF-12), 병원 동행 칸, 부재 중 표시. 새 문구는 반영됨(copy.md 2-1, 2-4, 2-7, 2-12, 2-13, 2-15~2-17, 4-2). 문구는 B copy.md. 2026-11-04 P1: 병원에 가신 분(SAF-13), 부재 중인 입주자(SAF-14), 호실 현황판(SAF-15 제안), 사고·학대 보고(SAF-16 제안), 비상 때 재실 명단(SAF-17 제안). 모든 화면을 클릭형 프로토타입으로 만든다(MVP 구현 없음).

데이터 모델 초안

tech-design.md 2절(엔티티, ERD), 3절(상태 전이), 4절(규칙·넘김). 모든 테이블은 safety 스키마, 코어 엔티티는 ID만. 핵심 결정:

ADR 결정
S1 수신 원본 먼저 보관 → 정규화. 신호는 (source, vendor_event_id) 유일. 다시 오면 중복 수신 기록만
S2 넘김 escalation_due_at + 상주 작업자. 전이는 조건부 갱신이라 중복 실행·동시 확인에도 한 번. 데모 시계와 함께 동작
S3 보호자 문장 B가 쓰고 D post에 요약·본문을 담아 올린다. D가 보인 그대로 스냅샷 저장, 동의 검사는 D(D 안 채택). 의존은 B → family/api 한 방향
S4 비상 연락처 복사하지 않고 볼 때마다 코어 EmergencyContactQuery. 통화 기록은 순위만
S5 묶음 같은 입주자 신호는 화면에서만 30분 창으로 묶음. 알림·타이머는 각자 [가설]
S6 확장 사업장마다 규칙·당번표·기기(site_id + 코어 RLS). 새 업체 = 어댑터 1개, 새 자산 유형 = 신호 종류와 규칙 조합
S7 장기 부재 B에 복사하지 않고 신호를 평가할 때마다 코어 AbsenceQuery.absenceOf로 읽는다. 코어 이벤트는 구독하지 않는다(모듈 경계 8번)
  • P1 추가 엔티티: VisitPlan·VisitRecord(안부 방문), HospitalEscort(병원 동행). 장기 부재는 저장하지 않고 코어 AbsenceQuery로 읽는다(ADR-S7). 사업장 단위 조회는 safety/api SafetyBoardQuery.boardOf(siteId, at, actor)이고 대시보드(app/ D1)가 읽기만 한다. 2026-11-04: IncidentReport(사고·학대 보고), EvacuationAssist·EvacuationRoll·EvacuationCheck·EvacuationCheckCorrection(비상 때 재실 명단, 대피 확인 정정은 추가만). 생활 요청에서 옮긴 호출은 safety/api SafetyFrontCallCommand.registerFromRequest. 소유주 월 요약은 SafetyBoardQuery.monthOf(행동 safety.owner_report.view, 그달 숫자만).
