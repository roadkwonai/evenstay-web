표기 규칙은 strategy.md와 같다. 시기는 날짜가 아니라 단계다. 포트폴리오 기준의 "확인 방법"은 데모와 테스트로 확인할 수 있는 것만 쓴다. 실서비스 효과는 [가설]이고 목표 수치를 정하지 않는다.

전략 맥락

  • B는 코어 다음 첫 모듈이다(A → B → D → G → C) [사실, 2026-11-02 확정]. 그래서 B의 첫 결과는 "모듈이 코어 경계를 지키며 붙는다"는 증명이기도 하다.
  • 순서 원칙: (1) 데모 5단계에 필요한 이벤트 처리 → (2) 보호자 출구(D)와 비서(G)가 기다리는 것 → (3) 현장 근거가 생긴 뒤 실서비스에 가까워지는 것.
  • 핵심 가정: 현장에서 신호가 흩어져 놓친다(H1). 인터뷰에서 사례가 없으면 Next의 "교대 인계 요약"을 앞당기고 새 신호 종류 추가는 미룬다(shortlist B 전환 기준).

Now — MVP (2~4주, 코어 위)

기능(출력) 결과 문장 확인 방법
신호 수신, 어댑터 3종, 원본 보관, 중복 확인, 늦은 신호 정렬, 시뮬레이터 (F1, F2, F10) 운영사가 기기 업체를 바꾸거나 늘려도 직원 화면과 기록을 그대로 쓰게 해서, 출입통제·IoT 연동 비용이 기기 단위가 아니라 어댑터 단위로 늘어난다 [가설] 중복·순서 테스트(KR2), 데모 1·2단계
규칙·등급, 당번표, 넘김 타이머 (F3, F4, F5) 야간 직원이 바로 받지 못한 알림도 정해진 시간 안에 다른 사람이 맡게 해서, 아무도 맡지 않은 알림이 남지 않는다 타이머 테스트(KR2), 데모 3단계
확인과 조치 기록, 알림 기록, 같은 입주자 묶음 (F6, F9, F11) 사업장 책임자가 밤사이 누가 무엇을 했는지 시간 순서로 설명하게 해서, 야간 대응 책임이 기록으로 분명해진다(P-010) 데모 4단계·부록, 동시 확인 테스트
보호자 알림 미리보기, 건강 소식 올리기·정해진 이유로 올리지 않기(D family/api 목업 먼저), 비상 연락처 보기 (F7, F8, F12) 보호자가 회원이 허락한 범위에서만 무슨 일이 있었는지 사실 그대로 보게 해서, 결과 공유가 동의와 기록 위에서만 일어난다 데모 5단계, 동의 없는 보호자 403 테스트
판단 단어 금지어 검사 (KR3) 직원과 면접관이 "시스템은 판단하지 않는다"를 모든 화면에서 같은 말로 보게 해서, 오탐 때 책임이 사람과 기록에 분명히 남는다 CI 금지어 검사
신호 끊김 (F13, P1 1순위) 야간 직원이 신호가 없는 것을 "이상 없음"으로 착각하지 않게 해서, 기기 쪽 공백이 숨지 않는다 데모 부록(시뮬레이터로 기기 멈춤)
회원 안심 알림, 규칙·당번표 설정, 안부 전화, 기기 연결·장치 동의, 전화 호출, 닿지 않음 문자 (F14~F19, P1) 회원이 앱을 쓰지 않아도 호출벨이나 방 전화로 도움을 부르고 무엇이 모이는지 미리 알게 해서, 센서 도입이 감시가 아니라 동의한 서비스가 된다 [가설] 회원 화면 접근성 점검, 동의 없는 기기 신호는 입주자와 연결되지 않는 테스트
확인·만남까지 걸린 시간 표시, 야간 당번 보기 한 줄 (F20, F24, P0 확장) 책임자가 늦은 알림을 다음 날 찾고, 야간 직원이 근무를 시작할 때 할 일을 한 줄로 보게 해서, "즉시 확인"이 지켜졌는지 기록으로 말할 수 있다 걸린 시간이 알림 기록 시각과 같다. 효과 수치로 주장하지 않는다
병원 동행 기록, 안부 방문 기록, 장기 부재 구독, 사업장 단위 조회 SafetyBoardQuery (F21, F22, F23, F25, P1) 아무 신호도 없는 분도 하루 한 번 사람이 챙기고, 병원에 가신 분을 교대 뒤에도 놓치지 않게 해서, 신호가 와야만 움직이는 구조의 빈 곳을 메운다 놓친 방문이 기존 규칙·넘김으로 알림이 된다. 부재 중에는 침대 센서 알림이 없다(코어 AbsenceQuery로 읽음)
생활 요청에서 옮긴 호출(registerFromRequest), 첫 화면 P1 줄과 목록, 호실 현황판, 사고·학대 보고, 비상 때 재실 명단 (F17, F29, F26, F27, F28, P1. 2026-11-04 보완) 직원이 생활 요청에 섞인 일을 같은 카드로 받고, 책임자가 오늘 챙기지 못한 분과 비상 때 확인할 분을 빠뜨리지 않게 해서, 사람이 한 일이 판정 없이 기록으로 남는다 통합 데모 장면 B-1~B-3과 부록에서 화면이 흐름대로 움직인다. 보고에 판정 칸이 없다. 명단이 출입 신호를 쓰지 않는다

Next — 안심 알림 v1.1 (D·G가 붙는 동안, 각 1~2주)

기능(출력) 결과 문장 기다리는 곳 확인 방법
D 실연동: family/api 목업을 D 실구현(viewersOf, post, withhold, HealthEventWithheld)으로 바꾸기. 같은 계약 테스트를 그대로 통과 보호자가 건강 소식 한 곳에서 B 결과와 다른 건강 기록을 함께 보게 해서, 보호자 쪽 창구가 하나로 남는다 D 기획·개발 D 데모에서 B 결과가 건강 소식에 같은 문장으로 나온다
확인 중 오래 머문 알림 표시(30분 [가설]) 맡은 뒤 조치 기록이 빠진 알림을 책임자가 그 밤 안에 보게 해서, "가고 있어요"라는 회원 화면 약속과 실제가 어긋나지 않는다 — 시뮬레이션: 맡고 기록하지 않은 알림이 책임자 화면에 뜬다
G 비서 도구: 내 호출 상태 조회, 오늘 직원이 다녀간 기록 조회(읽기만) 회원이 말로 "직원이 오고 있나요?"를 물어도 같은 상태를 듣게 해서, 공고의 AI Agent 연동을 안전 영역에서 판단 없이 보여 준다 G G 평가 세트에서 답이 회원 화면 상태와 같다. 건강 판단 질문은 직원에게 넘긴다
교대 인계 요약(밤 → 아침) 아침 근무자가 밤사이 알림·조치를 한 장으로 받게 해서, 인계에서 끊기는 기록이 줄어든다 [가설] H1 결과 인계 요약이 알림 기록과 같은 건수
알림 수 시뮬레이션 비교(H3) 운영사가 신호를 모아도 직원 알림이 늘지 않는지 숫자로 보게 해서, 알림 피로 걱정에 답한다 — 가상 하룻밤 신호 묶음: 기기별 방식 vs 기록만·중복 제거 적용 알림 수
떠남·돌아옴만 보내는 침대 센서용 미복귀 타이머 업체가 계산해 주지 않는 기기도 같은 규칙을 쓰게 해서, 기기 선택 폭이 넓어진다 실제 기기 사양 [NEED] 같은 시나리오가 두 기기 형식에서 같은 알림을 낸다
사업장 대응 절차 연결 직원이 알림 상세에서 사업장이 정한 대응 절차를 바로 열게 해서, 시스템이 처치를 안내하지 않으면서 현장을 돕는다 사업장 문서 문서를 열기만 하고 내용을 만들지 않는다
협력 의료기관 연락처 직원이 비상 연락처 옆에서 사업장 공용 연락처를 찾게 해서, 연락 순서가 짧아진다 운영 전제 [미정] 협력 기관이 있는 사업장에서만 보인다

Later — 실서비스에 가까워지기

기능(출력) 결과 문장 전제 확인 방법
실제 기기·출입통제·안부 전화 업체 연동, 직원 푸시·문자 업체 현장이 시뮬레이터 대신 실제 신호로 같은 화면을 쓰게 해서, 운영사가 시범 사업장 1곳에서 효과를 측정할 수 있다 업체 선정, 비용(범위 밖), [법률 검토] 수집 근거 시범 사업장의 알림 → 확인 시간 기록
C 연계: 일정 기간의 안전 기록을 생활 지원 단계 검토 자료로 제공(요약만, 판정 없음) 생활 지원 단계 검토 때 직원이 기억이 아닌 기록을 함께 보게 해서, 단계 결정이 근거를 가진다 C 기획, 낙인·오용 방지 설계(C 윤리 ★) C가 B 원문 대신 요약 API만 쓴다
임대주택 설비·출입 알림 임대주택 관리 직원도 같은 허브로 설비 신호를 받게 해서, B가 자산 유형을 넘어 쓰인다 [가설, assumptions B 전략 "중"] 임대 시나리오 1개 사업장 2에 규칙 2개로 데모
여러 사업장 공용 본사 야간 당직 야간 인원이 적은 사업장도 3차 담당을 본사 당직으로 채우게 해서, 3차 자리가 비지 않는다 본사 당직 체계 [미확인] 사업장 2곳이 한 3차 당직을 공유

확인할 것

결정됨 [가설] (2026-11-03 사용자 결정: 문서의 제안값으로 확정하고 [가설]로 표시)

  1. D 실연동 시점 [가설]: Now는 family/api 목업으로 끝내고, D 개발이 끝나면 Next에서 실구현으로 바꾼다. B를 D 일정에 묶지 않는다. 같은 계약 테스트를 목업과 실구현 양쪽에서 돌린다. 버린 대안: D와 동시에 개발하며 처음부터 실연동.
  2. G 도구의 범위 [가설]: 읽기 2개(내 호출 상태, 오늘 다녀간 기록)만 둔다. 호출을 대신 만드는 쓰기 도구는 두지 않고, 회원이 말로 부르면 비서가 호출벨·프런트 전화를 안내한다. 버린 대안: 비서가 "직원 불러 줘"에 호출을 만든다(음성 오인식이 즉시 확인 알림이 될 위험).

남은 것 3. [NEED] H1 결과에 따른 순서 조정: 종사자 인터뷰에서 놓친 사례가 없으면 Next의 교대 인계 요약을 Now 뒤로 앞당긴다(strategy.md 확인할 것 1·3).
