이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

꼭 지킬 규칙

  • 동의의 주인은 회원이다. 보호자는 회원 화면에서 "함께 보실 분", 기본값은 "안 보여요".
  • 권한은 코어 authorize()에 확장 정책으로 "허용"만 더한다. 매 요청 다시 계산하고, 거부 응답은 하나로 둔다. 보호자 화면은 못 보는 이유를 구분하지 않는다(ADR-F2).
  • 넓힘과 좁힘은 다르게 다룬다. 직원이 대신 넓히면 회원 확인 뒤 적용, 좁히면 즉시 적용(ADR-F3).
  • 동의 항목은 생활 소식, 일정(코어 keyDates 6개만), 청구서, 건강 소식(민감정보 별도 동의, 동의한 날부터). B·C는 HealthFeedCommand.post로 올리고, 빼는 경우는 MEMBER_REQUEST·NOT_A_HEALTH_EVENT 두 가지뿐이다(ADR-F4).
  • 보호자 문자는 머리말 [Evenstay 패밀리], 내용·"건강"이라는 말·링크 없음. 조용한 시간 22~08시 [가설].
  • AI 고지 원본은 D가 관리한다(purpose LIFE_REPORT·ASSISTANT). G는 ASSISTANT 고지 확인 전에는 비서를 열지 않는다.
  • 다른 모듈은 core/api로만 쓴다. 스키마는 family만 쓴다.

하지 않을 것

  • 진단명·진료 결과·처방 공유, 병원·의료기관 연동
  • 보호자가 범위를 요청하는 기능, 다른 보호자의 범위 보기, 못 보는 이유 구분 표시
  • 센서·호출 신호의 실시간 보호자 보기(감시)
  • 직원 재량으로 건강 소식 빼기(이유 코드 2가지만, 119·병원 이송 기록은 회원 요청으로만)
  • 일정의 병원 일정, MVP 면회 예약
  • 금전 대행·자산 조회·금융상품 권유, 보호자 대신 결제
  • AI가 건강 소식을 쓰거나 판단하기, 직원 확인 없는 AI 글 발송
  • 비상 연락처 전화(B·코어 몫), 실제 문자·본인 확인 연동(MVP는 로그·목업)
