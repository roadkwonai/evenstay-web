한 줄 요약

여가 프로그램의 회차를 만들고 신청·대기·출석을 받으며, 공용 방의 예약 시간이 프로그램·다른 예약·막은 시간과 겹치지 않게 나누고, 사업장 공지가 대상 호실에 닿았는지([읽었어요] 또는 직원의 직접 전함) 남기는 모듈. 회원 앱, 프런트 대신 신청, 직원 대신 신청이 같은 정원과 같은 대기 순서를 쓰고, 마감 전 취소는 대기 맨 앞을 자동으로 신청으로 올린다. 이번 버전은 무료 프로그램만.

대상

  • 주 이용자: 생활 지원 직원(프로그램 등록, 명단, 출석), 프런트 직원(대신 신청·예약·취소, 직접 전함)
  • 함께 쓰는 사람: 사업장 책임자(공지, 확인 현황, 공용 시설 설정, 운영 현황 칸)
  • 결과를 보는 사람: 회원(Evenstay 홈 묶음 화면 COM-09의 버튼 "프로그램", "시설 예약", "공지"), 보호자(Evenstay 패밀리 일정 안 "신청하신 프로그램"(회원이 "일정"을 허락한 경우)과 첫 화면 "레지던스 공지"(직원이 고른 공지))

핵심 흐름 (MVP)

  1. P0 자리: 회차(4주 앞 생성) → 신청(회차 행 잠금. 정원이 차면 회원은 [기다리기]를 골라 대기, 직원 대신 신청은 바로 대기. 대기가 있으면 빈자리는 승급으로만) → 마감 전 취소면 같은 트랜잭션에서 대기 맨 앞 승급 + 문자 / 마감(전날 18:00 [가설]) 뒤 취소면 승급 없이 진행 직원 알림 → 직원이 맨 앞에 [신청으로 올리기] → 출석(온 분만 저장).
  2. P0 방: 회차·회원 예약·막은 시간이 한 테이블(PlaceBooking)에 있고 PostgreSQL 배제 제약이 겹침을 거부 → 같은 방 그날 빈 시간을 함께 돌려줌.
  3. P0 공지: 쓰기(대상 전체·동, 중요 공지, 문자 함께, 보호자에게도 보이기 기본 끔) → 게시 때 대상 입주자 고정 → [읽었어요] / [직접 전함] → 확인 현황.
  • P1: 보호자 일정·레지던스 공지·생활 소식 출석 재료(D), 운영 현황 카드 후보(코어), 장기 부재 반영(승급 건너뜀, 명단 표시), 프로그램·회차 바꾸기·쉬기, 예약 바꾸기·시간 막기, 공용 시설 설정, 예약 게시, 층 대상, 나머지 문자·직원 알림.
  • 데모와 시드: prd.md 9절. N1 장면(11/17) 뒤 시드 초기화 없이 시계만 2026-11-18 08:50으로 옮겨 장면 M0~M11을 이어 붙인다. N2 시드는 통합 데모를 시작할 때 COM-03 "기본" 초기화 한 번으로 community/seed base()가 넣고(시드 행은 기준 시각으로 보임), 그 뒤 데모 중에는 다시 초기화하지 않는다(prd.md 9절 "시드 출처"). 장면만 따로 할 때는 AFTER_SUCCESSION(= base()와 같은 내용)에서 같은 시각으로. 주인공 이은숙의 공지 확인 → 수채화 대기 → 프런트 대신 예약(겹침) → 박영순 대신 취소로 자동 승급 → 김지민 일정 → 확인 현황·직접 전함 → 11/19 수채화 출석. 수채화 시드 정원은 4(거주 입주자 7명).

ADR 결정
M1 한 방 한 일정 회차·예약·막은 시간을 PlaceBooking 한 테이블에, EXCLUDE USING gist (place_id WITH =, period WITH &&) WHERE active
M2 정원은 행 잠금 회차 행 FOR UPDATE, 순서 = (queued_at, seq)
M3 승급은 마감 전 자동 자리를 낸 트랜잭션 안에서 대기 맨 앞 승급 + 문자 아웃박스. 마감 뒤는 직원 전화
M4 출석은 온 분만 ATTENDED·WALK_IN 행만, 오지 않음 행·입주자별 합계 조회 없음
M5 공지 대상 고정 게시 때 NoticeRecipient(ID만), 확인은 ACKED·DELIVERED_IN_PERSON 두 길, 열람 기록 없음
M6 보호자 조회 일정 community.enrollment.view_as_guardian(D가 SCHEDULE 허락으로 엶)과 공지 community.notice.view_as_guardian(D가 보호자 관계만으로 엶) 모두 D 동의 행동으로 선언
M7 부재는 읽기만 AbsenceQuery.absenceOf를 승급·표시 때 읽음, 구독·자동 취소 없음
M8 회차 상태 계산 저장은 ACTIVE·CANCELLED, 나머지는 시계·숫자로 계산
M9 무료만 코어 청구·시스템 주체 없음
M10 사업장별 기능 community_features(공지, 프로그램, 시설). 새봄은 셋 다, 다온하우스는 공지만 [가설]

하지 않을 것

  • 프로그램 효과 주장, 참여 인원·참여율 홍보, 추천, 권유·전날 안내 문자
  • 출석으로 입주자 평가·순위·신청 제한, 입주자별 참여 횟수·비율 계산, 출석을 안심 알림·생활 지원 단계 신호로 보내기
  • "오지 않음"을 회원·보호자에게 보이거나 알리기, 오지 않은 예약 기록
  • 비용이 드는 프로그램, 재료비, 코어 청구 연결(다음 버전), 강사 관리, 외부 회원 모집
  • 건강 상태를 짐작하게 하는 프로그램(재활, 치료, 인지 훈련)
  • 보호자의 신청·예약, 보호자에게 직접 문자(D가 보낸다), 보호자 허락 저장(D)
  • 공지 열람 추적, 열람을 확인으로 치기
  • 시설 관리 전체(정기 청소·점검은 N1)
  • 다른 모듈 데이터 복사(입주자·호실·직원·부재를 저장하지 않고 매번 읽음)
