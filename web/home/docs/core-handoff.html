한 줄 요약

소유주가 다른 시니어 레지던스와 임대주택의 입주 계약과 월 청구를 한 기준으로 처리하고, 바뀐 모든 것을 이력으로 남기는 PMS 코어. 모든 모듈(safety, family, assistant, transitions, leasing)이 이 코어의 도메인 모델과 권한 검사를 쓴다.

대상

  • 주 이용자: 본사 운영 매니저, 사업장 경리
  • 함께 쓰는 사람: 사업장 직원(프런트), 소유주(읽기 전용)
  • 청구서를 보는 사람: 회원(입주자), 대리인(후견인·위임). 보호자 화면은 family 모듈이 연다

핵심 흐름 (MVP)

  1. 계약: 작성(비상 연락처 포함) → 체결(입주 예정) → 입주(거주 중) → 사별 승계(옛 계약 승계됨 + 새 계약). 퇴거 접수 → 단순 정산은 P1
  2. 청구: 결식 기록(직원 대행·CSV) → 식사 마감 → 월 청구 생성(멱등) → 근거 확인 → 발행(불변) → 회원 청구서(쉬운 말, 인쇄)
  • 청구 규칙은 3개: 정기 요금, 식비, 결식 감면. 일할 없음: 입주 월 1개월분, 승계는 다음 달 1일부터, 퇴거는 그 달 말일까지. 요금표는 체결 때 버전으로 고정
  • 데모 5단계와 시드 데이터: prd.md 9절
  1. 장기 부재(P1, 2026-11-03): 부재 시작(이유·종류 없음) → 이벤트로 D, 신호 평가 때 조회로 B → 예정 복귀일 지남 확인할 일 → 복귀 기록. 부재 끼니 감면은 요금표 설정(기본 끔, [미정])
  2. 운영 현황 카드(P1, 2026-11-03): 사업장 책임자용. app/이 코어와 모듈 api/를 매 요청 읽어 조립하고 저장하지 않는다
  3. 서비스 사용 기록(P1, 2026-11-04): N1 확인 → ServiceChargeCommand.record(멱등) → 다음 청구서 SERVICE_FEE 항목
  4. 소유주 월 리포트, 보증금 보호 상태, 위탁 운영 계약 이력(P1, 2026-11-04)
  • 통합 데모는 시드 초기화 없이 시계만 옮겨 이어 간다(2026-11-04). 코어 장면은 prd.md 9절 "통합 데모에 넣는 코어 장면"
