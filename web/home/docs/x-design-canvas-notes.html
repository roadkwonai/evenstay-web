문구 대조 방법

copy.md 전체와 대조하면 "교정 기록" 표에 남은 옛 문구까지 맞는 것으로 나온다. design/site/src/copycheck.py는 0절과 1절의 표만 본다. 문구를 맞출 때는 이 스크립트를 쓴다. recopy.py는 copy.md 표의 현재 값을 build.py에 넣는다(옛 문구를 찾는 짝이라 다음 교정 때는 옛 값을 갱신해 쓴다). capfit.mjs는 히어로 설명 칸을 폭마다 잰다.

9쪽과 스크롤 모션 (새 캔버스 Version 12)

  • 문구: 화면 문장은 모두 design/site/src/strings/<페이지>.json(공통 common.json)에 있다. build.py·pages.py는 T(키)만 쓰고 copy.md와 asset-plan을 빌드 때 읽지 않는다. copy.md가 바뀌면 JSON 값을 고치고 check_strings.py를 돌린다. recopy.py는 더 쓰지 않는다.

  • 일반 페이지: build_static.py가 보드를 design/prototype/site/의 정적 페이지 11개로 바꾼다. 동작은 static-site.js이고 build.py의 LOGIC을 옮긴 것이라 둘을 같이 고친다.
  • 생성: design/site/src/pages.py가 strings 값으로 쪽을 만든다. 공통 머리·푸터·전화 안내·로직은 build.py를 쓴다. measure.mjs → layout.py → pages.py → canvas.py 순서다.
