한 줄 요약

입주자, 허락받은 보호자, 프런트 직원, 홈 비서가 올린 생활의 부탁(고장·수리, 청소, 세탁, 외출 차량, 병원 동행, 불편한 점, 그 밖의 일)을 한 요청 모델로 받아 담당 팀에 배정하고, 직원이 마친 뒤 입주자가 확인해야 닫히게 하는 모듈. 7일 동안 확인이 없으면 확인 없이 닫히고, 정기 청소·점검은 사업장 일정에서 회차로 만들며, 비용 있는 요청은 확인 뒤 코어 청구 명령으로 넘긴다. 몸이 불편하다는 요청은 직원이 안심 알림으로 옮긴다.

대상

  • 주 이용자: 프런트 직원(대신 등록, 배정, 분류), 담당 직원(시설, 청소·세탁, 운전, 생활 지원)
  • 함께 쓰는 사람: 사업장 책임자(정기 작업, 종류 설정, 운영 현황), 경리(청구 넘김 실패 확인)
  • 결과를 보는 사람: 회원(Evenstay 홈 "생활 요청"), 보호자(Evenstay 패밀리, 회원이 "생활 요청"을 허락한 경우만)

핵심 흐름 (MVP)

  1. P0 요청 한 건의 수명: 회원 앱 또는 프런트 대신 등록 → RECEIVED → [맡기]·[배정] → [시작] → [완료](한 일 한 줄) → 회원 [다 됐어요] = CONFIRMED / [아직이에요] = IN_PROGRESS + "다시 열림" / 7일 뒤 AUTO_CLOSED. 직원 대신 확인, 시작 전 취소, 기다림(이유 4), 하지 않음(이유 4), 같은 요청과 합치기, P1: [안심 알림으로 옮기기](B 명령 성공 뒤 MOVED_TO_SAFETY, 허브 보완 지시 2026-11-04).
  2. P1 정기 작업과 청구: 그날 0시 회차 생성(빈 호실 제외, 장기 부재면 쉼, 회원 쉬기 신청이면 쉼), 회원 확인 없이 완료, [다시 봐 주세요] → 새 청소 요청. 비용 있는 요청은 CONFIRMED·AUTO_CLOSED 때 아웃박스로 코어 ServiceChargeCommand.record.
  • P1 나머지: 병원 동행(가실 곳 제한 정보), 보호자 보기·대신 올리기(D), 홈 비서 넘김 받기(G), 운영 현황 openCount, 문자·직원 알림, 종류 설정, 말로 하기.
  • 데모와 시드: prd.md 9절. 통합 데모 10단계(11/12) 뒤 [시드 초기화] 없이 시계만 2026-11-17 08:40으로 옮겨 장면 L0L10을 이어 붙인다(허브 보완 지시 R2). 장면만 따로 할 때는 AFTER_SUCCESSION에서 같은 시각으로 옮긴다. 주인공 A동 201호 이은숙의 수리(전등) → 다시 열림 → 입주자 확인, 프런트 최민수의 세탁 대신 등록, 배경 요청 R-01R-06. 세 상태 모두 유료 요청을 시드에 넣지 않는다(코어 골든 금액 불변).

ADR 결정
R1 상태 + 전이 기록 현재 상태는 행에, 전이마다 RequestTransition 추가 + 코어 AuditLog WRITE
R2 회차는 별도 RecurringOccurrence(예정·처리 중·완료·쉼·못 함), 회원 확인 없음, 다시 봐 주세요는 새 요청
R3 입주자 확인으로 닫힘 DONE은 확인 기다림, 7일 뒤 SYSTEM이 AUTO_CLOSED
R4 청구는 코어 명령 N1은 금액·기간을 정하지 않고 금액을 저장하지 않는다. 확인 뒤 아웃박스로 ServiceChargeCommand.record(요청 ID 멱등, 안내한 요금표 버전)
R5 홈 비서 넘김 일부만 직접 요청(주제 그 밖)·도구 밖 질문만, G가 receiveFromAssistant 호출, 종류는 프런트가 정함
R6 보호자는 D 동의 행동 requests.request.view_as_guardian·create_as_guardian(D가 넣어 둔 이름)을 선언, D 정책이 LIFE_REQUEST 허락으로 연다. 보호자는 취소하지 않는다. 보호자 문자는 D
R7 옮기기는 B 명령 SafetyFrontCallCommand.registerFromRequest, 성공해야 닫힘, 요청 글은 넘기지 않음
R8 팀은 N1 설정 프런트·시설·청소·세탁·운전·생활 지원, 직원은 코어 StaffQuery
R9 기한은 직원 전용 설정 종류 설정 버전, 회원·보호자 DTO에 필드 없음
R10 병원 동행 입력 제한 body·done_note·hold_note null CHECK, 한 일은 선택지, 가실 곳은 별도 테이블·SENSITIVE_READ·30일 뒤 지움 [가설]

하지 않을 것

  • 요청 내용을 읽어 종류·담당·급함을 자동으로 가르기(AI, 낱말 규칙), 자동으로 안심 알림 옮기기
  • 회원·보호자에게 처리 시간 약속, 처리 기한 표시
  • 병원 동행의 진료 과목·증상·진료 내용 받기, 진료 예약, 의료 판단
  • 안전 신호 대신하기(급한 일은 호출벨·프런트·안심 알림)
  • 시설 관리 전체(자산 대장, 법정 점검 서류, 협력 업체 계약·정산)
  • 요금 계산, 코어 청구 항목 직접 쓰기
  • 보호자에게 직접 문자 보내기(D가 보낸다), 보호자 허락 저장(D)
  • 금전 부탁 처리(D), 비서의 건강·금전·계약 판단 넘김 받기(G 화면에 남음)
  • 만족도 점수, 직원 평가, 처리 시간 순위, 효과 수치 주장
  • 다른 모듈 데이터 복사(입주자·직원·부재를 저장하지 않고 매번 읽음)
