이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

이 파일은 세 가지를 정한다. 1절 모듈 이름(직원 화면, 회원·보호자 화면), 2절 요청 종류, 3절 요청 상태, 4절 그 밖의 표시(들어온 곳, 표시 딱지, 정기 작업 상태). 브랜드(Evenstay, Evenstay 홈, Evenstay 패밀리, Evenstay 홈 비서)는 이미 확정이라 다시 고르지 않았다 [사실: 코어 names v4].

라벨을 고른 기준

  1. 다른 모듈과 같은 결. 직원 화면 모듈 이름은 한글 업무 명사다: 안심 알림, 보호자 포털·동의, AI 생활 비서, 생활 지원 단계 [사실: 코어 names v3 변경, 2026-11-03].
  2. 판단하지 않는다. 라벨이 입주자의 상태나 잘잘못을 말하지 않는다. 낙상, 쓰러짐, 응급, 위험, 배회, 미납, 연체, 퇴소, 판정은 쓰지 않는다. 처리하지 않는 요청도 "반려", "처리 불가" 대신 "하지 않음"과 이유로 쓴다.
  3. 안심 알림과 헷갈리지 않는다. "도움", "호출", "부르기"는 안심 알림(B)의 말이다. 생활 요청에는 쓰지 않는다. 급한 일은 생활 요청이 아니다.
  4. 직원 화면에서 "회원"을 쓰지 않는다. "입주자 확인", 들어온 곳 "Evenstay 홈"처럼 쓴다 [사실: 코어 Glossary 규칙].
  5. 회원 화면은 해요체 문장, 직원 화면은 짧은 명사. 외래어(티켓, SLA, 작업 지시)는 코드와 면접 자료에서만 쓴다.

1. 모듈 이름

직원 화면 이름 후보 5개

이름 이유 브랜드 적합성 기억성 상표·도메인

"생활"이 세 모듈(AI 생활 비서, 생활 지원 단계, 생활 요청)에 들어간다. 메뉴에서 헷갈릴 수 있다 [추정]. 메뉴 아이콘을 따로 두어 구분한다. 이름은 "생활 요청"으로 확정했다 (사용자 "추천대로", 2026-11-03).

2. 요청 종류 (RequestType)

회원은 큰 버튼으로 고른다. 버튼마다 그림과 한 줄 풀이를 둔다. 정기 점검은 사업장 일정에서만 생기고 회원이 고르지 않는다.

코드 직원 화면 회원 버튼 회원 버튼 아래 풀이 기본 담당 팀 버린 후보
REPAIR 수리 고장·수리 전등, 수도, 문, 냉난방처럼 고칠 것 시설 하자(계약 말), AS(외래어)
CLEANING 청소 청소 정해진 청소 말고 더 필요하실 때 청소·세탁 하우스키핑(외래어)
LAUNDRY 세탁 세탁 옷과 이불을 맡기실 때 청소·세탁 세탁 대행(직원 화면 청구 항목 이름으로만 씀)
TRANSPORT 외출 차량 외출 차량 장 보기, 은행처럼 나가실 때 타실 차 운전 이동(뜻이 넓음), 셔틀(정기 노선 안내와 헷갈림)
HOSPITAL_ESCORT 병원 동행 병원 동행 병원 가시는 날 직원이 함께 가요. 날짜와 가실 곳만 알려 주세요 생활 지원 진료 동행(진료를 다루는 것처럼 읽힘)
FEEDBACK 의견·불편 불편한 점 소음, 서비스처럼 말씀하고 싶은 것 프런트 민원(관청 말), 불만(감정을 단정)
OTHER 그 밖의 일 그 밖의 일 위에 없는 부탁 프런트 기타(회원 화면에서는 딱딱함. 직원 화면 필터에서만 "기타" 허용)
INSPECTION 점검 (고르지 않음) — 시설 정기 정비(길다)
  • 병원 동행은 날짜, 시각, 가실 곳, 돌아오실 때도 함께 갈지만 받는다. 진료 과목, 증상, 진료 내용은 받지 않는다. 이 종류에는 자유 입력 칸을 두지 않는다 [가설: 기획에서 확정].
  • 데모 사업장이 병원 동행과 세탁 대행을 제공한다는 전제다 [가설]. 국내 시설 중 병원 동행(평창카운티), 주 2회 청소와 세탁 대행(삼성노블카운티)을 제공하는 곳이 있다 [사실: A12 https://www.sidae.com/article/2025032413431314629 2025-03-25, A6 https://www.heraldk.com/article/2026062013480077891 2026-06-20].
  • 기본 담당 팀은 사업장 책임자가 바꿀 수 있다 [가설].

3. 요청 상태 (RequestStatus)

코드 직원 화면 회원 화면 보호자 화면 고른 이유 버린 후보
RECEIVED (담당 없음) 접수 · 배정 전 요청을 받았어요. 요청을 받았어요. 들어왔다는 사실만 말한다 신규, 미처리(탓함)
RECEIVED (담당 있음) 접수 · 담당 한도윤 한도윤 직원이 맡았어요. 한도윤 직원이 맡았어요. 맡은 사람을 이름으로 보인다. 배정은 담당자 칸으로 보인다 배정됨(회원에게 낯선 말)
IN_PROGRESS 처리 중 한도윤 직원이 처리하고 있어요. 처리하고 있어요. 짧고 익숙하다 진행 중(뜻이 흐림)
ON_HOLD 기다림 · 이유 부품을 기다리고 있어요. (이유마다 한 문장) 같음 왜 멈췄는지를 같이 보인다. 기다림 이유: 부품, 외부 업체, 원하시는 날짜, 입주자와 시간 맞추기 보류(관청 말), 지연(탓함)
DONE 완료 · 확인 기다림 직원이 마쳤어요. 확인해 주세요. 직원이 마쳤어요. 회원님 확인을 기다려요. 직원이 "완료"를 눌러도 요청은 아직 닫히지 않는다 해결(결과를 단정)
CONFIRMED 입주자 확인 확인하셨어요. 회원님이 확인하셨어요. 직원 화면에서 "회원"을 쓰지 않는다 회원 확인(직원 화면 규칙 위반), 종료
AUTO_CLOSED 확인 없이 닫힘 7일 동안 확인이 없어 마친 것으로 했어요. 아직 안 됐으면 프런트에 말씀해 주세요. 같음 회원이 확인하지 않아도 목록이 쌓이지 않게 한다 자동 종료
CANCELLED 취소 · 누가 요청을 취소했어요. 요청이 취소됐어요. 누가 취소했는지 직원 화면에 남긴다 철회
DECLINED 하지 않음 · 이유 이 요청은 해 드리기 어려워요. (이유 한 문장 + 다른 길) 같음 이유를 함께 보인다 반려, 처리 불가, 거절
  • 회원이 [아직이에요]를 누르면 상태는 다시 처리 중이 되고 직원 화면에 다시 열림 딱지가 붙는다. 회원 화면은 "다시 봐 달라고 전했어요."다.
  • 확인 없이 닫히는 기간은 7일이다 (사용자 "추천대로", 2026-11-03).
  • 비용이 드는 요청은 입주자 확인 또는 확인 없이 닫힘 때 코어 청구 항목이 된다. [아직이에요] 사이에는 청구되지 않는다 [가설: 기획에서 확정].
  • 처리 기한은 직원 화면에만 있다. 회원·보호자 화면에는 시간 약속을 보이지 않는다.

4-2. 딱지 (직원 화면만)

딱지 뜻 누가 붙이나
먼저 처리 물이 새는 것처럼 기다리면 집이 상하는 일 직원이 고른다. 시스템이 정하지 않는다
기한 지남 사업장이 정한 처리 기한이 지남 시스템(시각만 비교)
다시 열림 입주자가 [아직이에요]를 누름 시스템
비용 있음 사업장 요금표에 금액이 있는 요청 시스템
정기 정기 작업에서 생긴 요청 시스템

"기한 지남"은 요청에만 쓰는 말이다. 돈에 관한 말(미납, 연체)과 섞지 않는다.

4-3. 정기 작업 상태 (RecurringTask 회차)

코드 직원 화면 회원 화면
SCHEDULED 예정 화요일에 청소해요.
IN_PROGRESS 처리 중 지금 청소하고 있어요.
DONE 완료 오늘 청소를 마쳤어요.
SKIPPED 쉼 · 입주자 요청 이번 주 화요일 청소는 쉬어요.
MISSED 못 함 · 이유 오늘 청소를 하지 못했어요. 이유: 방에 안 계셨어요. 다시 할 날은 프런트에서 알려 드려요.
  • 정기 청소는 회차마다 회원 확인을 받지 않는다. 회원 부담을 줄이려는 것이다. 대신 마친 날 [다시 봐 주세요]를 누르면 새 요청(청소)이 생긴다 (사용자 "추천대로", 2026-11-03).
  • "못 함" 이유 선택지: 방에 안 계심 · 회원이 다음에 해 달라고 함 · 담당자 사정. 담당자 사정은 회원 화면에 "직원 사정으로"라고 쓴다.

정한 것 (사용자 "추천대로", 2026-11-03)

  • 모듈 이름: 직원·회원·보호자 화면 모두 "생활 요청".
  • 보호자 허락: D 허락 항목에 "생활 요청"을 더한다(보기 + 대신 올리기, 기본값 "안 보여요"). D 문서 반영은 D 몫이다.
  • 병원 동행: 건강 소식도 허락받은 보호자에게만 보이고, 병원 이름은 빼고 보인다.
  • 확인 없이 닫히는 기간: 7일.
  • 정기 청소 회차: 회원 확인 없이 완료로 닫고 [다시 봐 주세요]만 둔다.
