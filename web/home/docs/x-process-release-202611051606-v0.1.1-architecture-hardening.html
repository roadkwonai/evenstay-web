이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

기록 시각: 2026-11-05 16:06 KST

보호자 공유 철회와 원본 파기를 구분하고, 운영사·사업장 격리와 장애 뒤 신호 처리를 명확히 했다. 문서와 도식 16장, 통합 웹과 공개 문서를 같은 기준으로 맞춘다.

변경 내용

  • 보호자 공유 철회는 해당 보호자의 조회·예정 발송·캐시를 차단한다. 원본 파기는 처리 근거와 보존 정책으로 따로 판단한다. 복원 뒤 철회 재적용이 끝나기 전에는 공유 조회와 관련 발송을 재개하지 않는다.
  • RLS 문맥에 운영사·허용 사업장·주체를 함께 명시한다. 늦은 호출은 현장 종료·진행·확인 전 상태를 대사한다.
  • 한 사업장 실패가 다른 사업장 반복 작업을 중단하지 않도록 한다. 기존 업무별 멱등과 정본 재조회를 사용하며 범용 실행 테이블이나 모든 이벤트의 버전 필드를 새로 요구하지 않는다.
  • CMS의 결과 대기 중 수납·승계 미결정을 닫거나 해당 기능을 끈 뒤 운영 전환 조건을 확인한다.
  • Next.js는 도입 시점의 공식 보안 공지를 확인한 지원 패치를 정확히 고정한다. 회원·보호자·청구·권한 응답은 공유 캐시 제외를 기본으로 둔다.
  • RDS의 서울·엔진·인스턴스·스토리지·Multi-AZ 주문 조합을 확인한 뒤 비용을 재산정하도록 한다. 현재 비용은 기존 전제의 계산값이다.
  • 오프라인 사본은 기존 최소 수집 항목만 담고 생성 시각·만료·열람 범위·복구 후 파기를 정한다. 수집 설계가 없는 알레르기 항목은 뺀다.
  • 개관과 공통 지침의 옛 기술표를 최신 0~5단계 설계와 맞추고 프로젝트 로컬 도식 스킬 3종을 사용한다.

영향과 호환성

문서와 클릭형 프로토타입의 설계 보완 버전이다. 실제 서비스·결제·장비 연동은 구현하지 않는다. 기존 데모 데이터와 화면 흐름은 유지한다. 기존 승인 기록은 보존하며 보완분을 새 승인으로 표시하지 않는다.

검증과 한계

최종 검사 결과와 산출물 해시는 같은 릴리즈의 VERIFICATION.md와 GitHub Release 첨부 체크섬에 남긴다. AWS 주문 가능 조합, 현장 장비 규격과 법률 적용은 실제로 확인한 것이 아니다.
