누르면 용어집의 풀이가 열립니다.

표기 규칙은 strategy.md와 같다. 시기는 날짜가 아니라 단계다. 포트폴리오 기준의 "지표"는 데모와 테스트로 확인할 수 있는 것만 쓴다. 실서비스 지표는 [가설]이고 목표 수치를 정하지 않는다.

전략 맥락

  • 코어는 모든 모듈(B, D, G, C, E)이 같은 입주자·계약·권한을 쓰게 하는 바닥이다 [사실, 2026-11-02 확정]. 그래서 로드맵의 첫 결과는 "모듈이 기댈 수 있는 코어"다.
  • 순서 원칙: (1) 데모 5단계에 필요한 것 → (2) 다음 모듈이 기다리는 것 → (3) 실서비스에 가까워지는 것.
  • 핵심 가정: 3개 규칙 유형으로 시작해도 규칙을 추가하는 구조가 설명된다(H1). 틀리면 Next의 규칙 확장이 앞당겨진다.

Now — MVP (2~4주)

기능(출력) 결과 문장 확인 방법
조직 계층, 역할·범위 권한, 소유주 화면 (F1, F2, F10) 소유주 담당자가 다른 소유주의 데이터를 볼 걱정 없이 자기 사업장 숫자를 직접 확인하게 해서, 운영사가 위탁 계약의 데이터 분리 요구를 설계로 증명한다 격리 테스트 전부 통과(KR3), 데모 5단계
계약 상태 전이와 사별 승계 (F3, F4, F11) 경리가 사별 같은 변화에도 계약·요금·보증금을 한 번에 틀림없이 넘기게 해서, 승계 처리의 실수와 분쟁 소지를 줄인다 [가설] 승계 트랜잭션 테스트, 데모 4단계

대리인 등록·범위 검사 (F13, P1 1순위) 판단이 어려워진 회원의 일을 등록된 대리인만 정해진 범위에서 처리하게 해서, 운영사가 대리 처리의 근거를 남긴다(I-30) 범위 밖 거부 테스트, 데모 부록
조정 전표, 청구 문의, 수납 목업, 퇴거 단순 정산 (F14~F17, P1) 발행된 청구를 지우지 않고 바로잡고, 퇴거 시 반환액을 근거와 함께 확정하게 해서, 정정과 정산이 모두 설명 가능해진다 원장 불변성 테스트
장기 부재 (F18, P1, 2026-11-03) 직원이 입주자가 며칠 없다는 사실을 이유 없이 한 번 적으면 식당·안심 알림·보호자 소식이 같은 기록을 쓰게 해서, 부재 중 잘못된 알림과 "운영 규칙으로 정한다"로 남아 있던 빈칸을 줄인다 [가설] D의 부재 이벤트 구독과 B의 AbsenceQuery.absenceOf 조회 통합 테스트, 예정 복귀일 지남 확인할 일, 데모 부록 2
운영 현황 카드 (F19, P1, 2026-11-03) 사업장 책임자가 아침에 여러 모듈의 지금 상태를 한 화면의 사실 숫자로 보게 해서, 오늘 먼저 챙길 일을 고르고, 모듈 데이터를 복사하지 않는 조립 구조를 화면으로 보여 준다 카드별 모듈 조회 테스트(모듈 없음·권한 없음·실패), 데모 부록 2. 목표값은 두지 않는다
서비스 사용 기록과 청구 (F20, P1, 2026-11-04) 생활 요청에서 회원이 확인한 유료 서비스가 안내한 금액 그대로 다음 청구서에 한 번만 들어가게 해서, 모듈을 붙여도 청구 원장 규칙이 코어 한 곳에 남는다 멱등·넣을 기간·버전 단가 테스트, 통합 데모 11/17
소유주 월 리포트 (F21, P1, 2026-11-04. I-25를 단순형으로 당김) 소유주가 달마다 자기 사업장의 입주·청구·수납과 운영 숫자를 직접 보게 해서, 운영사가 위탁 성과를 숫자로 설명한다 [가설] 소유주 격리 테스트, 통합 데모 12/1
보증금 보호 상태 (F22, P1, 2026-11-04) 회원이 맡긴 보증금이 어떻게 보호되는지 적힌 사실을 직접 보게 해서, 보증금 불안(P-002)에 답할 자리를 만든다 [가설] 데모 부록, 승계 복사 테스트
위탁 운영 계약 이력 (F23, P1, 2026-11-04. Later에서 당김) 본사가 사업장마다 누가 언제부터 위탁 운영하는지 이력을 바로 꺼내게 해서, 개정안의 신고 의무가 확정되면 그 위에 신고 칸만 더한다 기간 겹침 테스트, 데모 부록
