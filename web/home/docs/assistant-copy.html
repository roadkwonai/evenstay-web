1. 포트폴리오 소개 (README, 면접 자료)

제목

Evenstay 홈 비서: 계약과 청구 기록으로만 답하고, 판단은 사람에게 넘기는 AI 비서

부제

회원이 큰 버튼이나 말로 계약 날짜와 이번 달 청구서를 묻습니다. 비서는 코어 PMS의 API 세 개(조회 두 개, 청구 문의 하나)만 도구로 부르고, 모르는 일과 판단이 필요한 일은 회원 확인을 받아 직원에게 넘깁니다.

문제 (한 단락)

시니어 레지던스 회원이 청구서 금액이나 계약 날짜가 궁금하면 프런트에 전화하거나 앱 메뉴를 찾아야 합니다. 만 55세 이상 중 AI 서비스를 써 본 사람은 30.2%로, 일반 국민(59.4%)의 절반 정도입니다. 범용 AI 비서는 회원의 계약과 청구서를 모르고, AI 안부전화는 시설 업무와 이어지지 않습니다. AI가 회원과 직접 이야기하려면 AI 기본법(2026-01-22 시행)에 따라 미리 알려야 하고, 건강·돈·계약 판단을 하지 않도록 막아야 합니다.

근거: G3 2025 디지털정보격차 실태조사(과기정통부·NIA, 2026-03-26 발표. 보도 https://www.mt.co.kr/tech/2026/03/27/2026032710093798860 ), G4 AI 기본법 제31조 사전 고지(로펌 요약 https://shinkim.com/kor/media/newsletter/3114 , 법 원문 대조 안 함 [미확인]), ai-assistant.md 2절(범용 비서·AI 안부전화. E7, E15), G5·G15·G21(판단은 사람에게). 출처 목록: senior-lab/01-research/sources/axis9-senior-ai-assistant.md.

무엇을 만들었나

  1. 조회 도구 두 개, 확인한 곳이 붙는 답 일정 조회는 계약과 청구 날짜를, 청구 설명은 청구서 항목과 그 근거를 읽습니다. 비서는 금액을 계산하지 않고, 답마다 어느 기록에서 확인했는지 붙입니다. 큰 버튼은 AI를 부르지 않고 정해진 답 틀로 답합니다.
  2. 모르면 모른다고 하고, 판단은 사람에게 도구 밖 질문에는 모른다고 답하고 프런트 전화를 보여 줍니다. 건강, 돈, 계약을 정해야 하는 말은 회원에게 한 번 더 묻고 직원에게 넘기며, 넘긴 이유를 남깁니다.
  3. 모든 호출이 남는 기록 직원 화면에서 대화, 도구 호출, 권한 검사 결과, 넘긴 요청을 봅니다. 효과 수치를 주장하지 않고, 넘긴 비율과 권한 거부 건수를 이 기록으로 잽니다.

설계에서 먼저 정한 것 (면접관용)

  • 비서는 새 데이터를 만들지 않는다. 코어 API를 도구로 부르고, 권한은 코어 Authorization이 회원 본인·대리인 범위로 검사한다.
  • 상태를 바꾸는 호출(청구 문의 접수, 직원에게 넘기기)은 회원 확인 토큰이 없으면 서버가 거부한다.
  • 조회 도구 하나 = 회원 화면 큰 버튼 하나 + 답 틀 하나 + 직원 화면 기록 한 줄. 쓰기 도구 하나 = 확인 화면 하나 + 기록 한 줄. B, D, C 모듈이 붙어도 같은 틀이다.
  • AI 사용 고지를 확인하기 전에는 비서를 열지 않는다. 고지 문구와 확인 기록은 D(I-42)가 갖는다.
