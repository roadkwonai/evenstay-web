한 줄 요약

입주자의 건강이 바뀌었을 때 간호·생활지원 직원이 본 일을 기록하고, 그 기록으로 생활 지원 단계 변경을 제안해 회원에게 설명한 뒤, 제안하지 않은 사업장 책임자가 결정하게 하는 모듈. 시스템은 단계를 판정하거나 추천하지 않는다. 단계가 바뀌어도 입주 계약과 청구는 그대로이고(계약 변경 요청 한 줄까지), 보호자에게는 결정된 변경만 D(Evenstay 패밀리)의 "건강 소식"으로 간다.

대상

  • 주 이용자: 간호·생활지원 직원(평가, 제안, 설명, 외부 돌봄), 사업장 책임자(결정)
  • 함께 쓰는 사람: 경리(계약 변경 요청 확인), 프런트(회원 화면을 읽어 드림), 본사 운영 매니저(결정자 대체 [가설])
  • 결과를 보는 사람: 회원("생활 지원 단계" 화면), 보호자(D 건강 소식, 회원이 허락한 경우만)

핵심 흐름 (MVP)

  1. 단계 변경: 평가 기록(일상생활 7항목 × 4선택지 + 본 일, 점수·병명·추천 없음) → 단계 변경 제안(근거 평가 30일 안 [가설], 입주자당 열린 제안 1건) → 입주자 설명·의견 → 결정(제안자 ≠ 결정자, 결정 규칙 표) → 한 트랜잭션으로 단계 구간·서비스 시간·계약 변경 요청(요금 영향이 "계약 변경 필요"면)·건강 소식 아웃박스 → D HealthFeedCommand.post(kind CARE_STAGE_CHANGE [가설]) 또는 회원 요청이면 withhold(MEMBER_REQUEST)
  2. 외부 돌봄 병행: 외부 돌봄 일정 입력 → 입주자 서비스 시간과 겹침 계산(경고, 저장은 막지 않음) → 처리 3종 기록 → 회원 화면
  • 단계는 양쪽으로 바뀐다(기본 서비스로 돌아가기도 같은 흐름).
  • 요금: 단계마다 요금 묶음을 두고 결정 전후 묶음이 다르면(어느 방향이든) 계약 변경 요청. 외부 돌봄 병행·거처 상담은 지금 서비스와 묶음을 이어받는다 [가설].
  • 데모 6단계와 시드: prd.md 9절. 주인공 A동 201호 이은숙(입주 2026-10-01, 11/10 승계), 12/2 입원 → 12/7 퇴원(통합 데모에서는 이 사이에 안심 알림 병원 동행, 코어 장기 부재, 보호자 포털·동의 부재 소식, 12/7 16:40 전후 복귀 기록 장면이 들어가고 C는 12/7 18:00에 시작한다, HUB-A1) → 12/8 평가(박서준·김하진) → 12/9 제안·설명(딸 김지민 전화 동석) → 12/10 결정(최영미) → 2027-01-08 외부 돌봄 입력(김하진), 목욕 도움 화 → 목(화 구간 1/11 닫음, 목 1/14부터) → 01-12 방문요양 시작. 12월 청구서는 2,910,000원 그대로(코어 시드 12/24 사전 결식 3끼, G 2027-01-05 장면과 같음).
