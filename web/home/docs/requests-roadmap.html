이 문서에 나오는 용어

누르면 용어집의 풀이가 열립니다.

표기 규칙은 strategy.md와 같다. 효과 수치를 목표로 쓰지 않는다. 포트폴리오에는 실제 이용자가 없으므로 "결과를 확인할 신호"는 데모·테스트에서 보이는 사실이다. 기간은 상대 기간이다. 날짜를 약속하지 않는다.

전략 맥락

  • 비전: 어떤 길로 말한 부탁이든 맡을 직원에게 닿고, 입주자의 확인까지 기록으로 남는다(strategy.md 1절).
  • 북극성 [가설]: 입주자 확인으로 끝난 요청의 비율. MVP에서는 측정 대상이 없어 계산이 맞는지만 보인다.
  • 순서 원칙: (1) 상태 기계 하나를 먼저 단단하게 → (2) 들어오는 길을 하나씩 더함 → (3) 나가는 길(청구, 대시보드)을 붙임. 다른 모듈 변경이 필요한 결과는 그 모듈이 준비된 순서로 붙인다.

Now — MVP P0 (1~2주, 코어 위)

만들 것 (output) 결과 (outcome) 결과를 확인할 신호
요청 모델·상태 기계·전이 기록(F11), 회원 올리기(F1), 대신 등록(F2) 회원과 프런트가 앱이든 전화든 같은 요청으로 올리게 해서, 부탁이 메모에서 사라지지 않게 한다 두 길에서 들어온 요청이 같은 목록에 들어온 곳과 함께 보인다(통합 장면 L1·L2)
직원 목록(F3), 배정(F4), 처리(F5), 기한(F9) 담당 직원이 오늘 할 일과 기한 지난 일을 한 목록에서 알게 해서, 다시 묻는 일을 줄인다 통합 장면 L3·L5. 기한은 직원 응답에만 있다(KR3 테스트)
입주자 확인·다시 열림·대신 기록(F6), 7일 닫힘(F7), 취소(F8) 입주자가 확인해야 요청이 끝나게 해서, "끝났다"를 직원 혼자 정하지 않게 한다 통합 장면 L4, 전이표 테스트 통과(KR2)
(P1로 옮김, 2026-11-04) 안심 알림으로 옮기기(F10, B 목업 먼저) 몸이 불편하다는 요청이 생활 요청 목록에 묻히지 않게 직원이 바로 안심 알림 당번에게 넘기게 한다 통합 장면 부록. 옮긴 뒤 생활 요청에는 옮긴 기록만

Now — MVP P1 (3~4주, 다른 모듈이 준비된 것부터)

만들 것 결과 결과를 확인할 신호 의존
정기 작업(F12) 책임자가 정한 청소·점검이 회차로 남게 해서, 빠진 회차와 쉰 이유를 나중에 확인할 수 있게 한다 통합 장면 L0(301호 쉼)·L8. 같은 날 두 번 생성해도 회차 수 같음 코어 AbsenceQuery(있음)
청구 넘김(F13) 비용 있는 요청이 확인 뒤 청구서에 근거와 함께 들어가게 해서, 청구 누락을 줄일 길을 보인다 [가설] 통합 장면 L9(정옥자). 같은 요청 ID로 두 번 넘겨도 청구 대기 1건 코어 ServiceFeeQuery·ServiceChargeCommand [요청]
운영 현황 조회(F17), 소유주 월 요약(F22) 책임자가 열린 요청과 정기 작업 결과를 숫자로 보게 한다 통합 장면 L10 코어 운영 현황 카드(P1)
병원 동행(F14) 회원이 몸 상태를 말하지 않고 동행을 신청하게 한다 스키마에 진료 칸 없음, 가실 곳 열람 기록 없음
보호자 보기·올리기(F15), 보호자 문자(F19) 멀리 있는 보호자가 회원님이 허락한 범위에서 불편을 전하게 한다 통합 장면 L6. 허락 없으면 막힘 D 허락 항목·정책·이벤트 구독 [요청]
홈 비서 넘김 받기(F16) 비서에게 한 말이 직원에게 닿는 받는 곳을 만든다 G_START 부록 시연(11/17 통합 장면에는 없음, H4). 넘김 ID로 멱등 G 넘김 호출 [요청]
알림(F18), 종류 설정(F20), 말로 하기(F21) 앱을 열지 않아도 변화를 알고, 사업장이 담당과 기한을 스스로 정하게 한다 문자 로그, 설정 버전 Notifier(있음)

Next — 생활 요청 v1.1 (각 1~2주)
