흐름 1. 입주 계약 체결 → 입주

시나리오: 새봄 레지던스(가상) A동 201호에 부부(가상)가 입주한다.

단계 물리적 증거 이용자 행동 프런트스테이지 백스테이지 지원 프로세스
1. 계약 작성 계약 초안 화면, 상태 "작성 중" 부부가 상담실에서 조건을 확인한다 ACC가 호실, 기간, 당사자 2명, 보증금, 요금 플랜(2인)을 입력한다 호실 기간 겹침 검사. 사업장의 현재 요금 규칙 버전을 계약에 고정 요금 규칙 설정, 호실 점유 이력
1a. 비상 연락처 등록 계약 작성 화면의 "비상 연락처" 칸(copy 2-8 반영됨), 회원에게 주는 계약 사본의 "급할 때 연락할 분" 부부가 급할 때 전화할 분(예: 딸)과 순서를 알려 준다 ACC가 이름, 관계, 전화번호, 연락 순서를 입력하고 등록 동의를 받는다. 등록되는 분께 알렸는지 기록 동의 일시·근거(계약 동의 / 급박한 생명·신체 예외 [법률 검토]) 저장. 순서 중복 검사. 변경 이력 기록. 보호자(GuardianLink)와 따로 저장 비상 연락처, 변경 이력. B가 EmergencyContactQuery로 읽는다
2. 서명 종이 계약서(서명본) + 상태 "입주 예정" 부부가 종이 계약서에 서명한다 ACC가 "계약 체결"을 누르고 서명일과 서명자(본인 2명)를 기록 서명자가 계약 당사자 본인이거나 SIGN_CONTRACT 범위의 유효한 대리인인지 검사. DRAFT → SIGNED(이때부터 호실을 잡는다). 변경 이력 기록 권한 검사, 변경 이력
3. 보증금 수납 보증금 영수 기록 부부가 보증금을 입금한다 ACC가 보증금 입금을 기록 보증금 원장(청구 원장과 분리)에 입금 결제 어댑터(목업)
4. 입주 처리 상태 "거주 중", 회원 안내문 입주한다 FD 또는 ACC가 "입주 처리", 입주일 입력 SIGNED → ACTIVE 전이. 입주일이 없으면 거부. ContractActivated 이벤트 발행 이벤트 아웃박스 → 다른 모듈(B, D) 구독. G 최소판은 구독하지 않는다(2026-11-03 G 요청)

흐름 2. 월 청구

단계 물리적 증거 이용자 행동 프런트스테이지 백스테이지 지원 프로세스
1. 결식 신청 (전화·프런트 메모) 회원이 "다음 주 화요일 점심은 안 먹어요"라고 프런트에 말한다 FD가 결식을 입력한다(회원 대행) 결식 기록 저장(회원, 날짜, 끼니, 접수 경로, 접수 직원) 식사 기록
2. 식사 마감 마감 확인 창 "○월 식사 기록을 마감할까요?" — ACC가 월말에 식사 기록을 마감한다 마감 이후 해당 월 결식 수정 불가(정정은 조정 전표로) 마감 기록
3. 청구 생성 "청구서 ○건을 만들었습니다." — ACC가 "이번 달 청구서 만들기" 대상 계약(청구 기간이 그 달과 겹치는 계약)마다 규칙 3개 계산: 정기 요금, 식비, 결식 감면. 각 청구 항목에 근거(규칙 버전, 식사 기록 수, 계산식)를 붙인다. 같은 사업장·같은 달 재실행은 결과를 바꾸지 않는다(멱등) 규칙 계산기, 청구 원장
4. 검토·발행 청구서 목록(감면 반영 건 표시) — ACC가 근거 패널을 열어 확인하고 발행 DRAFT → ISSUED. 발행 후 금액 변경 금지. InvoiceIssued 이벤트 청구 원장, 이벤트
5. 회원 확인 Evenstay 홈 청구서, 종이 청구서 출력본 회원이 "이번 달 내실 돈"과 이유를 본다 쉬운 말 명세: "드시지 않은 식사 3끼, 27,000원을 빼 드렸어요." 회원 본인, VIEW_INVOICE 범위 대리인만 조회(보호자는 D가 붙인 뒤). 조회 기록 권한 검사
6. 문의 "이 금액이 이상해요" 버튼, 접수 안내 회원 또는 대리인이 문의한다(전화면 직원 대행) "문의를 받았어요. 담당 직원이 ○일 안에 연락드릴게요" [NEED: 회신 기한] 문의 큐에 등록, 담당 ACC 배정 문의 기록
7. 정정 다음 달 청구서의 "조정" 항목 — ACC가 사유와 함께 조정 전표 입력 원래 항목은 그대로 두고 조정 전표가 원래 항목을 가리킨다. 다음 청구서에 반영 청구 원장
8. 수납 수납 상태 표시(완납, 일부, 미수 구분) 회원 또는 대리인이 납부 ACC가 수납 기록(또는 결제 웹훅) 결제 어댑터 웹훅은 멱등 키로 한 번만 반영 결제 어댑터(목업)
8-1. 앱 결제 (2026-11-05, 사용자 재승인 2026-11-05, 결제 화면) CORE-08 [내기], CORE-16 확인·결과 화면 회원 또는 PAY 대리인이 낼 금액을 확인하고 낸다. [돌아가기]로 멈출 수 있다 결과 화면에 낸 금액과 날짜, 실패면 copy 4절 문구와 프런트 전화 권한과 남은 금액을 검사하고 결제 시도를 한 건 연다. 목업 웹훅이 오면 수납을 한 번 기록한다. 대리인이면 대리 사실을 남긴다 결제 어댑터(목업). 카드 번호·계좌 번호를 받지 않음
8-2. 수납 보기 (2026-11-05, 사용자 재승인 2026-11-05, 결제 화면) CORE-07 수납 상태·방법, CORE-09·CORE-14 수납 합계 — ACC가 낸 금액, 방법, 대신 낸 사실을 본다. 소유주는 합계만 본다 수납 상태는 수납 기록에서 계산한다. 소유주 조회에는 이름과 낸 사람이 없다 청구 원장

흐름 3. 사별에 따른 계약 승계

단계 물리적 증거 이용자 행동 프런트스테이지 백스테이지 지원 프로세스
1. 소식 접수 (전화) 배우자나 보호자가 프런트에 알린다 FD가 위로를 전하고, 필요한 서류를 안내한다 — 안내 문구
2. 증빙 확인 증빙을 확인한 직원과 날짜 기록 가족이 서류를 보여 준다 FD가 서류를 확인한다 서류 원본은 저장하지 않고 확인 사실(종류, 확인 직원, 날짜)만 기록 변경 이력
3. 승계 실행 확인 창 "계약을 1인으로 바꿀까요?" — ACC가 남는 당사자와 새 요금 플랜(1인), 요금 적용 시작일(다음 달 1일)을 고른다 기존 계약 ACTIVE → SUCCEEDED(청구 종료일 = 이번 달 말일). 남는 회원의 새 계약 ACTIVE(청구 시작일 = 다음 달 1일, succeeded_from 연결). 보증금 잔액은 새 계약으로 이전. 한 트랜잭션 계약 상태 전이, 보증금 원장
4. 안내 회원 화면 "계약이 바뀌었어요", 다음 달 청구서 회원이 바뀐 요금을 본다 FD가 직접 설명(전화·방문) ContractSucceeded 이벤트 → D(보호자 안내), B(사별한 분의 기기 연결 종료) 구독. G는 구독하지 않고 회원이 물을 때 코어를 조회한다(2026-11-03 G 요청) 이벤트

흐름 4. 후견인(대리인) 등록

단계 물리적 증거 이용자 행동 프런트스테이지 백스테이지 지원 프로세스
1. 요청 (방문·전화) 보호자가 "어머니 대신 결제하고 싶다"고 한다 FD가 대리 근거(성년·한정·특정·임의후견, 위임장)와 필요한 증빙을 안내한다. 법적 판단은 하지 않는다고 말한다 — 안내 문구

3. 승인 대리인 등록 완료 표시 — HQ 또는 사업장 책임자가 확인 후 승인(입력자와 승인자 분리) 승인 전에는 권한 검사에 쓰지 않음. RepresentativeActivated 이벤트 권한 검사, 변경 이력
